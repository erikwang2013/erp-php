## 1. Overview

On top of the existing `service/` system-management base, extend three business domains — inventory/purchase/sales, finance, and CRM — to build a complete ERP system.
All code is deployed as a monolith under `service/app/`, with modules layered by directory.

### 1.1 Phase Planning

| Phase | Modules | Description |
|-------|---------|-------------|
| Phase 1 | Product master data + purchase + sales + inventory + finance + CRM | Core business loop closure |
| Phase 2 | Manufacturing + project management | Later extension |

### 1.2 Tech Stack (reusing the existing one)

- PHP 8.3+, webman v2, MySQL 8.0+
- Primary keys are BIGINT generated by snowflake-php
- API-layer IDs are encrypted/decrypted with hashids
- JWT auth and sensitive-data encryption all use the erikwang2013/* package family
- Table prefix `erik_`, soft deletes, no leading `\` on global functions

## 3. Module Feature List

### 3.1 Product and Master Data

| Feature | Description |
|---------|-------------|
| Product archive | Product name, code, barcode, category (tree), brand, spec attributes |
| Multi-SKU specs | Multiple specs for one product, each with independent SKU, barcode, price |
| Multi-unit conversion | Base unit ↔ auxiliary unit conversion rates |
| Price strategy | Purchase price, wholesale price, retail price, customer-tier prices |
| Category management | Unlimited-level category tree with drag-and-drop sorting |
| Brand management | Brand CRUD |
| Warehouse management | Multiple warehouses, each with multiple locations |
| Location management | Storage positions under a warehouse, codes are unique |
| Supplier archive | Name, contact, phone, address, bank account, tax rate |
| Customer archive | Name, contact, phone, address, customer tier, credit limit |

### 3.2 Purchase Module

| Feature | Description |
|---------|-------------|
| Purchase request | Departments/people submit purchase needs, supports approval flow |
| Purchase order | Created from a request or directly, linked to supplier, product, quantity, unit price |
| Purchase receiving | Receive goods against an order, generate inbound documents, supports partial receiving |
| Purchase return | Return goods to the supplier, generate an outbound document to reverse |
| Supplier reconciliation | Aggregate purchase amounts, paid, and payable by supplier + time range |
| Purchase settlement | Reconcile purchase receiving against payments |

### 3.3 Sales Module

| Feature | Description |
|---------|-------------|
| Quotation | Quote to customers, supports conversion to sales order |
| Sales order | Customer places an order, linked to product, quantity, unit price, discount |
| Sales delivery | Ship against an order, generate outbound documents, supports partial delivery |
| Sales return | Customer returns goods, generate an inbound document to reverse |
| Customer reconciliation | Aggregate sales amounts, received, and receivable by customer + time range |
| Sales settlement | Reconcile sales delivery against receipts |
| Sales gross margin | Calculate gross margin by order/product/customer dimensions |

### 3.4 Inventory Module

| Feature | Description |
|---------|-------------|
| Real-time inventory | Stock quantity by warehouse + location + batch + SKU dimensions |
| Batch tracking | Production date, expiry date, batch number |
| Serial number tracking | Unique serial numbers, recorded on inbound/outbound |
| In/out flow | Unified log of all inventory changes (source document number + type + quantity + direction) |
| Inventory transfer | Transfer between warehouses/locations, generating transfer in/out documents |
| Check tasks | Planned checks (by warehouse/category) + dynamic checks (by SKU) |
| Check variance | Surplus/shortage automatically generates in/out flow records |
| Inventory alerts | Set upper/lower limits per SKU + warehouse, alert below lower or above upper |
| Costing | Moving weighted average, cost price recalculated on each inbound |

### 3.5 Finance Module

| Feature | Description |
|---------|-------------|
| Chart of accounts | Subject tree (assets/liabilities/equity/revenue/expenses), customizable |
| AR/AP | Auto-generated from sales/purchase documents, manually reconciled |
| Receipts | Multi-account, multi-method (cash/bank/WeChat/Alipay) receipts |
| Payments | Multi-account, multi-method payments |
| Reconciliation | Receipts reconcile AR, payments reconcile AP |
| Cash/bank journal | Income/expense flow by account + date |
| Expense reimbursement | Submit→approve→pay out, linked to subjects |
| Income statement | Monthly aggregation of revenue/cost/expenses/profit |

### 3.6 CRM Module

| Feature | Description |
|---------|-------------|
| Customer management | Customer archive (linked to master-data customers) |
| Contact management | Multiple contacts under a customer |
| Follow-up records | Follow-up method, time, content, next follow-up plan |
| Sales funnel | Stage configuration + opportunity amount estimation + stage conversion rates |

## 6. Cross-Module Data Flow

```
Purchase receiving → inventory_flow (inbound) → inventory (+quantity) → cost_record (recompute average price)
                   → finance_ar_ap (payable)

Sales delivery → inventory_flow (outbound) → inventory (-quantity) → cost_record (record cost)
               → finance_ar_ap (receivable)

Receipt reconciliation → finance_ar_ap (received updated) → cash_journal (income record)
Payment reconciliation → finance_ar_ap (paid updated) → cash_journal (expense record)

Check variance → inventory_flow (surplus inbound / shortage outbound) → inventory (adjusted)

Expense reimbursement (paid) → finance_payment (auto-generated) → cash_journal (expense record)
```

Implementation: after each business operation completes, downstream actions are triggered via events, without directly calling Services across modules.

## 7. Excel/PDF Export

- All list pages support the `?export=excel` parameter, generating a styled .xlsx file
- Dashboard panels support `?export=pdf`, outputting a PDF report with charts
- Sensitive fields (amounts, phone numbers, etc.) are masked via EncryptionService on export
- Reuse the existing ExportController base class; each module controller extends it and implements its own export column definitions

|-------|-------|---------|
| Business overview | `/admin/dashboard` | Today/this-month sales, purchase amounts, AR/AP, total inventory value, gross margin |
| Inventory board | `/admin/dashboard/inventory` | Alert list, in/out trends, location occupancy |
