## 1. System Overview

The Open ERP System (open-erp) is a full-stack enterprise resource planning system built on webman v2 + Flutter, covering fourteen business domains: system management, purchasing/sales/inventory, finance, CRM, approval workflow, message notifications, project management, human resources, manufacturing, and custom reports.

### 1.1 Design Goals
- Monolithic deployment, modular design
- All IDs generated by snowflake + hashids encrypted transport
- Sensitive data double-layer encryption (transport layer AES-256-CBC + storage layer AES-128-ECB)
- Moving weighted average costing
- Cross-module automatic linkage (purchase→AP, sales→AR, receipts/payments→reconciliation)

### 1.2 Technical Constraints
- PHP 8.3+, MySQL 8.0+, Redis 7, Elasticsearch 8
- Table prefix erik_, BIGINT non-auto-increment primary keys
- API versions controlled via the API-Version request header
- JWT authentication + RBAC permissions
- Global functions without `\` prefix

## 2. System Management Module

### 2.1 User Management
- Admin CRUD, batch enable/disable and batch soft delete supported
- Excel batch import (per-row validation + error report)
- Passwords bcrypt hashed; changing a password requires confirming the original password
- Delete operations require second confirmation with the current user's password
- Phone/email/ID number stored encrypted, list views auto-masked

### 2.2 Roles & Permissions (RBAC)
- Role CRUD, slug unique identifier
- Permission tree (unlimited-level parent_id self-reference), types: menu/button/API
- Permission identifier format: {method}.{path} (e.g. get.admin/product, post.admin/user/batch/destroy)
- Role-permission many-to-many association
- Super admin (super_admin) skips all permission checks
- AdminPermission middleware caches permissions in Redis (TTL=60s)

### 2.3 System Config
- Key-value storage, grouping supported
- Value types: string|int|bool|json|array

### 2.4 Operation Audit
- Auto-records all POST/PUT/DELETE operations
- Records: operator, action, method, path, IP, parameters (sensitive fields masked), time
- Auto-detects 8 platform sources (Web/Flutter/HarmonyOS/API, etc.)
- Query-only; cannot be deleted or modified

### 2.5 Security Protection
- 18-layer defense in depth (see SECURITY.md)
- SecurityFilter: HTTP method restriction + XSS/SQL injection/path traversal/command injection/CSRF blocking
- RateLimit: Redis sliding-window rate limiting (Lua atomic, 60 times/minute)
- Click captcha (mandatory on login/registration)
- Account lockout: 5 failed attempts locks for 15 minutes
- Concurrent session limit: at most 3 Tokens per user
- CSP headers, security.txt (RFC 9116)
- poster-php random second verification for sensitive operations

## 4. Purchase Module

### 4.1 Purchase Flow
Requisition → Approval → Order → Receiving → Settlement

### 4.2 Purchase Requisition
- Departments/people submit purchase requirements
- Status: pending approval → approved/rejected → converted to order
- Approver actions supported

### 4.3 Purchase Orders
- Linked to supplier, item lines (quantity, unit price, amount)
- Status: pending review → reviewed → partially received → received → cancelled
- Can be created from a purchase requisition or directly

### 4.4 Purchase Receiving (cross-module linkage)
- Receive against the order, partial receiving supported
- Auto-triggered on receiving:
  1. InventoryService.stockIn() → update live inventory + recalculate moving weighted average
  2. FinanceService.createAp() → generate AP record
  3. Update order received quantity and status
- Location and batch number recording supported

### 4.5 Purchase Returns
- Return to supplier, generates stock-out reversal
- Linked to receiving documents

### 4.6 Supplier Settlement
- Aggregated per supplier: purchase amount, paid, payable
- Settlement status: unsettled/partially settled/settled

## 5. Sales Module

### 5.1 Sales Flow
Quote → Order → Delivery → Settlement

### 5.2 Quotations
- Quote to customer, convertible to sales order
- Status: draft → quoted → converted to order → expired

### 5.3 Sales Orders
- Linked to customer, item lines (quantity, unit price, discount)
- Status: pending review → reviewed → partially shipped → shipped → cancelled
- Discount amounts supported

### 5.4 Sales Delivery (cross-module linkage)
- Ship against the order, partial shipment supported
- Auto-triggered on delivery:
  1. InventoryService.stockOut() → deduct inventory (at moving weighted average cost)
  2. FinanceService.createAr() → generate AR record
  3. Update order shipped quantity and status

### 5.5 Sales Returns
- Customer returns, generates stock-in reversal

### 5.6 Customer Settlement & Gross Margin
- Aggregated per customer: sales amount, received, receivable
- Sales gross margin: computed by order/item/customer dimension

## 6. Inventory Module

### 6.1 Inventory Management
- Live inventory: four-dimension precision of warehouse+location+batch+SKU
- Stock in/out flows: all inventory changes recorded uniformly (direction, quantity, cost price, source document number)
- Batch tracking: production date, expiry date
- Serial number tracking: unique serial numbers, status recorded on stock in/out (in stock/out)

### 6.2 Costing
- Moving weighted average method
- Formula: new average = (original total stock value + incoming total value) / (original stock quantity + incoming quantity)
- Auto-recalculated on each stock-in; stock-outs costed at the current average
- Complete cost record chain (average before change → average after change)

### 6.3 Inventory Transfers
- Transfers between warehouses/locations
- Status: pending transfer → transferred out → transferred in → completed
- Transfer-out/in stock flows auto-generated

### 6.4 Stock Counts
- Planned counts (by warehouse/category) + dynamic counts (by SKU)
- Records book quantity vs. actual quantity
- Count differences auto-generate count gain/loss stock flows

### 6.5 Inventory Alerts
- Min/max limits per SKU+warehouse
- Auto-records alert logs when below min/above max

## 7. Finance Module

### 7.1 Chart of Accounts
- Account tree: five categories — assets/liabilities/equity/revenue/expenses
- Account codes unique
- Balance direction: debit/credit

### 7.2 Accounting Vouchers
- Voucher number, date, summary
- Double-entry: each entry contains a debit amount and a credit amount (debits must equal credits)
- Status: draft → reviewed

### 7.3 General Ledger
- Aggregated by account + accounting period (year/month)
- Records: opening debit/credit balances, period debit/credit activity, closing debit/credit balances
- Closing balance = opening balance ± period activity (per account balance direction)
- Auto-updated after voucher review
- Filtering by year/month/account supported

### 7.4 Subsidiary Ledger
- Every voucher entry for a given account recorded line by line
- Includes: voucher number, direction (debit/credit), amount, balance, summary, date
- Query by account + date range supported
- Synced with voucher entries

### 7.5 Balance Sheet
- Generated per accounting period (monthly/yearly)
- Auto-aggregates general ledger balances:
  - Asset accounts (1) → total assets = current assets + non-current assets
  - Liability accounts (2) → total liabilities = current liabilities + non-current liabilities
  - Equity accounts (3) → owner's equity
  - Identity: assets = liabilities + owner's equity
- Snapshot saving supported (full JSON data)
- Auto-generated from the general ledger when no snapshot exists

### 7.6 Cash Flow Statement
- Generated per accounting period (monthly/yearly)
- Three categories:
  - Operating cash flow (sales receipts - purchase payments - expense disbursements)
  - Investing cash flow
  - Financing cash flow
- Opening/closing cash balance = total of all bank account opening/closing balances
- Auto-generated by aggregating cash and bank journals
- Snapshot saving supported (full JSON data)

### 7.7 AR/AP
- Auto-generated by purchase receiving/sales delivery
- AR: type=receivable, linked to customer, source=sales delivery document
- AP: type=payable, linked to supplier, source=purchase receiving document
- Status: unreconciled → partially reconciled → reconciled
- Same source document cannot be generated twice (idempotency protection)

### 7.8 Receipt Management
- Multiple accounts (cash/bank/WeChat/Alipay)
- Auto-updates bank account balance and cash journal after review
- Reconciliation: select AR records, enter the reconciliation amount (not exceeding the unreconciled balance)
- Partial reconciliation status flows automatically

### 7.9 Payment Management
- Same logic as receipts, opposite direction
- Reconciles AP records

### 7.10 Cash & Bank Journals
- Records each income/expense per account+date
- Records the balance after the change
- Bank account balance updated in real time

### 7.11 Expense Reimbursement
- Flow: submit → approve → pay out
- Linked to expense accounts
- Auto-generates payment voucher + journal entry after pay-out

### 7.12 Income Statement
- Monthly aggregation: operating revenue, operating cost, expenses, profit
- Data snapshot storage (year+month unique)

### 7.13 Fixed Asset Depreciation
- Full asset lifecycle management: acquisition → usage → depreciation → disposal
- Depreciation method: straight-line ((original value - residual value) / months of useful life)
- Monthly depreciation accrual, depreciation records auto-generated
- Records: original value, residual value, useful life in years, monthly depreciation, accumulated depreciation, net book value

### 7.14 Tax Management
- Multiple tax types supported: VAT/corporate income tax/personal income tax/stamp duty
- Tax rates flexibly configurable
- Linked to purchase/sales documents, tax amounts auto-recorded

### 7.15 Multi-Currency
- Currency management: CNY/USD/EUR/JPY, etc.
- Base currency flag
- Exchange rates managed by effective date
- Foreign currency conversion supported

### 7.16 Budget Management
- Annual budget planning: by cost center + account + month
- Budget vs. actual comparison analysis
- Execution rate calculation + variance analysis
- Status: draft → approved → in execution → closed

### 7.17 Cost Center / Profit Center
- Tree hierarchy structure
- Cost collection + expense allocation
- Profit centers account independently

## 8. CRM Module

### 8.1 Customer Management
- Customer profiles linked to master-data customers
- Multiple contacts per customer (primary contact flag)
- Contact phone/email stored encrypted

### 8.2 Follow-up Records
- Follow-up methods: phone/visit/email/message/other
- Records follow-up content, next follow-up plan, next follow-up time
- Linked to customer, contact, opportunity

### 8.3 Campaign Management
- Full campaign lifecycle: planned → in progress → completed → cancelled
- Multi-channel: email/SMS/phone/event/social media
- Participant tracking, conversion rate statistics
- Budget vs. actual spend comparison

### 8.4 Service Tickets
- Ticket management: pending → in progress → resolved → closed
- Priority: low/medium/high/urgent
- Categories: tech support/complaint/consultation/return & exchange/other
- Assigned handler + replies (public/internal memo)
- Resolution rate statistics

### 8.5 Customer Analytics Reports
- 6 core metrics: new customers/active customers/retention rate/average order value/CLV/ticket resolution rate
- Reports auto-generated (JSON data snapshot)
- Monthly/quarterly/yearly supported

### 8.6 Sales Funnel
- Stage configuration: initial contact (10%) → requirement confirmed (30%) → quotation proposal (50%) → business negotiation (70%) → won (100%) → lost (0%)
- Opportunities: customer, current stage, estimated amount, win probability, expected closing date, owner
- Opportunity status: lost/in progress/won
- Stage movement tracking

### 8.7 Customer Public Pool
- Customer public pool: unassigned or overdue-unfollowed customers automatically enter the public pool
- Recovery rules: auto-recovery days without follow-up set per customer level
- Per-person claim limits prevent customer resources from stagnating
- Claim/release/recover operations all leave flow records
- Drives sales team activity and prevents customer stagnation

### 8.8 CRM Quotation Management
- In-CRM quotation flow independent of the sales module
- Status: draft → sent → customer confirmed → converted to contract → expired
- Quotation validity period supported
- Direct conversion to contract supported (`to-contract`)
- Linked to customer and opportunity

### 8.9 Contract Management
- Full contract lifecycle: draft → pending approval → approved → in execution → completed/terminated
- Linked to customer, opportunity, quotation
- Contract items: product/quantity/unit price/amount
- Records signing date, start/end dates
- Contract terms content (TEXT large field)
- Owner assignment

## 16. Internationalization (i18n)

### 16.1 Automatic Language Detection
- `Accept-Language` request header auto-detection (zh-CN → Chinese, en → English)
- Locale middleware runs first in the global middleware chain
- Fallback chain: current language → configured fallback_locale → original key returned

### 16.2 Translation Files
- Directory: `resource/translations/{locale}/`
- Common messages: `common.php` (41 keys: success/failure/create/update/delete/validation, etc.)
- Module names: `modules.php` (69 keys: products/purchase/sales/inventory/finance/CRM, etc.)
- Validation rules: `validation.php` (11 rules + 10 field labels)

### 16.3 Usage
- In controllers: `$this->trans('created')`
- Global functions: `__('modules.product')`, `__m('finance')`
- Module names: `__('modules.product')` → 商品 / Product
