## 1. システム概要

オープン ERP システム (open-erp) は webman v2 + Flutter ベースで構築されたフルスタック企業資源計画システムで、システム管理、購買・在庫・販売、財務、CRM、承認ワークフロー、メッセージ通知、プロジェクト管理、人事、生産製造、カスタムレポートの 14 大業務ドメインをカバーします。

### 1.1 設計目標
- モノリシックデプロイ、モジュール化設計
- すべての ID は snowflake 生成 + hashids 暗号化転送
- 機密データの二重暗号化（転送層 AES-256-CBC + 保存層 AES-128-ECB）
- 移動加重平均原価計算
- モジュール横断の自動連動（購買→買掛、販売→売掛、入出金→消込）

### 1.2 技術制約
- PHP 8.3+, MySQL 8.0+, Redis 7, Elasticsearch 8
- テーブルプレフィックス erp_、主キー BIGINT 非オートインクリメント
- API バージョンはリクエストヘッダー API-Version で制御
- JWT 認証 + RBAC 権限
- グローバル関数に \ プレフィックスを付けない

## 2. システム管理モジュール

### 2.1 ユーザー管理
- 管理者 CRUD、一括有効/無効化・一括ソフトデリート対応
- Excel 一括インポート（行単位検証 + エラーレポート）
- パスワードは bcrypt ハッシュ、パスワード変更には元パスワードの確認が必要
- 削除操作には現在のユーザーのパスワードによる二重確認が必要
- 携帯番号/メール/身分証番号は暗号化保存、一覧は自動マスキング

### 2.2 ロール権限 (RBAC)
- ロール CRUD、slug 一意識別
- 権限ツリー（無限段の parent_id 自己参照）、型：メニュー/ボタン/API
- 権限識別形式: {method}.{path}（例: get.admin/product, post.admin/user/batch/destroy）
- ロール-権限の多対多関連
- スーパー管理者(super_admin)はすべての権限チェックをスキップ
- AdminPermission 中間ウェアが権限を Redis キャッシュ（TTL=60s）

### 2.3 システム設定
- キーバリュー保存、グループ対応
- 値の型: string|int|bool|json|array

### 2.4 操作監査
- すべての POST/PUT/DELETE 操作を自動記録
- 記録内容: 操作者、アクション、メソッド、パス、IP、パラメータ（機密フィールドはマスキング）、時間
- 8 プラットフォーム送信元の自動検出（Web/Flutter/HarmonyOS/API など）
- 照会のみ対応、削除/変更不可

### 2.5 セキュリティ対策
- 18 層の多層防御（詳細は SECURITY.md）
- SecurityFilter: HTTP メソッド制限 + XSS/SQLインジェクション/パストラバーサル/コマンドインジェクション/CSRF 遮断
- RateLimit: Redis スライディングウィンドウのレート制限（Lua 原子化、60回/分）
- クリック検証コード（ログイン/登録で強制）
- アカウントロック: 5 回失敗で 15 分ロック
- 同時セッション制限: 同一ユーザーの Token は最大 3 個
- CSP ヘッダー、security.txt (RFC 9116)
- poster-php による機密操作のランダム二重検証

## 3. 商品とマスターデータ

### 3.1 商品管理
- 商品マスタ: コード(一意)、名称、バーコード、規格、基本単位、画像、説明
- 多規格 SKU: 同一商品配下に複数 SKU、それぞれ独立したコード・バーコード・規格属性(JSON)
- 多単位換算: 基本単位 ↔ 補助単位、換算率
- 価格戦略: 仕入価格、卸売価格、小売価格、顧客等級別価格
- 商品分類: 無限段のツリー構造、ドラッグ並び替え対応
- ブランド管理: ブランド名、Logo、説明

### 3.2 倉庫・庫位
- 多倉庫管理（名称、コード、住所、責任者）
- 各倉庫に複数庫位（コードは倉庫内で一意）
- 倉庫連絡電話は暗号化保存

### 3.3 仕入先/顧客
- 仕入先マスタ: コード、名称、連絡先、電話/メール(暗号化)、住所、銀行情報
- 顧客マスタ: コード、名称、顧客等級、信用枠
- 顧客等級: 名称、デフォルト割引率
- 仕入先/顧客は ES 全文検索対応

## 4. 購買モジュール

### 4.1 購買フロー
申請 → 承認 → 注文 → 入荷 → 決済

### 4.2 購買申請
- 部門/担当者が購買ニーズを提出
- 状態: 承認待ち → 承認済み/却下 → 注文化済み
- 承認者操作対応

### 4.3 購買注文
- 仕入先、商品明細（数量、単価、金額）に関連付け
- 状態: 審査待ち → 審査済み → 一部入荷 → 入荷済み → キャンセル済み
- 購買申請ベースで作成可能、直接作成も可能

### 4.4 購買入荷（モジュール横断連動）
- 注文単位で入荷、分割入荷対応
- 入荷時に自動発動:
  1. InventoryService.stockIn() → リアルタイム在庫更新 + 移動加重平均再計算
  2. FinanceService.createAp() → 買掛記録を生成
  3. 注文の入荷済み数量と状態を更新
- 庫位、ロット番号の記録対応

### 4.5 購買返品
- 仕入先へ返品、出庫相殺を生成
- 入荷伝票に関連付け

### 4.6 仕入先決済
- 仕入先単位で集計: 購買金額、支払済み、買掛
- 決済状態: 未決済/一部決済/決済済み

## 5. 販売モジュール

### 5.1 販売フロー
見積 → 注文 → 出荷 → 決済

### 5.2 見積書
- 顧客への見積、販売注文への変換対応
- 状態: 下書き → 見積済み → 注文化済み → 失効済み

### 5.3 販売注文
- 顧客、商品明細（数量、単価、割引）に関連付け
- 状態: 審査待ち → 審査済み → 一部出荷 → 出荷済み → キャンセル済み
- 割引金額対応

### 5.4 販売出荷（モジュール横断連動）
- 注文単位で出荷、分割出荷対応
- 出荷時に自動発動:
  1. InventoryService.stockOut() → 在庫を減算（移動加重平均原価を使用）
  2. FinanceService.createAr() → 売掛記録を生成
  3. 注文の出荷済み数量と状態を更新

### 5.5 販売返品
- 顧客返品、入庫相殺を生成

### 5.6 顧客決済と粗利
- 顧客単位で集計: 販売金額、回収済み、売掛
- 販売粗利: 注文/商品/顧客の次元で計算

## 6. 在庫モジュール

### 6.1 在庫管理
- リアルタイム在庫: 倉庫+庫位+ロット+SKU の 4 次元精度
- 入出庫明細: すべての在庫変動を統一記録（方向、数量、原価単価、元伝票番号）
- ロット追跡: 製造日、賞味期限
- シリアル番号追跡: 一意のシリアル番号、入出庫時に状態を記録（在庫/出庫済み）

### 6.2 原価計算
- 移動加重平均法
- 公式: 新平均単価 = (元の在庫総額 + 今回入庫総額) / (元の在庫数量 + 今回入庫数量)
- 入庫のたびに自動再計算、出庫は現在の平均単価で原価を計上
- 完全な原価記録チェーン（変動前平均単価 → 変動後平均単価）

### 6.3 在庫振替
- 倉庫間/庫位間の振替
- 状態: 振替待ち → 出庫済み → 入庫済み → 完了
- 出庫/入庫の明細を自動生成

### 6.4 棚卸管理
- 計画棚卸（倉庫/分類単位）+ 動的棚卸（SKU 単位）
- 帳簿数量 vs 実棚数量を記録
- 棚卸差異から盤盈/盤虧の入出庫明細を自動生成

### 6.5 在庫アラート
- SKU+倉庫単位で上下限を設定
- 下限未満/上限超過を自動でアラートログに記録

## 7. 財務モジュール

### 7.1 会計科目
- 科目ツリー: 資産/負債/純資産/収益/費用の 5 大分類
- 科目コードは一意
- 残高方向: 借方/貸方

### 7.2 記帳伝票
- 伝票番号、日付、摘要
- 複式記帳: 各仕訳は借方金額と貸方金額を含む（借貸必ず一致）
- 状態: 下書き → 審査済み

### 7.3 総勘定元帳
- 会計科目+会計期間（年度/月）単位で集計
- 記録: 期初借方/貸方残高、当期借方/貸方発生額、期末借方/貸方残高
- 期末残高 = 期初残高 ± 当期発生額（科目残高方向に応じる）
- 伝票審査後に自動更新
- 年度/月/科目でのフィルタリング対応

### 7.4 明細帳
- 指定科目の各伝票仕訳を逐筆記録
- 内容: 伝票番号、方向(借/貸)、金額、残高、摘要、日付
- 科目+日付範囲での照会対応
- 伝票仕訳と同期更新

### 7.5 貸借対照表
- 会計期間単位で生成（月次/年次）
- 総勘定元帳残高を自動集計:
  - 資産類科目(1) → 総資産 = 流動資産 + 非流動資産
  - 負債類科目(2) → 総負債 = 流動負債 + 非流動負債
  - 純資産類科目(3) → 株主資本
  - 恒等式: 資産 = 負債 + 株主資本
- スナップショット保存対応（JSON 完全データ）
- スナップショットがない場合は総勘定元帳から自動生成

### 7.6 キャッシュフロー計算書
- 会計期間単位で生成（月次/年次）
- 3 分類:
  - 営業活動キャッシュフロー（売上回収 - 仕入支払 - 費用支出）
  - 投資活動キャッシュフロー
  - 財務活動キャッシュフロー
- 期初/期末現金残高 = 全銀行口座の期初/期末残高合計
- 現金銀行仕訳帳を自動集計して生成
- スナップショット保存対応（JSON 完全データ）

### 7.7 売掛買掛
- 購買入荷/販売出荷から自動生成
- 売掛: 型=売掛、顧客に関連付け、送信元=販売出荷伝票
- 買掛: 型=買掛、仕入先に関連付け、送信元=購買入荷伝票
- 状態: 未消込 → 一部消込 → 消込済み
- 同一送信元伝票の重複生成不可（冪等保護）

### 7.8 回収管理
- 複数口座（現金/銀行/WeChat/支付宝）
- 審査後に銀行口座残高と現金仕訳帳を自動更新
- 消込: 売掛記録を選択し、消込金額を入力（未消込残高を超えない）
- 一部消込の状態が自動遷移

### 7.9 支払管理
- 回収と同じロジック、方向は逆
- 買掛記録を消込

### 7.10 現金銀行仕訳帳
- 口座+日付単位で各入出金を記録
- 変動後の残高を記録
- 銀行口座残高をリアルタイム更新

### 7.11 経費精算
- フロー: 提出 → 承認 → 入金
- 費用科目に関連付け
- 入金後に支払伝票 + 仕訳帳を自動生成

### 7.12 損益計算書
- 月次集計: 営業収益、営業原価、費用、利益
- データスナップショット保存（year+month 一意）

### 7.13 固定資産減価償却
- 資産ライフサイクル管理: 取得 → 使用 → 減価償却 → 処分
- 償却方法: 定額法（(原価-残存価額) / 使用月数）
- 毎月償却を計上、償却記録を自動生成
- 記録: 原価、残存価額、耐用年数、月次償却額、累計償却、純額

### 7.14 税務管理
- 複数税種対応: 付加価値税/法人税/個人所得税/印紙税
- 税率は柔軟に設定可能
- 購買/販売伝票と連携、税額を自動記録

### 7.15 多通貨
- 通貨管理: CNY/USD/EUR/JPY など
- 本位通貨の識別
- 為替レートは発効日単位で管理
- 外貨換算対応

### 7.16 予算管理
- 年度予算編成: コストセンター+科目+月単位で編成
- 予算 vs 実績の比較分析
- 執行率計算 + 差異分析
- 状態: 下書き → 承認済み → 執行中 → クローズ済み

### 7.17 コストセンター/利益センター
- ツリー型の階層構造
- コスト帰集 + 費用配賦
- 利益センターの独立採算

## 8. CRM モジュール

### 8.1 顧客管理
- 顧客マスタはマスターデータの顧客と関連
- 顧客配下に複数の連絡先（主要連絡先のマーク）
- 連絡先の電話/メールは暗号化保存

### 8.2 フォローアップ記録
- フォローアップ手段: 電話/訪問/メール/メッセージ/その他
- フォローアップ内容、次回フォローアップ計画、次回フォローアップ日時を記録
- 顧客、連絡先、商機に関連付け

### 8.3 マーケティング活動
- 活動ライフサイクル: 計画 → 進行中 → 完了 → キャンセル
- マルチチャネル: メール/ショートメッセージ/電話/イベント/ソーシャルメディア
- 参加顧客の追跡、コンバージョン率の統計
- 予算 vs 実費の比較

### 8.4 サービス工単
- 工単管理: 未処理 → 処理中 → 解決済み → クローズ済み
- 優先度: 低/中/高/緊急
- 分類: 技術サポート/苦情/相談/返品交換/その他
- 処理担当者への割り当て + 返信（公開/内部メモ）
- 解決率の統計

### 8.5 顧客分析レポート
- 6 大中核指標: 新規顧客/アクティブ顧客/維持率/客単価/CLV/工単解決率
- レポート自動生成（JSON データスナップショット）
- 月次/四半期/年次対応

### 8.6 販売ファネル
- ステージ設定: 初回接触(10%) → ニーズ確認(30%) → 見積提案(50%) → 商談(70%) → 成約(100%) → 失注(0%)
- 商機: 顧客、現在ステージ、見込み金額、成約確率、成約見込み日、担当者
- 商機状態: 失注/進行中/成約済み
- ステージ移動の追跡

### 8.7 顧客公海プール
- 顧客公海プール: 担当未割当またはタイムアウトで未フォローアップの顧客が自動的に公海へ
- 回収ルール: 顧客等級に応じて未フォローアップの自動回収日数を設定
- 1 人あたりの最大取得数の制限、顧客リソースの滞留を防止
- 取得/解放/回収の操作はすべて明細記録あり
- 販売チームの活性化を促進し、顧客の滞留を回避

### 8.8 CRM 見積管理
- 販売モジュールとは独立した CRM 内部の見積フロー
- 状態: 下書き → 送信済み → 顧客確認 → 契約化済み → 失効済み
- 見積有効期限対応
- 契約への直接変換対応（`to-contract`）
- 顧客と商機に関連付け

### 8.9 契約管理
- 契約ライフサイクル: 下書き → 承認待ち → 承認済み → 執行中 → 完了済み/終了済み
- 顧客、商機、見積に関連付け
- 契約明細: 商品/数量/単価/金額
- 締結日、開始/終了日を記録
- 契約条項の内容（TEXT 大フィールド）
- 担当者割り当て

## 9. 承認ワークフローモジュール

### 9.1 ワークフロー定義
- ワークフロー名、説明、適用モジュール
- 多ノード承認チェーン設定
- 各ノードに承認者/承認ロール、承認戦略（会簽/或簽）を指定

### 9.2 承認フロー
- 業務伝票の承認提出 → 承認インスタンスを自動生成
- 定義済みノードに沿って遷移、各ノードの承認者が順に処理
- 承認操作: 提出(業務モジュールから発起)、承認、却下、撤回
- 承認結果は業務モジュールにコールバックして伝票状態を更新
- 私の承認一覧: 承認待ち/承認済み

### 9.3 承認記録
- 完全な承認チェーン追跡: 各ステップで承認者、操作、意見、時間を記録
- 承認インスタンスは業務伝票番号に関連付け

## 11. プロジェクト管理モジュール

- タスク CRUD: タイトル、説明、優先度、状態、締切日
- プロジェクトに関連付け、親子タスク対応
- タスク状態: 未開始 → 進行中 → 完了 → クローズ済み
- タスク割り当て: 担当者を指定

### 11.3 工数記録
- タスク単位で工数を入力: 日付、時間、説明
- プロジェクト単位で工数を集計

## 12. 人事モジュール

### 12.1 組織構造
- 部門管理: ツリー構造、部門名、コード、責任者、親部門
- 役職管理: 役職名、コード、所属部門、状態

### 12.2 従業員管理
- 従業員マスタ: コード、氏名、性別、携帯番号(暗号化)、メール(暗号化)、入社日、部門、役職
- 状態: 在職/退職
- システムユーザーアカウントと関連付け

### 12.3 勤怠管理
- 打刻: 出勤打刻、退勤打刻、時間を記録
- 勤怠照会: 従業員+日付範囲で照会
- 勤怠ルール: 勤務時間、遅刻/早退のしきい値

### 12.4 休暇管理
- 休暇 CRUD: 種別(事由休暇/病欠/年次有給など)、開始終了時間、理由
- 承認フロー: 提出 → 部門責任者承認 → 通過/却下
- 状態: 承認待ち → 承認済み → 却下済み

### 12.5 給与管理
- 給与項目: 基本給/業績/手当/控除項目など、計算方式
- 給与支給: 月次で給与明細を生成、従業員に関連付け
- 支給状態: 未支給 → 支給済み

## 13. 生産製造モジュール

### 13.1 BOM (部品表)
- BOM 定義: 親製品、子部材、標準使用量、単位、工程
- BOM 階層: 多段 BOM 展開対応
- バージョン管理: BOM 改訂記録

### 13.2 製造オーダー
- 製造オーダー CRUD: 製品、計画数量、計画開始/終了日
- 状態: 生産待ち → 生産中 → 完工済み → クローズ済み
- 着手/完工操作: 実際の開始/終了時間を記録
- 生産明細: 払出リスト（BOM 展開ベース）

### 13.3 工順
- 工順定義: 製品、工程順序、各工程の標準工数
- BOM とワークステーションに関連付け

### 13.4 ワークステーション
- ワークステーション CRUD: 名称、コード、型、能力、状態
- 工順工程に関連付け

### 13.5 MRP (資材所要量計画)
- MRP 計画: 販売注文/生産計画 + BOM に基づき資材所要量を計算
- 購買提案（原材料不足時）と生産提案（半製品不足時）を自動生成
- MRP 明細: 資材、総所要量、在庫利用可能量、純所要量、提案オーダー量
- 計画状態: 下書き → 生成済み → 購買/生産提案発行済み

- 実行履歴の照会

## 16. 国際化 (i18n)

### 16.1 言語自動検出
- リクエストヘッダー `Accept-Language` で自動識別（zh-CN → 中文, en → English）
- Locale 中間ウェアはグローバル中間ウェアチェーンの先頭で実行
- フォールバックチェーン: 現在の言語 → 設定の fallback_locale → 元のキーを返す

### 16.2 翻訳ファイル
- ディレクトリ: `resource/translations/{locale}/`
- 共通メッセージ: `common.php`（41 キー: 成功/失敗/作成/更新/削除/検証など）
- モジュール名: `modules.php`（69 キー: 商品/購買/販売/在庫/財務/CRM など）
- 検証ルール: `validation.php`（11 ルール + 10 フィールドラベル）

### 16.3 使用方法
- コントローラー内: `$this->trans('created')`
- グローバル関数: `__('modules.product')`、`__m('finance')`
- モジュール名: `__('modules.product')` → 商品 / Product
