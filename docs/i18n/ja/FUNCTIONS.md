## 概要

オープンERPシステム (open-erp) は 19 の業務ドメイン <!-- stats:modules=19 -->、163 のデータテーブル <!-- stats:tables=163 --> をカバーし、進銷存（仕入・在庫・販売）から生産製造、財務会計から人事管理までを提供するフルスタック企業管理システムです。国際化: 中国語/English のバイリンガル対応、Accept-Language リクエストヘッダーで自動切替。

> API ドキュメント: サービス起動後に `http://localhost:8788/apidoc` へアクセスして対話型インターフェースドキュメントを確認（hg/apidoc 自動生成）

## 1. システム管理

### 1.1 ユーザー管理
- 管理者アカウントのライフサイクル全体を管理（作成/編集/削除/有効・無効）
- 一括操作：一括削除、一括有効/無効
- Excel 一括インポート、行単位の検証 + エラーレポート
- パスワードは bcrypt ハッシュで保存、変更には旧パスワードの確認が必要
- 削除などの機密操作には現在のユーザーパスワードによる再確認が必要
- 携帯番号/メール/身分証番号は暗号化保存、一覧では自動マスキング

### 1.2 ロール権限 (RBAC)
- ロール管理：作成/編集/削除、slug 一意識別子
- 権限ツリー：無限階層のツリー構造、3 タイプ——メニュー（ナビゲーション表示）、ボタン（ページ内操作）、API（インターフェースアクセス）
- 権限識別子の形式: `{method}.{path}`、例: `get.admin/product`、`post.admin/user/batch/destroy`
- ロール-権限は多対多の関連付け、スーパー管理者はすべての権限チェックをスキップ
- AdminPermission ミドルウェアが Redis でユーザー権限をキャッシュ（TTL=60s）

### 1.3 システム設定
- キーバリュー保存、グループ管理対応
- 値型: 文字列/整数/ブール/JSON/配列

### 1.4 操作監査
- すべての POST/PUT/DELETE 操作を自動記録
- 操作者、アクション、メソッド、パス、IP、パラメータ（機密フィールドはマスキング）、時間を記録
- 8 プラットフォームのクライアント種別を自動検出（Web/Flutter/HarmonyOS/API など）
- 読み取り専用照会、削除や変更は不可

### 1.5 セキュリティ対策
- 18 層の多層防御：HTTP メソッド制限、XSS/SQL インジェクション/パストラバーサル/コマンドインジェクション/CSRF ブロック
- クリック式 CAPTCHA（ログイン/登録で強制検証）
- Redis スライディングウィンドウレート制限（Lua アトミック、デフォルト 60回/分）
- アカウントロック：5 回失敗で 15 分ロック
- 同時セッション制限：同一ユーザーの有効トークンは最大 3 つ
- CSP ヘッダー、security.txt (RFC 9116)
- 機密操作のランダム二次検証（poster-php）

## 2. 商品と基本データ

### 2.1 商品管理
- 商品マスタ：コード（一意）、名称、バーコード、規格、基本単位、画像、説明

- 多単位換算：基本単位と補助単位の換算率
- 価格戦略：仕入れ価格、卸売価格、小売価格、顧客ランク価格
- ES 全文検索対応

### 2.2 商品カテゴリ
- 無限階層のツリー型カテゴリ構造
- 並び順、有効/無効対応
- ドラッグ並び替え

### 2.3 ブランド管理
- ブランド名、Logo、説明、並び順

### 2.4 倉庫・ロケーション
- 複数倉庫管理（名称、コード、住所、責任者、連絡電話）

### 2.5 仕入先管理

### 2.6 顧客管理
- 顧客コード、名称、顧客ランク、与信限度額
- 連絡先/電話/メール(暗号化) / 住所
- 顧客ランク：名称、デフォルト割引率
- ES 全文検索

## 3. 購買管理

### 3.1 購買申請
- 部門/担当者が購買ニーズを申請
- 承認フロー：承認待ち → 承認済み/却下済み → 注文化済み
- 承認ワークフローエンジンへの接続可

### 3.2 購買注文
- 仕入先、商品明細（数量、単価、金額）を関連付け
- 状態：審査待ち → 審査済み → 一部入荷 → 入荷済み → キャンセル済み
- 申請に基づいて作成可、直接作成も可

### 3.3 購買入荷（モジュール横断連動）
- 注文に基づく入荷、分割入荷対応
- 入荷で自動トリガー: ① 入庫（移動加重平均原価計算）② 買掛記録の生成 ③ 注文の入荷済み数量を更新

### 3.4 購買返品
- 仕入先へ返品、出庫相殺を生成

### 3.5 仕入先決済
- 仕入先単位で集計：購買金額、支払済み、買掛
- 状態：未決済/一部決済/決済済み

## 4. 販売管理

### 4.1 見積書
- 顧客へ見積提示、販売注文への変換対応
- 状態：草稿 → 見積済み → 注文化済み → 失効

### 4.2 販売注文
- 顧客、商品明細（数量、単価、割引）を関連付け
- 状態：審査待ち → 審査済み → 一部出荷 → 出荷済み → キャンセル済み

### 4.3 販売出荷（モジュール横断連動）
- 注文に基づく出荷、分割出荷対応
- 出荷で自動トリガー: ① 出庫（移動加重平均原価ベース）② 売掛記録の生成 ③ 注文の出荷済み数量を更新

### 4.4 販売返品
- 顧客からの返品、入庫相殺を生成

### 4.5 顧客決済と粗利
- 顧客単位で集計：販売金額、回収済み、売掛
- 注文/商品/顧客の次元で粗利を計算

## 5. 在庫管理

### 5.1 リアルタイム在庫
- 4 次元の精度：倉庫 + ロケーション + ロット + SKU
- 複数倉庫、複数ロケーション対応
- リアルタイム在庫照会

### 5.2 入出庫流水
- すべての在庫変動を統一的に記録（方向、数量、原価単価、元伝票番号、時間）

### 5.3 ロット追跡
- 製造日、賞味期限、ロット番号
- 入出庫時にロットを記録

### 5.4 シリアル番号追跡
- 一意のシリアル番号管理
- 入出庫時に状態を記録（在庫中/出庫済み）

### 5.5 原価計算
- 移動加重平均法
- 公式: 新平均単価 = (元在庫総額 + 今回入庫総額) / (元在庫数量 + 今回入庫数量)
- 入庫のたびに自動再計算、出庫は現在の平均単価で原価計上

### 5.6 在庫振替
- 倉庫間/ロケーション間の振替
- 状態：振替待ち → 出庫済み → 入庫済み → 完了
- 出庫/入庫の流水を自動生成

### 5.7 棚卸管理
- 計画棚卸（倉庫/カテゴリ単位）+ 動的棚卸（SKU 単位）
- 帳簿数量 vs 実地数量を記録
- 差異は棚卸差益/差損の流水を自動生成

### 5.8 在庫アラート
- SKU+倉庫 単位で上下限を設定
- 下限未満/上限超過でアラートログを自動記録

## 6. 財務管理

### 6.1 売掛・買掛
- 購買入荷/販売出荷から自動生成
- 状態：未消込 → 一部消込 → 消込済み
- 同一発注元伝票の冪等保護

### 6.2 入金管理
- 複数口座（現金/銀行/微信/支付宝）
- 審査後に口座残高と現金仕訳帳を自動更新
- 売掛記録の消込対応

### 6.3 出金管理
- 入金と同じロジック、方向は逆
- 買掛記録の消込対応

### 6.4 現金・銀行仕訳帳
- 口座+日付単位で入出金の流水を記録
- 銀行口座残高をリアルタイム更新

### 6.5 費用精算
- フロー：申請 → 承認 → 支払い
- 支払い後に出金伝票 + 仕訳帳を自動生成

### 6.6 損益計算書
- 月単位で集計：営業収益、営業原価、費用、利益
- スナップショット保存（year+month 一意）

### 6.7 固定資産
- 資産ライフサイクル全体：取得 → 使用 → 減価償却 → 処分
- 定額法： (取得原価-残存価額) / 使用月数
- 毎月減価償却を計上し、償却記録を自動生成
- 記録：取得原価、残存価額、使用年数、月次償却額、累計償却額、帳簿価額

### 6.8 税務管理
- 複数税種：付加価値税/法人所得税/個人所得税/印紙税
- 税率を柔軟に設定（4 つのデフォルト税率シードデータ含む）
- 購買/販売伝票と関連付け、税額を自動記録

### 6.9 多通貨
- 通貨管理：CNY/USD/EUR/JPY（4 つのデフォルト通貨シードデータ含む）
- 本座通貨の標識
- 為替レートは発効日で管理

### 6.10 予算管理
- 年度予算編成：コストセンター + 科目 + 月単位
- 予算 vs 実績の比較分析（執行率 + 差異）
- 状態：草稿 → 承認済み → 執行中 → クローズ済み

### 6.11 コストセンター/利益センター
- ツリー型の階層構造
- コスト集計 + 費用配賦
- 利益センターは独立採算

## 12. 生産製造

### 12.1 BOM 部品表

- BOM に基づいて製造オーダーを作成

- 製品ごとに工程フローを定義

### 12.4 ワークステーション
- ワークステーションコード、名称、生産能力（時間あたり）
- 有効/無効

### 12.5 MRP 資材所要計画
- 正味所要量計算：総所要量 - 計画受入 - 現有在庫 = 正味所要量

- 状態：草稿 → 生成済み → 確定済み

## モジュール横断のデータフロー

```
采购收货 → 自动入库(移动加权平均成本) → 生成应付记录
销售发货 → 自动出库 → 生成应收记录
收付款 → 核销应收应付 → 更新日记账
盘点差异 → 自动生成盈亏出入库流水
审批提交 → 工作流引擎路由 → 逐级审批 → 通知推送
费用报销打款 → 自动生成付款单 + 日记账
资产折旧 → 按月计提 → 成本分摊到成本中心
MRP 运算 → BOM 展开 → 净需求计算 → 生成采购/生产建议
请假审批 → 通过后更新考勤状态
生产完工 → 自动入库(产成品) + 扣减原材料库存
工时记录 → 汇总到任务 → 聚合到项目成本
```

## 16. 注文管理 (OMS)

### 16.1 注文管理
- **マルチチャネル注文の取り込み**：manual/web/mobile/api/marketplace/edi/pos 対応
- **注文拡張情報**：チャネル注文番号、店舗、フルフィルメント状態、支払い状態、優先度
- **在庫割当**：ATP（約束可能量）計算 → 在庫予約（悲観ロックで売り切れ防止）
- **フルフィルメントオーケストレーション**：割当 → フルフィルメント作成 → WMS へ指示 → ピッキング/梱包 → TMS 出荷
- **注文キャンセル**：在庫予約を自動解放

### 16.2 RMA 返品交換
- RMA 作成(返品/交換/修理) → 承認 → 返送 → 入荷入庫(stockIn) → 返金
- 返送運賃、返金金額の管理対応

### 16.3 チャネル管理
- チャネルコード/名称/タイプ(direct/marketplace/edi/pos)
- チャネル設定(JSON)、状態の有効/無効

## 17. 倉庫管理 (WMS)

### 17.1 エリア・ロケーション
- **エリア**：入荷エリア/保管エリア/ピッキングエリア/梱包エリア/出荷エリア/返品エリア/品質検査エリア
- **ロケーション拡張**：通路→棚→層→マスの階層 + バーコード/容積/耐荷重/ピッキング順序

### 17.2 入庫フロー
- **ASN（入荷予定通知）**：仕入先→到着予定→運送会社→追跡番号
- **入荷タスク**：月台入荷→実入荷数量入力→品質検査
- **上架タスク**：自動生成→割当→戦略(fifo/zone_fixed/abc)→上架確認(stockIn)

### 17.3 出庫フロー
- **ウェーブ管理**：複数注文を集約→ピッキングウェーブ/出荷ウェーブ→優先度
- **ピッキングタスク**：注文別/一括/ゾーン/ウェーブピッキング→割当→確認(実ピッキング数量)
- **梱包タスク**：梱包タイプ(box/bag/pallet)→重量/寸法

## 18. 輸送管理 (TMS)

### 18.1 運送会社
- 運送会社コード/タイプ(宅配/LTL/トラック満載/航空/海上/鉄道)
- 運送会社サービス：standard/express/overnight/2day/economy + リードタイム
- API 設定：custom/shippo/afterShip/17track 抽象

### 18.2 運賃管理
- **レートカード**：出発地/目的地→重量帯→基本料金/1kg あたり料金/燃油サーチャージ
- **多通貨**：CNY/USD/EUR など、exchange_rate と関連付け
- **運賃比較**：目的国+重量で利用可能な全レートを照会、昇順に並べ替え

### 18.3 運送状と追跡
- **運送状**：運送会社サービス→追跡番号→状態(出荷待ち→集荷済み→輸送中→配達済み/異常/返送)
- **物流追跡**：webhook コールバック→運送状状態を自動同期
- **運送費請求書**：作成→確認→支払い→AP 生成
