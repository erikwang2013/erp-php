## 概要

オープンERPシステム (open-erp) は 23 の業務ドメイン <!-- stats:modules=23 -->、227 のデータテーブル <!-- stats:tables=227 --> をカバーし、進銷存（仕入・在庫・販売）から生産製造、財務会計から人事管理までを提供するフルスタック企業管理システムです。国際化: 13 語種対応（中文/English/日本語/한국어/Deutsch/Français/Español/Português/Русский/العربية/हिन्दी/বাংলা/Bahasa Indonesia）、Accept-Language リクエストヘッダーで自動切替。

## 1. システム管理

### 1.1 ユーザー管理
- 管理者アカウントのライフサイクル全体を管理（作成/編集/削除/有効・無効）
- 一括操作：一括削除、一括有効/無効
- Excel 一括インポート、行単位の検証 + エラーレポート
- パスワードは bcrypt ハッシュで保存、変更には旧パスワードの確認が必要
- 削除などの機密操作には現在のユーザーパスワードによる再確認が必要
- 携帯番号/メール/身分証番号は暗号化保存、一覧では自動マスキング

### 1.2 ロール権限 (RBAC)
- ロール管理：作成/編集/削除、slug 一意識別子
- 権限ツリー：無限階層のツリー構造、3 タイプ——メニュー（ナビゲーション表示）、ボタン（ページ内操作）、API（インターフェースアクセス）
- 権限識別子の形式: `{method}.{path}`、例: `get.admin/product`、`post.admin/user/batch/destroy`
- ロール-権限は多対多の関連付け、スーパー管理者はすべての権限チェックをスキップ
- AdminPermission ミドルウェアが Redis でユーザー権限をキャッシュ（TTL=60s）

### 1.3 システム設定
- キーバリュー保存、グループ管理対応
- 値型: 文字列/整数/ブール/JSON/配列

### 1.4 操作監査
- すべての POST/PUT/DELETE 操作を自動記録
- 操作者、アクション、メソッド、パス、IP、パラメータ（機密フィールドはマスキング）、時間を記録
- 8 プラットフォームのクライアント種別を自動検出（Web/Flutter/HarmonyOS/API など）
- 読み取り専用照会、削除や変更は不可

### 1.5 セキュリティ対策
- 7 層の多層防御：HTTP メソッド制限、XSS/SQL インジェクション/パストラバーサル/コマンドインジェクション/CSRF ブロック
- クリック式 CAPTCHA（ログイン/登録で強制検証）
- Redis スライディングウィンドウレート制限（Lua アトミック、デフォルト 60回/分）
- アカウントロック：5 回失敗で 15 分ロック
- 同時セッション制限：同一ユーザーの有効トークンは最大 3 つ
- CSP ヘッダー、security.txt (RFC 9116)
- 機密操作のランダム二次検証（poster-php）

## 3. 購買管理

### 3.1 購買申請
- 部門/担当者が購買ニーズを申請
- 承認フロー：承認待ち → 承認済み/却下済み → 注文化済み
- 承認ワークフローエンジンへの接続可

### 3.2 購買注文
- 仕入先、商品明細（数量、単価、金額）を関連付け
- 状態：審査待ち → 審査済み → 一部入荷 → 入荷済み → キャンセル済み
- 申請に基づいて作成可、直接作成も可

### 3.3 購買入荷（モジュール横断連動）
- 注文に基づく入荷、分割入荷対応
- 入荷で自動トリガー: ① 入庫（移動加重平均原価計算）② 買掛記録の生成 ③ 注文の入荷済み数量を更新

### 3.4 購買返品
- 仕入先へ返品、出庫相殺を生成

### 3.5 仕入先決済
- 仕入先単位で集計：購買金額、支払済み、買掛
- 状態：未決済/一部決済/決済済み

## 4. 販売管理

### 4.1 見積書
- 顧客へ見積提示、販売注文への変換対応
- 状態：草稿 → 見積済み → 注文化済み → 失効

### 4.2 販売注文
- 顧客、商品明細（数量、単価、割引）を関連付け
- 状態：審査待ち → 審査済み → 一部出荷 → 出荷済み → キャンセル済み

### 4.3 販売出荷（モジュール横断連動）
- 注文に基づく出荷、分割出荷対応
- 出荷で自動トリガー: ① 出庫（移動加重平均原価ベース）② 売掛記録の生成 ③ 注文の出荷済み数量を更新

### 4.4 販売返品
- 顧客からの返品、入庫相殺を生成

### 4.5 顧客決済と粗利
- 顧客単位で集計：販売金額、回収済み、売掛
- 注文/商品/顧客の次元で粗利を計算

### 4.6 顧客与信管理（v1.4.0 納品）

- 与信限度額管理：顧客ごとに与信限度額・占有・遮断ルールを維持
- 受注/出荷前の遮断：CreditControlService assertOrderCreate / assertDeliveryCreate / guard が限度超過の注文を拒否し、理由を返します

## 5. 在庫管理

### 5.1 リアルタイム在庫
- 4 次元の精度：倉庫 + ロケーション + ロット + SKU
- 複数倉庫、複数ロケーション対応
- リアルタイム在庫照会

### 5.2 入出庫流水
- すべての在庫変動を統一的に記録（方向、数量、原価単価、元伝票番号、時間）

### 5.3 ロット追跡
- 製造日、賞味期限、ロット番号
- 入出庫時にロットを記録

### 5.4 シリアル番号追跡
- 一意のシリアル番号管理
- 入出庫時に状態を記録（在庫中/出庫済み）

### 5.5 原価計算
- 移動加重平均法
- 公式: 新平均単価 = (元在庫総額 + 今回入庫総額) / (元在庫数量 + 今回入庫数量)
- 入庫のたびに自動再計算、出庫は現在の平均単価で原価計上

### 5.6 在庫振替
- 倉庫間/ロケーション間の振替
- 状態：振替待ち → 出庫済み → 入庫済み → 完了
- 出庫/入庫の流水を自動生成

### 5.7 棚卸管理
- 計画棚卸（倉庫/カテゴリ単位）+ 動的棚卸（SKU 単位）
- 帳簿数量 vs 実地数量を記録
- 差異は棚卸差益/差損の流水を自動生成

### 5.8 在庫アラート
- SKU+倉庫 単位で上下限を設定
- 下限未満/上限超過でアラートログを自動記録

### 5.9 ロット/シリアル番号の追跡と有効期限アラート（v1.4.0 納品）

- 追跡チェーン：TraceService forward/backward がロットの行き先/由来を正方向・逆方向に追跡、serial はシリアル番号台帳
- 有効期限アラート：expiryAlert が期限間近および期限切れのロットを通知

## 6. 財務管理

### 6.1 売掛・買掛
- 購買入荷/販売出荷から自動生成
- 状態：未消込 → 一部消込 → 消込済み
- 同一発注元伝票の冪等保護

### 6.2 入金管理
- 複数口座（現金/銀行/微信/支付宝）
- 審査後に口座残高と現金仕訳帳を自動更新
- 売掛記録の消込対応

### 6.3 出金管理
- 入金と同じロジック、方向は逆
- 買掛記録の消込対応

### 6.4 現金・銀行仕訳帳
- 口座+日付単位で入出金の流水を記録
- 銀行口座残高をリアルタイム更新

### 6.5 費用精算
- フロー：申請 → 承認 → 支払い
- 支払い後に出金伝票 + 仕訳帳を自動生成

### 6.6 損益計算書
- 月単位で集計：営業収益、営業原価、費用、利益
- スナップショット保存（year+month 一意）

### 6.7 固定資産
- 資産ライフサイクル全体：取得 → 使用 → 減価償却 → 処分
- 定額法： (取得原価-残存価額) / 使用月数
- 毎月減価償却を計上し、償却記録を自動生成
- 記録：取得原価、残存価額、使用年数、月次償却額、累計償却額、帳簿価額

### 6.8 税務管理
- 複数税種：付加価値税/法人所得税/個人所得税/印紙税
- 税率を柔軟に設定（4 つのデフォルト税率シードデータ含む）
- 購買/販売伝票と関連付け、税額を自動記録

### 6.9 多通貨
- 通貨管理：CNY/USD/EUR/JPY（4 つのデフォルト通貨シードデータ含む）
- 本座通貨の標識
- 為替レートは発効日で管理

### 6.10 予算管理
- 年度予算編成：コストセンター + 科目 + 月単位
- 予算 vs 実績の比較分析（執行率 + 差異）
- 状態：草稿 → 承認済み → 執行中 → クローズ済み

### 6.11 コストセンター/利益センター
- ツリー型の階層構造
- コスト集計 + 費用配賦
- 利益センターは独立採算

### 6.12 期末振替 / 多組織会計 / 連結決算（v1.4.0 納品）

- 期末損益振替：期間ごとに損益科目の発生額を集計（収益類 - 費用類 = 当期純利益、status=calculated）
- 振替は伝票を生成しません（本年利益科目の設定と重複振替防止ルールが未整備）、コントローラーのエンドポイントもなし —— v1.4.0 の納品には含めず、TODO として保留
- 多組織会計：CompanyController / LedgerPeriodController による独立した核算主体と会計期間（v1.4.0 納品）
- 連結決算エンジン（v1.4.0 納品）：ConsolidationService rateToBase/translateLedger による期末レート換算（レートがなければ拒否）、addElimination による子会社間の相殺（貸借一致の検証付き）、generateDraft による出表（確定済み期間はスナップショットを読み、スナップショットがなければ承認済み伝票からリアルタイム再計算）、issue の重複出具防止、latest/list；結果は FinanceConsolidationReport に保存
- テスト：PeriodCloseServiceTest 4 例 + ConsolidationServiceTest 3 例

### 6.13 棚卸資産と生産原価の計算（v1.4.0 納品）

- 生産への材料払出と原価集計：MaterialIssueController が払出を出庫として計上し、CostEntryController + MfgCostService が製造オーダー単位で材料費/労務費/製造間接費を集計
- 伝票ルール：MfgCostVoucherRule が完成原価と差異の振替伝票を生成（§12 製造オーダーと連動）

### 6.14 手形と銀行勘定調整（v1.4.0 納品）

- 手形の全ライフサイクル：FinanceBillService store/update/endorse（裏書）/discount（割引）/collect（取立）/cash（決済）/reject + dueWarnings 期日アラート
- 銀行勘定調整：BankReconService importStatement 明細取込、autoReconcile/manualReconcile/unreconcile 消込、reconReport 調整レポート

### 6.15 仕入税額控除プールと電子インボイス（v1.4.0 納品）

- 仕入プール：TaxInvoicePoolService registerOne/registerBatch/verify/check/deduct/deductStats；検証は MockTaxVerifier 経由（実際の税務当局チャネルはアダプターポイント）
- 電子インボイス：EInvoiceService issueInvoice/voidInvoice/issueLogs、EInvoiceAdapter/MockEInvoiceAdapter 経由（実際の税務当局チャネルはアダプターポイント）
