## 適用シーン

| エディション | 推奨シーン |
|------|---------|
| **Lite** | 中小規模の商貿企業。進銷存+基礎財務を中核とし、承認プロセスや拡張モジュールを必要としない |
| **Standard** | 同等の機能規模でデータテーブル設計を簡素化。カスタマイズ開発のベースに適する |
| **Full** | 中大手企業。完全な進銷存+財務+CRM+HR+製造+プロジェクト管理のフルスタックプラットフォームが必要 |

## ブランチ戦略（2026-08 より）

> 本ドキュメントはリポジトリの現行バージョンブランチ規約に対応し、`lite` / `standard` / `full` の 3 ブランチに適用されます。

- **`main` は唯一の開発源**: すべての機能開発、欠陥修正、依存関係アップグレードは一律に `main` へマージします。
- **バージョンブランチはリリース時の cherry-pick のみ**: `lite` / `standard` / `full` は独立した開発ラインとして日常コミットを受け付けず、
  リリース時にバージョンエンジニアが `main` から対応機能を cherry-pick し（または必要に応じて 1 回の全体マージを行い）、
  ブランチごとの裁剪意図（モジュール差異は上記機能比較表を参照）を保持します。
- **裁剪原則**: バージョンブランチ = main のサブセット。main の内容をマージ/移植する際、衝突がバージョン裁剪ロジック
  （EDITIONS.md のモジュール差異、ルート裁剪など）に該当する場合はブランチの裁剪意図を保持し、無関係なコードはすべて main 版を優先します。
- **検証**: バージョンブランチのマージ後は `php -l` による全量構文チェックを必須とします。裁剪により適用不能なテストはスキップを許可し、理由を記録します。
- **リリース**: バージョンブランチのマージ/移植はバージョンエンジニアが実施し merge commit を提出します。`main` のコミットは Lead が一括実行します。
