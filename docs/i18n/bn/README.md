## ERP মডিউল

বিভিন্ন ব্যবসায়িক মডিউলের মধ্যে ডেটা প্রবাহ:

- ক্রয় রিসিভ → স্বয়ংক্রিয় স্টক-ইন (মুভিং ওয়েটেড এভারেজ খরচ হিসাব) → স্বয়ংক্রিয় AP (পেয়েবল) তৈরি
- বিক্রয় ডেলিভারি → স্বয়ংক্রিয় স্টক-আউট → স্বয়ংক্রিয় AR (রিসিভেবল) তৈরি
- রসিদ ও পেমেন্ট → AR/AP রাইট-অফ → জার্নাল আপডেট
- ভাউচার অনুমোদন → স্বয়ংক্রিয়ভাবে জেনারেল লেজার (অ্যাকাউন্ট সমষ্টি) + সাবসিডিয়ারি লেজার (প্রতি লেনদেন রেকর্ড) আপডেট
- ব্যালেন্স শিট → স্বয়ংক্রিয়ভাবে জেনারেল লেজারের সমাপনী ব্যালেন্স থেকে তৈরি
- ক্যাশ ফ্লো স্টেটমেন্ট → স্বয়ংক্রিয়ভাবে ক্যাশ ও ব্যাংক জার্নাল থেকে তৈরি (অপারেটিং/ইনভেস্টিং/ফাইন্যান্সিং তিন শ্রেণি)
- অ্যাপ্রুভাল ওয়ার্কফ্লো → ব্যবসায়িক ডকুমেন্ট অনুমোদনের জন্য সাবমিট → মাল্টি-নোড প্রবাহ → অনুমোদনের ফলাফল ব্যবসায়িক মডিউলে ফিরে যায়
- নোটিফিকেশন → অনুমোদন/সতর্কতা/সিস্টেম ইভেন্ট ট্রিগার → রিয়েল-টাইম পুশ → ব্যবহারকারী পঠিত চিহ্নিত করে
- MRP → সেলস অর্ডার + BOM ভিত্তিক → মেটেরিয়াল চাহিদা গণনা → ক্রয়/উৎপাদন পরামর্শ তৈরি
- OMS → মাল্টি-চ্যানেল অর্ডার ইমপোর্ট → ইনভেন্টরি রিজার্ভেশন (ATP) → ফুলফিলমেন্ট তৈরি → WMS-এ পিকিং/প্যাকিং নির্দেশ
- WMS → ওয়েভ সমষ্টিকরণ → পিকিং টাস্ক → পিকিং নিশ্চিতকরণ → প্যাকিং সম্পন্ন → TMS শিপমেন্ট তৈরি
- TMS → ফ্রেট তুলনা → শিপমেন্ট তৈরি → ডেলিভারি নিশ্চিতকরণ (stockOut+AR) → ট্র্যাকিং → স্বাক্ষর
- WMS ইনবাউন্ড → ASN প্রি-অ্যারাইভাল → রিসিভিং → কোয়ালিটি পরীক্ষা → পুটওয়ে নিশ্চিতকরণ (stockIn+AP) → ইনভেন্টরি আপডেট
- RMA → রিটার্ন আবেদন → অনুমোদন → রিটার্ন স্টক-ইন → রিফান্ড

### রিকোয়েস্ট লাইফসাইকেল

![Request Lifecycle](diagrams/request-lifecycle-cn.svg)

**ক্লায়েন্ট থেকে ডাটাবেস পর্যন্ত সম্পূর্ণ রিকোয়েস্ট পাথ**: ক্লায়েন্ট (Flutter/হারমনি) → Nginx SSL টার্মিনেশন → ভাষা শনাক্তকরণ → ক্রস-অরিজিন হ্যান্ডলিং → নিরাপত্তা ফিল্টার → রেট লিমিট → API ভার্সন যাচাই → [অ্যাডমিন: JWT প্রমাণীকরণ → RBAC অনুমোদন → অপারেশন লগ] → কন্ট্রোলার → সার্ভিস স্তর → মডেল স্তর → ক্যাশ/ডাটাবেস/সার্চ ইঞ্জিন → JSON রেসপন্স। চিত্রে ক্যাশ হিট ও ক্যাশ মিস দুটি পথ অন্তর্ভুক্ত।

### নিরাপত্তা ডিফেন্স-ইন-ডেপথ আর্কিটেকচার

![Security Architecture](diagrams/security-architecture-cn.svg)

**১৮ স্তরের ডিফেন্স-ইন-ডেপথ**: L0 ফিজিক্যাল নেটওয়ার্ক → L1 ট্রান্সমিশন নিরাপত্তা → L2 HTTP নিরাপত্তা হেডার → L3 রিকোয়েস্ট যাচাই → L4 ইনপুট স্যানিটাইজেশন → L5 CSRF সুরক্ষা → L6 রেট লিমিট → L7 প্রমাণীকরণ (JWT+Captcha+ব্ল্যাকলিস্ট+সেশন কন্ট্রোল) → L8 RBAC অনুমোদন → L9 ডেটা সুরক্ষা (ট্রান্সমিশন এনক্রিপশন+স্টোরেজ এনক্রিপশন+ID অবসিকিউরেশন+ডেটা মাস্কিং) → L10 অডিট মনিটরিং → L11 কমপ্লায়েন্স ডিসক্লোজার।

মূল কনফিগারেশন আইটেম:

### 6. Docker Compose এক-ক্লিক ডিপ্লয়মেন্ট (প্রোডাকশনের জন্য সুপারিশকৃত)

# 1. Docker 环境变量配置

# 2. 启动所有服务

# 3. 初始化数据库（进入 app 容器执行）

# 4. 访问
# http://localhost:8788  (webman)

- `docker-compose.yml`: ৫টি সার্ভিস অর্কেস্ট্রেশন, নেটওয়ার্ক আইসোলেশন, ডেটা ভলিউম পার্সিস্টেন্স

## ব্যবহার

### 1. লগইন

প্রথম ব্যবহারে ওয়েব ইনস্টলার `http://localhost:8788/install` খুলে ইনস্টলেশন সম্পন্ন করুন এবং অ্যাডমিন অ্যাকাউন্ট তৈরি করুন। ইনস্টল হয়ে গেলে কনসোল খুলুন, পরিচয়পত্র দিন এবং ক্লিক-ক্যাপচা পাস করে লগইন করুন।

### 2. নেভিগেশন

লগইনের পর সাইডবার থেকে মডিউলগুলোতে যান: ড্যাশবোর্ড, পণ্য, ক্রয়, বিক্রয়, ইনভেন্টরি, অর্থ, CRM, অনুমোদন ওয়ার্কফ্লো, বিজ্ঞপ্তি, প্রকল্প, মানবসম্পদ, উৎপাদন, কাস্টম রিপোর্ট, OMS/WMS/TMS, BI ড্যাশবোর্ড এবং সিস্টেম প্রশাসন (ব্যবহারকারী/ভূমিকা/কনফিগ/লগ)। সাইডবার ডেস্কটপে স্থির এবং মোবাইলে ড্রয়ারে ভাঁজ হয়।

### 3. অনুমতি ও নিরাপত্তা

- ফিচার ও API RBAC দ্বারা নিয়ন্ত্রিত; অনুমতি ছাড়া মেনু ও ইন্টারফেস অগম্য (403)
- সংবেদনশীল কাজ (ব্যবহারকারী/ভূমিকা মুছে ফেলা) অনুরোধে বর্তমান পাসওয়ার্ড নিশ্চিতকরণ প্রয়োজন
- লগআউটের পর টোকেন সঙ্গে সঙ্গে ব্ল্যাকলিস্ট হয়

### 4. বহুভাষা

`Accept-Language` হেডার দিয়ে স্বয়ংক্রিয় সুইচিং (zh-CN / en), ডিফল্ট চীনা।

## ডাটাবেস নিয়মাবলী

- **টেবিল প্রিফিক্স**: `erp_`
- **প্রাইমারি কী**: সব টেবিলের প্রাইমারি কী `id BIGINT UNSIGNED NOT NULL`, **AUTO_INCREMENT নিষিদ্ধ**
- **ID তৈরি**: প্রাইমারি কী ID অ্যাপ্লিকেশন স্তরের `SnowflakeService::generate()` দিয়ে তৈরি, ডিস্ট্রিবিউটেড ইউনিক
- **অবশ্যই থাকতে হবে**: প্রতিটি টেবিলে `id`, `created_at`, `updated_at` থাকতে হবে
- **সফট ডিলিট**: সফট ডিলিট প্রয়োজন হলে `deleted_at DATETIME DEFAULT NULL` যোগ করুন
- **সংবেদনশীল ফিল্ড**: ফোন নম্বর, ইমেইল, আইডি কার্ড নম্বর ইত্যাদি `encryptable` প্লাগইন দিয়ে স্বয়ংক্রিয় এনক্রিপশন/ডিক্রিপশন, ডাটাবেস ফিল্ডে `VARCHAR(500)` সাইফারটেক্সট সংরক্ষিত

| `403` | অনুমতি নেই / নিরাপত্তা ব্লক | RBAC অনুমোদন ব্যর্থ / SecurityFilter আক্রমণ শনাক্ত |
| `404` | রিসোর্স নেই | |

| `413` | রিকোয়েস্ট বডি অতিরিক্ত বড় | SecurityFilter ট্রিগার, ১০MB-এর বেশি |
| `405` | রিকোয়েস্ট মেথড অনুমোদিত নয় | SecurityFilter ট্রিগার, শুধুমাত্র GET/POST/PUT/DELETE/OPTIONS/HEAD অনুমোদিত |

| `500` | সার্ভার অভ্যন্তরীণ ত্রুটি | |

### ইন্টারন্যাশনালাইজেশন

রিকোয়েস্ট হেডার `Accept-Language` স্বয়ংক্রিয়ভাবে ভাষা পরিবর্তন করে (zh-CN → চীনা, en → English), ডিফল্ট চীনা।

### ID হ্যান্ডলিং

- **রিকোয়েস্ট/রেসপন্সে ID**: hashids দিয়ে স্ট্রিং এনক্রিপ্ট করা, প্রকৃত ডাটাবেস ID প্রকাশ করা হয় না
- **ইন্টারফেস পাথ**: `GET /admin/user/{hashid}` — পাথে `{id}` হলো hashid স্ট্রিং
- **ডাটাবেস স্টোরেজ**: BIGINT আসল মান, snowflake দিয়ে তৈরি

### API ভার্সন

API ভার্সন রিকোয়েস্ট হেডার দিয়ে নিয়ন্ত্রিত, **URL-এ প্রকাশ করা হয় না**:

```http
API-Version: v1
```

- ভার্সন নম্বর না থাকলে ডিফল্ট `v1` ব্যবহৃত হয়
- অসমর্থিত ভার্সন `400 Bad Request` রিটার্ন করে
- নতুন ভার্সন যোগ করতে শুধু `app/api/{version}/controller/` ডিরেক্টরি তৈরি করে মিডলওয়্যারে নতুন ভার্সন নিবন্ধন করুন

### রেট লিমিট

Redis স্লাইডিং উইন্ডো অ্যালগরিদম ভিত্তিক, ডিফল্ট ৬০ বার/মিনিট/IP/রুট। সংবেদনশীল ইন্টারফেস আরও কঠোর:
- লগইন: ১০ বার/মিনিট
- রেজিস্টার: ৫ বার/মিনিট (ডিফল্ট বন্ধ, `REGISTRATION_ENABLED=1` দিয়ে চালু করতে হবে)

রেসপন্স হেডারে `X-RateLimit-Limit`, `X-RateLimit-Remaining`, `X-RateLimit-Reset` অন্তর্ভুক্ত। সীমা অতিক্রম করলে 429 রিটার্ন হয় এবং `Retry-After` সংযুক্ত থাকে।

### মিডলওয়্যার আর্কিটেকচার

গ্লোবাল মিডলওয়্যার সব রিকোয়েস্টে প্রযোজ্য, ক্রমানুসারে কার্যকর হয়:

```
Locale（Accept-Language 自动检测，设置语言环境）
  → Cors（跨域预处理 + 响应头）
  → SecurityFilter（HTTP方法限制/请求体大小/Content-Type校验/XSS/SQL注入/路径遍历/命令注入/CSRF 攻击拦截）
  → RateLimit（Redis 滑动窗口限流 + 账号锁定：5次登录失败锁定15分钟）
  → ApiVersion（API 版本校验，/api 路由组）
  → AdminAuth（JWT 认证 + 黑名单，/admin 路由组）
  → AdminPermission（RBAC 鉴权，/admin 路由组）
  → OperationLog（POST/PUT/DELETE 自动记录，含来源端检测，/admin 路由组）
```

`/health`, `/api/docs` এবং `/install` পাবলিক এন্ডপয়েন্ট, শুধুমাত্র `Locale → Cors → SecurityFilter → RateLimit` মধ্য দিয়ে যায়।

নিরাপত্তা বর্ধিতকরণ:
- **অ্যাকাউন্ট লক**: একটানা ৫ বার লগইন ব্যর্থ হলে অ্যাকাউন্ট স্বয়ংক্রিয়ভাবে ১৫ মিনিট লক হয়, লক অবস্থায় লগইন 429 রিটার্ন করে
- **কনকারেন্ট সেশন সীমা**: একজন ব্যবহারকারীর সর্বোচ্চ ৩টি সক্রিয় টোকেন, বেশি হলে সবচেয়ে পুরনো টোকেন স্বয়ংক্রিয়ভাবে ব্ল্যাকলিস্টে যায়
- **security.txt**: `GET /.well-known/security.txt` RFC 9116 স্ট্যান্ডার্ড নিরাপত্তা যোগাযোগ তথ্য প্রদান করে
- **Nginx নিরাপত্তা কনফিগারেশন**: `nginx-security.conf` দেখুন, সম্পূর্ণ রিভার্স প্রক্সি নিরাপত্তা শক্তিশালীকরণ উদাহরণ প্রদান করে

### প্রমাণীকরণ

লগইন ও রেজিস্টারের আগে **ক্লিক ক্যাপচা** যাচাই পাস করতে হবে:

1. ক্লায়েন্ট `POST /api/captcha/generate` রিকোয়েস্ট করে ক্যাপচা ছবি (base64 PNG) ও টেক্সট টার্গেট তালিকা পায়
2. ব্যবহারকারী ক্রমানুসারে ছবির সংশ্লিষ্ট টেক্সট অবস্থানে ক্লিক করে, ক্লিক কোঅর্ডিনেট সংগ্রহ করে `[{x, y}, ...]`
3. লগইনের সময় `captcha_key` ও `clicks` একসাথে সাবমিট করে, সার্ভার প্রথমে ক্যাপচা তারপর ক্রেডেনশিয়াল যাচাই করে

```http
POST /api/auth/login
Content-Type: application/json

{
  "username": "admin",
  "password": "******",
  "captcha_key": "abc123...",
  "clicks": [{"x": 120, "y": 85}, {"x": 210, "y": 140}, {"x": 95, "y": 170}]
}
```

অ্যাডমিন পরবর্তী ইন্টারফেসে JWT প্রমাণীকরণ প্রয়োজন:

```http
Authorization: Bearer <token>
```

লগইন সফল হলে access_token রিটার্ন হয়, ২ ঘণ্টা বৈধ; আরও refresh_token রিটার্ন হয়, ১৪ দিন বৈধ।

লগআউটের সময় টোকেন Redis ব্ল্যাকলিস্টে যায়, বৈধতা সময়ের মধ্যে পুনরায় ব্যবহার করা যায় না। POST /admin/profile/logout

### সংবেদনশীল অপারেশনের দ্বিতীয় নিশ্চিতকরণ

ইউজার, রোল, পারমিশন ইত্যাদি সংবেদনশীল অপারেশন মুছে ফেলতে রিকোয়েস্ট বডিতে বর্তমান লগইন করা ব্যবহারকারীর `password` পাঠিয়ে দ্বিতীয় নিশ্চিতকরণ করতে হয়:

```http
DELETE /admin/user/{id}
Content-Type: application/json
Authorization: Bearer <token>

{ "password": "******" }
```

- সব PHP ফাইলের শুরুতে কপিরাইট স্টেটমেন্ট থাকতে হবে
- সব কনফিগারেশন ফাইলে চীনা কমেন্ট বিবরণ থাকতে হবে
- ডাটাবেস প্রাইমারি কী অ্যাপ্লিকেশন স্তরের snowflake দিয়ে তৈরি হতে হবে, অটোইনক্রিমেন্ট নিষিদ্ধ
- API স্তরের সব প্যারামিটার ও রেসপন্সের ID hashids দিয়ে এনক্রিপ্ট/ডিক্রিপ্ট করতে হবে
- AdminPermission মিডলওয়্যার Redis ক্যাশে ইউজার পারমিশন রাখে (TTL=60s), N+1 কোয়েরি বটলনেক দূর করে

## ডিপ্লয়মেন্ট

### Docker Compose (সুপারিশকৃত)

প্রজেক্ট রুট ডিরেক্টরিতে `docker-compose.yml` আছে, ৫টি সার্ভিস অর্কেস্ট্রেট করে:

| সার্ভিস | ইমেজ | পোর্ট |
|------|------|------|
| `nginx` | nginx:alpine | 80, 443 |
| `app` | লোকাল `Dockerfile` দিয়ে তৈরি | 8788 |
| `mysql` | mysql:8.0 | 3306 |
| `redis` | redis:7-alpine | 6379 |
| `elasticsearch` | elasticsearch:8.x | 9200 |

PHP ইমেজ `Dockerfile` দিয়ে তৈরি, বেস ইমেজ `php:8.3-cli`, OPcache সক্রিয়।

```bash
cp .env.docker .env
docker-compose up -d
```

### CI/CD

GitHub Actions কন্টিনিউয়াস ইন্টিগ্রেশন পাইপলাইন: `.github/workflows/ci.yml`

- PHP সিনট্যাক্স চেক (`php -l`)
- PHPUnit ইউনিট টেস্ট
- Flutter স্ট্যাটিক অ্যানালাইসিস (`flutter analyze`, CI-তে অন্তর্ভুক্ত, সক্রিয় — `.github/workflows/ci.yml` এর flutter job দেখুন)

### ডাটাবেস ব্যাকআপ

`database/backup/` ডিরেক্টরি:

- `backup.sh` — mysqldump + gzip ব্যাকআপ, ৩০ দিনের আগের পুরনো ব্যাকআপ স্বয়ংক্রিয় পরিষ্কার
- `restore.sh` — ইন্টারঅ্যাক্টিভ রিস্টোর, উপলব্ধ ব্যাকআপ তালিকা থেকে বেছে নেওয়া যায়

### Nginx নিরাপত্তা কনফিগারেশন

প্রোডাকশন ডিপ্লয়মেন্টে `nginx-security.conf` দেখে রিভার্স প্রক্সি নিরাপত্তা শক্তিশালীকরণ কনফিগার করুন।
