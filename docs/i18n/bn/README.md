## প্রকল্প পরিচিতি

open-erp হলো ছোট ও মাঝারি প্রতিষ্ঠানের জন্য একটি **ওপেন সোর্স ফুল-স্ট্যাক ERP সিস্টেম**, যা ক্রয়-বিক্রয়-স্টক (ক্রয়/বিক্রয়/ইনভেন্টরি)、আর্থিক হিসাবরক্ষণ、উৎপাদন (BOM/MRP/অপারেশন রিপোর্টিং/ক্যাপাসিটি লোড)、CRM、অনুমোদন ওয়ার্কফ্লো、মানবসম্পদ、নোটিফিকেশন ও কাস্টম রিপোর্টসহ সম্পূর্ণ ব্যবসায়িক ডোমেইন কভার করে। ব্যাকএন্ড webman v2 + MySQL 8.0 দিয়ে তৈরি (টেবিল প্রিফিক্স `erp_`, Snowflake গ্লোবাল ইউনিক প্রাইমারি কী); অ্যাডমিন এন্ডে Angular 22 (`apps/angular/`)、React 19 + Vite (`apps/react/`) ও Flutter 3.x Web (`apps/flutter/`) — তিনটি বাস্তবায়ন; মোবাইল প্রান্তে HarmonyOS নেটিভ ক্লায়েন্ট (`apps/harmonyos/`)।

সিস্টেমের মূল ডিজাইন **ডকুমেন্ট-চালিত、স্বয়ংক্রিয় সংযোগ**: ব্যবসায়িক ডকুমেন্ট অডিট হলে স্বয়ংক্রিয়ভাবে স্টক পরিবর্তন、AR/AP তৈরি ও খরচ সংগ্রহ হয়; অনুমোদন ওয়ার্কফ্লো ও নোটিফিকেশন সব গুরুত্বপূর্ণ ডকুমেন্ট জুড়ে থাকে; MRP বিক্রয় অর্ডার ও BOM অনুযায়ী মেটেরিয়াল চাহিদা হিসাব করে ক্রয়/উৎপাদন প্রস্তাব তৈরি করে, ফলে বিক্রয় অর্ডার গ্রহণ থেকে ক্রয় রিসিভ、উৎপাদন শিডিউলিং থেকে আর্থিক ক্লোজিং পর্যন্ত এন্ড-টু-এন্ড ব্যবসায়িক লুপ সম্পূর্ণ হয়।

## প্রকল্প বিবরণ

- **সুনির্দিষ্ট দশমিক হিসাব**: অর্থ、পরিমাণ、ওজন ইত্যাদি ব্যবসায়িক সংখ্যা bcmath দশমিক অপারেশনে হিসাব হয়; মুভিং ওয়েটেড এভারেজ কস্ট、AR/AP সমন্বয় ও সব রিপোর্ট আউটপুট স্ট্রিং নির্ভুলতায় — কোনো ফ্লোটিং পয়েন্ট ত্রুটি নেই
- **এন্টারপ্রাইজ-স্তরের নিরাপত্তা বেসলাইন**: JWT টোকেন + RBAC মেথড-স্তরের অথেনটিকেশন、ডিপ ডিফেন্স (L0–L12 স্তরভিত্তিক প্যানোরামা + ৩৫ ধরনের অ্যাটাক ডিটেক্টর + ৭ স্তরের মিডলওয়্যার চেইন, XSS/SQL ইনজেকশন/CSRF/রেট লিমিট/CSP ইত্যাদি)、সংবেদনশীল ফিল্ড স্টোরেজ এনক্রিপশন ও ইন্টারফেস ট্রান্সমিশন এনক্রিপশন、সম্পূর্ণ অপারেশন অডিট ট্রেইল
- **কনফিগারেশন-চালিত সক্ষমতা**: মাল্টি-নোড অনুমোদন ওয়ার্কফ্লো (ভিজ্যুয়াল ফ্লো ডিজাইনার ক্যানভাস সহ)、ডকুমেন্ট প্রিন্ট টেমপ্লেট ইঞ্জিন (প্লেসহোল্ডার রেন্ডারিং + dompdf দিয়ে PDF + QR কোড লেবেল)、রিয়েল-টাইম কাস্টমার ক্রেডিট লিমিট ইন্টারসেপ্ট、ব্যাচ/সিরিয়াল নম্বরের সম্পূর্ণ ফরওয়ার্ড-ব্যাকওয়ার্ড ট্রেসেবিলিটি
- **ডেটা ট্রেসেবিলিটি**: ব্যবসায়িক ফ্লো প্রতি এন্ট্রিতে ট্রেইল রেখে যায়, ইনভেন্টরি ব্যাচ ও সিরিয়াল নম্বর স্টক-ইন→ইস্যু→স্টক-আউট→ট্রেস পুরো লাইফসাইকেল জুড়ে; কস্ট অ্যাকাউন্টিং ডকুমেন্ট-লাইন স্তর পর্যন্ত
- **ডিপ্লয়মেন্ট-বান্ধব**: Docker Compose v2 এক-ক্লিকে চালু (MySQL/Redis/Elasticsearch), লোকাল `composer install` দিয়েও সরাসরি চালানো যায়
- **ইন্টারন্যাশনালাইজেশন**: ১৩টি ভাষা (zh/en/ja/ko/de/fr/es/pt/ru/ar/hi/bn/id), ব্যাকএন্ড বার্তা এবং Angular/React দুই অ্যাডমিন এন্ডের ইন্টারফেস—দুটোই সম্পূর্ণ কভার; ফ্রন্টএন্ড অভিধান ভাষা অনুযায়ী লেজি-লোড হয়, README আলাদাভাবে ১২ ভাষায় ডকুমেন্টেশন দেয়

## ERP মডিউল

বিভিন্ন ব্যবসায়িক মডিউলের মধ্যে ডেটা প্রবাহ:

- ক্রয় রিসিভ → স্বয়ংক্রিয় স্টক-ইন (মুভিং ওয়েটেড এভারেজ খরচ হিসাব) → স্বয়ংক্রিয় AP (পেয়েবল) তৈরি
- বিক্রয় ডেলিভারি → স্বয়ংক্রিয় স্টক-আউট → স্বয়ংক্রিয় AR (রিসিভেবল) তৈরি
- রসিদ ও পেমেন্ট → AR/AP রাইট-অফ → জার্নাল আপডেট
- ভাউচার অনুমোদন → স্বয়ংক্রিয়ভাবে জেনারেল লেজার (অ্যাকাউন্ট সমষ্টি) + সাবসিডিয়ারি লেজার (প্রতি লেনদেন রেকর্ড) আপডেট
- ব্যালেন্স শিট → স্বয়ংক্রিয়ভাবে জেনারেল লেজারের সমাপনী ব্যালেন্স থেকে তৈরি
- ক্যাশ ফ্লো স্টেটমেন্ট → স্বয়ংক্রিয়ভাবে ক্যাশ ও ব্যাংক জার্নাল থেকে তৈরি (অপারেটিং/ইনভেস্টিং/ফাইন্যান্সিং তিন শ্রেণি)
- অ্যাপ্রুভাল ওয়ার্কফ্লো → ব্যবসায়িক ডকুমেন্ট অনুমোদনের জন্য সাবমিট → মাল্টি-নোড প্রবাহ → অনুমোদনের ফলাফল ব্যবসায়িক মডিউলে ফিরে যায়
- নোটিফিকেশন → অনুমোদন/সতর্কতা/সিস্টেম ইভেন্ট ট্রিগার → রিয়েল-টাইম পুশ → ব্যবহারকারী পঠিত চিহ্নিত করে
- MRP → সেলস অর্ডার + BOM ভিত্তিক → মেটেরিয়াল চাহিদা গণনা → ক্রয়/উৎপাদন পরামর্শ তৈরি
- OMS → মাল্টি-চ্যানেল অর্ডার ইমপোর্ট → ইনভেন্টরি রিজার্ভেশন (ATP) → ফুলফিলমেন্ট তৈরি → WMS-এ পিকিং/প্যাকিং নির্দেশ
- WMS → ওয়েভ সমষ্টিকরণ → পিকিং টাস্ক → পিকিং নিশ্চিতকরণ → প্যাকিং সম্পন্ন → TMS শিপমেন্ট তৈরি
- TMS → ফ্রেট তুলনা → শিপমেন্ট তৈরি → ডেলিভারি নিশ্চিতকরণ (stockOut+AR) → ট্র্যাকিং → স্বাক্ষর
- WMS ইনবাউন্ড → ASN প্রি-অ্যারাইভাল → রিসিভিং → কোয়ালিটি পরীক্ষা → পুটওয়ে নিশ্চিতকরণ (stockIn+AP) → ইনভেন্টরি আপডেট
- RMA → রিটার্ন আবেদন → অনুমোদন → রিটার্ন স্টক-ইন → রিফান্ড

| ব্যাকএন্ড বার্তা | `resource/translations/{ভাষা}/` | ১৩টি ভাষা ডিরেক্টরি: `zh_CN` ৫৬৫টি এন্ট্রি, বাকি ১১টি ভাষায় প্রতিটি ৫৪৪টি, `en` ৩০টি (গণনা: `common/modules/validation` তিন ফাইলের লিফ এন্ট্রি, `validation.php`-এর `attributes` ফিল্ড লেবেল গণনায় ধরা হয়, তার গ্রুপ কী ধরা হয় না) |
| Angular অ্যাডমিন | `apps/angular/src/app/core/zh-*.ts` (সোর্স অভিধান `zh-en/`, ৪টি স্লাইস একত্রিত) | সোর্স অভিধানে ১৪৫৬টি কী × ১১টি নতুন ভাষা (প্রতি ভাষার কী-সংখ্যা ১:১) |
| React অ্যাডমিন | `apps/react/src/lib/i18n/zh*.ts` | সোর্স অভিধানে ১৪৫১টি কী × ১১টি নতুন ভাষা |

- **ব্যাকএন্ডে «ইংরেজিই key»**: ব্যাকএন্ড বার্তার কী নিজেই ইংরেজি টেক্সট, `en` শুধু ফ্রেমওয়ার্ক নিয়মের নাম ইত্যাদি অল্প কিছু ম্যাপিং রাখে, পূর্ণ অভিধানের প্রয়োজন নেই
- **ভাষা অনুযায়ী লেজি-লোড**: ফ্রন্টএন্ডের ১২টি অভিধান আলাদা chunk-এ প্যাক হয়, ভাষা বদলালে চাহিদা অনুযায়ী লোড হয়, প্রথম স্ক্রিনের আকার বাড়ায় না
- **সুইচ এন্ট্রি**: টপবারের আলাদা globe আইকন + প্রোফাইল ড্রপডাউন (Angular/React দুই প্রান্তে একই)
- **ইন্টারফেস স্তর**: রিকোয়েস্ট হেডার `Accept-Language` স্বয়ংক্রিয় শনাক্তকরণ (zh-CN → চীনা, en → English, বাকি ভাষা তালিকা অনুযায়ী মিলিয়ে), ডিফল্ট চীনা
- **জেনারেটর**: `scripts/gen-be-locales.mjs` (ব্যাকএন্ড), `scripts/gen-fe-locales.mjs --app angular|react` (ফ্রন্টএন্ড), ব্রেকপয়েন্ট থেকে পুনরায় চালানো সমর্থিত

## সিস্টেম আর্কিটেকচার

> মূল SVG দেখতে ছবিতে ক্লিক করুন। ডায়াগ্রামে ইংরেজি নাম ব্যবহৃত, সিস্টেমের প্রতিটি স্তরের আর্কিটেকচার ডিজাইন সম্পূর্ণ ও স্পষ্টভাবে দেখায়।

### সিস্টেম টপোলজি আর্কিটেকচার

![System Architecture](diagrams/system-architecture-cn.svg)

**পাঁচ স্তরের আর্কিটেকচার**: ক্লায়েন্ট স্তর → গেটওয়ে এজ স্তর (Nginx রিভার্স প্রক্সি) → অ্যাপ্লিকেশন স্তর (webman v2 + মিডলওয়্যার চেইন + প্রমাণীকরণ ও অনুমোদন + ব্যবসায়িক লজিক + সাধারণ সার্ভিস) → ডেটা স্টোরেজ স্তর (MySQL + Redis + Elasticsearch) → অপারেশন স্তর (CI/CD + Docker + Prometheus)

### ব্যবসায়িক ডেটা ফ্লো চিত্র

![Business Flowchart](diagrams/business-flowchart-cn.svg)

**সাতটি ব্যবসায়িক ডোমেইনের সমন্বয়**: ক্রয় → ইনভেন্টরি → বিক্রয় → ফাইন্যান্স মূল সাপ্লাই চেইন ক্লোজড-লুপ গঠন করে; CRM বিক্রয় চালায়; ম্যানুফ্যাকচারিং MRP সেলস অর্ডার + বিল অফ ম্যাটেরিয়ালস ভিত্তিতে ক্রয় পরিকল্পনা ও উৎপাদন পরিকল্পনা চালায়; অ্যাপ্রুভাল ওয়ার্কফ্লো, নোটিফিকেশন, প্রজেক্ট ম্যানেজমেন্ট, হিউম্যান রিসোর্স সমর্থনকারী মডিউল হিসেবে পুরো প্রক্রিয়ায় ব্যাপ্ত।

### রিকোয়েস্ট লাইফসাইকেল

![Request Lifecycle](diagrams/request-lifecycle-cn.svg)

**ক্লায়েন্ট থেকে ডাটাবেস পর্যন্ত সম্পূর্ণ রিকোয়েস্ট পাথ**: ক্লায়েন্ট (Angular/React/Flutter/HarmonyOS) → Nginx SSL টার্মিনেশন → ক্রস-অরিজিন হ্যান্ডলিং → নিরাপত্তা ফিল্টার → রেট লিমিট → [অ্যাডমিন: JWT প্রমাণীকরণ → RBAC অনুমোদন → অপারেশন লগ] → কন্ট্রোলার → সার্ভিস স্তর → মডেল স্তর → ক্যাশ/ডাটাবেস/সার্চ ইঞ্জিন → JSON রেসপন্স। চিত্রে ক্যাশ হিট ও ক্যাশ মিস দুটি পথ অন্তর্ভুক্ত। (API ভার্সন এখন URL পাথে অন্তর্ভুক্ত, আলাদা যাচাই ধাপ নেই; ভাষা `app/common/I18n.php` থেকে `Accept-Language` দিয়ে নির্ধারিত হয়।)

### নিরাপত্তা ডিফেন্স-ইন-ডেপথ আর্কিটেকচার

![Security Architecture](diagrams/security-architecture-cn.svg)

**ডিফেন্স-ইন-ডেপথ প্যানোরামা (L0–L12)**: L0 ফিজিক্যাল নেটওয়ার্ক → L1 ট্রান্সমিশন নিরাপত্তা → L2 HTTP নিরাপত্তা হেডার → L3 রিকোয়েস্ট যাচাই → L4 ইনপুট স্যানিটাইজেশন → L5 CSRF সুরক্ষা → L6 রেট লিমিট → L7 প্রমাণীকরণ (JWT+Captcha+ব্ল্যাকলিস্ট+সেশন কন্ট্রোল) → L8 RBAC অনুমোদন → L9 ডেটা সুরক্ষা (ট্রান্সমিশন এনক্রিপশন+স্টোরেজ এনক্রিপশন+ID অবসিকিউরেশন+ডেটা মাস্কিং) → L10 অডিট মনিটরিং → L11 কমপ্লায়েন্স ডিসক্লোজার → L12 অবজারভেবিলিটি (X-Trace-Id বিতরণ ট্রেসিং + ব্যবসায়িক মেট্রিক + অডিট এনহ্যান্সমেন্ট)। কার্যকরযোগ্য চেইনের 7 স্তরের মিডলওয়্যার দেখুন `docs/SECURITY.md`-এ; 35 ধরনের অ্যাটাক ডিটেক্টর দেখুন `config/plugin/erikwang2013/security-php/app.php`-এ।

## ডিফল্ট লোকাল ডোমেইন

প্রজেক্টটি ডিফল্টভাবে লোকাল ডোমেইন **`http://erp.test`** ব্যবহার করে (Flutter ক্লায়েন্টের ডিফল্ট API ঠিকানা、ব্যাকএন্ড Web এন্ট্রির রীতি; HarmonyOS ক্লায়েন্ট ডিফল্টভাবে এমুলেটর হোস্ট মেশিন `http://10.0.2.2:8788`-এ পয়েন্ট করে)।

- **লোকাল অ্যাক্সেস**: hosts ফাইলে `127.0.0.1 erp.test` লাইনটি যোগ করুন, এবং Web সার্ভার/রিভার্স প্রক্সি ব্যাকএন্ডের লিসেনিং পোর্টে (ডিফল্ট `8788`, `.env`-এর `APP_HTTP_PORT` দেখুন, ইনস্টল উইজার্ড বা `.env`-এ পরিবর্তন করা যায়; WebSocket ডিফল্ট `8282` → `APP_WS_PORT`) পয়েন্ট করুন।
- **ডিপ্লয়মেন্ট ডোমেইন বদলানো**:
  - Flutter বিল্ডে ইনজেক্ট: `flutter build web --dart-define=API_BASE_URL=https://আপনার-ডোমেইন`
  - HarmonyOS: `apps/harmonyos/entry/src/main/ets/utils/Config.ets`-এর `BASE_URL` এডিট করুন (রিড-অনলি কনস্ট্যান্ট, ডিফল্ট `http://10.0.2.2:8788`)
  - এমুলেটর ডিবাগে সাময়িকভাবে `http://10.0.2.2:8788`-এ ফেরানো যায় (হোস্ট মেশিনে অ্যাক্সেস)
- সব ইন্টারফেসের ভার্সনই পাথে রাখা হয়েছে (`/admin/v1`、`/api/v1`、`/open/v1`), ক্লায়েন্টকে শুধু রুট ঠিকানা কনফিগার করতে হয়।

### 2. পরিবেশ ভেরিয়েবল কনফিগার করুন

পরিবেশ ভেরিয়েবল কপি করে পরিবর্তন করুন (ঐচ্ছিক, কনফিগার না করলে `config/*.php` এর ডিফল্ট মান ব্যবহৃত হয়):

```bash
cp .env.example .env
```

মূল কনফিগারেশন আইটেম:

| পরিবেশ ভেরিয়েবল | বিবরণ | ডিফল্ট মান |
|---------|------|--------|
| `JWT_SECRET_KEY` | JWT সিগনেচার কী (`env_required`: অনুপস্থিত/খালি/দুর্বল প্লেসহোল্ডার মান হলে স্টার্টআপেই প্রত্যাখ্যাত) | `.env.example`-এ আগে থেকেই 48 অক্ষরের র্যান্ডম মান |
| `HASHIDS_SALT` | Hashids সল্ট (`env_required`) | `.env.example`-এ আগে থেকেই 48 অক্ষরের র্যান্ডম মান |
| `ENCRYPTION_KEY` | API ট্রান্সমিশন স্তর ও স্টোরেজ স্তরের এনক্রিপশন মাস্টার কী (`env_crypto_key`: AES-256-এর জন্য 32 বাইট বাধ্যতামূলক, দৈর্ঘ্য না মিললে স্টার্টআপেই প্রত্যাখ্যাত) | `.env.example`-এ আগে থেকেই 32 অক্ষরের র্যান্ডম মান |
| `APIDOC_PASSWORD` / `APIDOC_SECRET_KEY` | ডকুমেন্ট সাইটের অ্যাক্সেস পাসওয়ার্ড ও টোকেন সিগনেচার কী। ফাঁকা রাখলে, বা এখনও `CHANGE_ME_*` প্লেসহোল্ডার হলে **সর্বদা কনফিগার না করা হিসেবে গণ্য** (প্লেসহোল্ডার মান এই পাবলিক রিপোজিটরিতেই আছে, তাই হুবহু কপি করে অনলাইনে নিলে পাসওয়ার্ড প্রকাশ্য হয়ে যায়) → ডকুমেন্ট সাইট অ্যাক্সেস প্রত্যাখ্যান করে, অ্যাপ চালু হওয়াকে প্রভাবিত করে না | `.env.example`-এ `CHANGE_ME_*` প্লেসহোল্ডার (নিচের জেনারেটর স্ক্রিপ্ট চালিয়ে প্রতিস্থাপন করতে হবে) |
| `SNOWFLAKE_DATACENTER_ID` | ডেটাসেন্টার ID (0-31) | `1` |
| `SNOWFLAKE_WORKER_ID` | ওয়ার্কার নোড ID (0-31) | `1` |
| `SCOUT_HOSTS` | ES ঠিকানা | `http://localhost:9200` |
| `APP_HTTP_PORT` / `APP_WS_PORT` | ব্যাকএন্ড HTTP / WebSocket লিসেনিং পোর্ট (Nginx ইত্যাদি রিভার্স প্রক্সি এখানে পয়েন্ট করে) | `8788` / `8282` |
| `ANGULAR_DEV_PORT` / `REACT_DEV_PORT` | ফ্রন্টএন্ড ডেভ সার্ভারের পোর্ট (`npm run dev`, শুধু ডেভেলপমেন্টে) | `4200` / `5173` |
| `NGINX_PORT` / `NGINX_SSL_PORT` / `MYSQL_PORT` / `ES_PORT` | docker-compose হোস্ট মেশিনে যে পোর্টগুলো প্রকাশ করে (কন্টেইনারের ভিতরের পোর্ট স্থির) | `80` / `443` / `3306` / `9200` |

**অনুপস্থিত, খালি, বা `change-me`/`xxx` ধরনের দুর্বল প্লেসহোল্ডার মান → স্টার্টআপেই `env_required` / `env_crypto_key` দ্বারা প্রত্যাখ্যাত (নীরবে ডিগ্রেড হয় না); `ENCRYPTION_KEY`-এর দৈর্ঘ্যের আলাদা কঠোর যাচাই আছে (AES-256-এর জন্য 32 বাইট বাধ্যতামূলক, না মিললে স্টার্টআপ ত্রুটি)।**

```bash
# র্যান্ডম কী তৈরি করে .env-এ লিখুন (আইডেম্পোটেন্ট, আগে থেকে কনফিগার করা মান আর লেখা হয় না)
bash scripts/gen-env-keys.sh .env
```

### 3. ডাটাবেস ইনিশিয়ালাইজ করুন

**পদ্ধতি ১: ওয়েব ইনস্টলেশন উইজার্ড (সুপারিশকৃত)**

সার্ভিস চালু করার পর `http://localhost:8788/install` এ যান, গাইড অনুযায়ী ৪ ধাপের ইনস্টলেশন সম্পন্ন করুন: পরিবেশ পরীক্ষা → ডাটাবেস কনফিগারেশন → অ্যাডমিন অ্যাকাউন্ট → এক-ক্লিক ইনস্টল। ডাটাবেস কনফিগারেশন ধাপে **ডেমো ডেটা আমদানি করুন** চেকবক্স রয়েছে (পণ্য/স্পেসিফিকেশন/SKU/গ্রাহক/সরবরাহকারী, ID পরিসর 41…, পরিসর অনুযায়ী মুছে ফেলা যায়); ডিফল্টে বন্ধ — প্রোডাকশনে চেক করবেন না।

**পদ্ধতি ২: কমান্ড লাইন ইমপোর্ট**

```bash
mysql -u root -p ডেটাবেস_নাম < database/install.sql
```

`install.sql` একক ফাইলের সম্পূর্ণ বেসলাইন, এতে সব ২২৭টি টেবিলের স্ট্রাকচার ও সিড ডেটা অন্তর্ভুক্ত।

**পদ্ধতি ৩: Docker পরিবেশ**

ম্যানুয়ালি ইমপোর্ট করার দরকার নেই: `install.sql` ইতিমধ্যে MySQL কন্টেইনারের `/docker-entrypoint-initdb.d`-এ মাউন্ট করা, প্রথম স্টার্টআপেই স্বয়ংক্রিয়ভাবে ইনিশিয়ালাইজ হয়।

### 4. ফুল-টেক্সট সার্চ ইঞ্জিন (ঐচ্ছিক)

ইনডেক্স সিঙ্ক `erikwang2013/webman-scout` দিয়ে বাস্তবায়িত (মডেলে `Searchable` trait যোগ করলে সেভ করার সময় স্বয়ংক্রিয়ভাবে ইনডেক্স সিঙ্ক হয়)। **Elasticsearch** ও **OpenSearch** — দুই ধরনের ইঞ্জিন সমর্থিত, দুটির একটি বেছে নিতে হবে:

**① সংশ্লিষ্ট ক্লায়েন্ট ইনস্টল করুন (Composer প্যাকেজ ও ড্রাইভার অবশ্যই মিলতে হবে, ভুল ইনস্টল করলে "Please install the ... client" এরর হয়)**

| ইঞ্জিন | Composer ক্লায়েন্ট |
|---|---|
| Elasticsearch | `composer require elasticsearch/elasticsearch:^9.5` |
| OpenSearch | `composer require opensearch-project/opensearch-php:^2.0` |

**② `.env`-এ ড্রাইভার নির্বাচন করুন**

```ini
# elasticsearch | opensearch（উপরে ইনস্টল করা ক্লায়েন্টের সঙ্গে মিলতে হবে）
SCOUT_DRIVER=opensearch
# ইনডেক্স নামের প্রিফিক্স / শার্ড / রেপ্লিকা / ব্যাচ ব্লক সাইজ / সফট ডিলিট（দুই ইঞ্জিনেই প্রযোজ্য）
SCOUT_PREFIX=erp_
SCOUT_SHARDS=1
SCOUT_REPLICAS=0
SCOUT_CHUNK_SIZE=500
SCOUT_SOFT_DELETE=true
```

**③ কানেকশন কনফিগ (দুই ইঞ্জিনের পড়ার জায়গা আলাদা)**

- **Elasticsearch**: `.env`-এর `SCOUT_HOSTS` (একাধিক নোড কমা দিয়ে আলাদা, যেমন `http://localhost:9200`), অথেনটিকেশন ছাড়া সরাসরি কানেক্ট;
- **OpenSearch**: অফিসিয়াল ইমেজে ডিফল্টভাবে সিকিউরিটি প্লাগইন চালু থাকে (সেলফ-সাইনড TLS + অ্যাকাউন্ট অথেনটিকেশন), তাই `config/scout.php`-এর `opensearch` সেকশন দিয়ে যায়, `SCOUT_HOSTS` পড়ে না:

  ```ini
  # .env
  SCOUT_OPENSEARCH_HOST=https://localhost:9200
  SCOUT_OPENSEARCH_USERNAME=admin
  SCOUT_OPENSEARCH_PASSWORD=আপনার-পাসওয়ার্ড
  ```

  `config/scout.php`-এর `opensearch` সেকশনে ডিফল্ট `ssl_verification=false` (লোকাল সেলফ-সাইনড সার্টিফিকেট); প্রোডাকশনে এটি `true` করে সার্টিফিকেট কনফিগার করা উচিত, এবং দুর্বল পাসওয়ার্ড ব্যবহার করা যাবে না।

> এই প্রজেক্টের Docker Compose-এ Elasticsearch বিল্ট-ইন (`open-admin-es` সার্ভিস): Docker দিয়ে ডিপ্লয় করলে **elasticsearch ড্রাইভার + ES ক্লায়েন্ট**; বাইরের/আলাদা OpenSearch কন্টেইনার হলে **opensearch ড্রাইভার + opensearch-php** বেছে নিন।
>
> **ইনডেক্স পরিসর**: `app/model/`-এর সব ২২৪টি মডেলেই `Searchable` আছে, ডেটাবেসে লেখা/সফট ডিলিট হলেই `ModelObserver` দিয়ে ইনডেক্স সিঙ্ক হয়; এর মধ্যে AdminUser、Customer、Product、Supplier — এই ৪টি মডেলে `toSearchableArray()`-এর হোয়াইটলিস্ট ফিল্ড, বাকি মডেল ডিফল্ট অনুযায়ী (সম্পূর্ণ রো) ইনডেক্সে যায়।
>
> **ইঞ্জিন অনুপলব্ধ থাকলে ব্যবসায়িক লেখা প্রভাবিত হয় না** (পরীক্ষিত: ড্রাইভারকে অগম্য পোর্টে পয়েন্ট করার পরেও `save()` সফল হয়, শুধু একবার কানেকশন টাইমআউটের সময় ব্যয় হয়) — সার্চ ইঞ্জিন একটি ঐচ্ছিক কম্পোনেন্ট, ইনস্টল না করলেও সম্পূর্ণ ব্যবসায়িক কার্যক্রম চলে।
>
> **পরিসরের নোট**: এই প্রজেক্টে এখন শুধু **ইনডেক্স সিঙ্ক** যুক্ত হয়েছে (ডেটাবেস লেখা/সফট ডিলিট হলেই সিঙ্ক), কোনো সার্চ ইন্টারফেস বা সার্চ UI নেই; ব্যবসায়িক প্রয়োজনে Scout-এর কোয়েরি API নিজে কল করুন (অ্যাডমিন লিস্ট পেজের ফিল্টার ব্যাকএন্ডের `where` কোয়েরি দিয়ে চলে, সার্চ ইঞ্জিন দিয়ে নয়)।

### 5. বহুভাষা

`Accept-Language` রিকোয়েস্ট হেডার দিয়ে স্বয়ংক্রিয় সুইচিং, ১৩টি ভাষা সমর্থিত (`zh` ডিফল্ট, এছাড়া `en`/`ja`/`ko`/`de`/`fr`/`es`/`pt`/`ru`/`ar`/`hi`/`bn`/`id`); Angular/React অ্যাডমিন এন্ডে অতিরিক্তভাবে টপবারের globe আইকন ও ব্যক্তিগত কেন্দ্রের ড্রপডাউন দিয়ে সুইচ করা যায়। বিস্তারিত দেখুন [ইন্টারন্যাশনালাইজেশন](#ইন্টারন্যাশনালাইজেশন)।

### API ডকুমেন্টেশন

প্রজেক্টটি `erikwang2013/apidoc-php` ব্যবহার করে, **ডকুমেন্টেশন কন্ট্রোলার অ্যানোটেশন থেকে স্বয়ংক্রিয়ভাবে তৈরি হয়**, আলাদা করে রক্ষণাবেক্ষণ করতে হয় না:

```bash
php start.php start          # ব্যাকএন্ড চালু করুন
# তারপর ব্রাউজারে দেখুন
http://localhost:8788/apidoc
```

- **অ্যাক্সেস পাথ**: `/apidoc` (প্লাগইন রাউট প্রিফিক্স, দেখুন `config/plugin/erikwang2013/apidoc/route.php`);
  রেট লিমিট মিডলওয়্যারে এই পাথটি ছাড় দেওয়া, ব্যাচে অ্যানোটেশন ব্রাউজ করলে রেট লিমিটে আটকাবে না
- **কভারেজ**: অ্যাডমিন ইন্টারফেস (Admin) মডিউল অনুযায়ী গ্রুপ করা, সম্পূর্ণ রিকোয়েস্ট প্যারামিটার ও রেসপন্স স্ট্রাকচার সহ; ক্লায়েন্ট ইন্টারফেস (Service API)-তে প্রমাণীকরণ/ক্যাপচা/পণ্য
- **নতুন ইন্টারফেসের ডকুমেন্টেশন কীভাবে যোগ করবেন**: কন্ট্রোলার মেথডে অ্যানোটেশন বসালেই হয়, সেভ করার পর `/apidoc` রিফ্রেশ করলে সঙ্গে সঙ্গে কার্যকর

  ```php
  #[\erikwang2013\apidoc\annotation\Title("商品列表")]
  #[\erikwang2013\apidoc\annotation\Desc("分页查询商品")]
  #[\erikwang2013\apidoc\annotation\Url("/admin/v1/product")]
  #[\erikwang2013\apidoc\annotation\Method("GET")]
  #[\erikwang2013\apidoc\annotation\Param(name:"page", type:"int", desc:"页码")]
  #[\erikwang2013\apidoc\annotation\Returned("code", type:"int", desc:"业务代码,0=成功")]
  public function index(Request $request): Response { /* ... */ }
  ```

- প্রোডাকশন পরিবেশে অ্যাক্সেস সীমিত করতে হলে দেখুন `docs/nginx-security.conf`

### ইন্টারন্যাশনালাইজেশন

রিকোয়েস্ট হেডার `Accept-Language` স্বয়ংক্রিয়ভাবে ভাষা পরিবর্তন করে, 13টি ভাষা সমর্থিত (`zh` ডিফল্ট, এছাড়া `en`/`ja`/`ko`/`de`/`fr`/`es`/`pt`/`ru`/`ar`/`hi`/`bn`/`id`)।

### ID হ্যান্ডলিং

- **রিকোয়েস্ট/রেসপন্সে ID**: hashids দিয়ে স্ট্রিং এনক্রিপ্ট করা, প্রকৃত ডাটাবেস ID প্রকাশ করা হয় না
- **ইন্টারফেস পাথ**: `GET /admin/v1/user/{hashid}` — পাথে `{id}` হলো hashid স্ট্রিং
- **ডাটাবেস স্টোরেজ**: BIGINT আসল মান, snowflake দিয়ে তৈরি

### API ভার্সন

API ভার্সন URL পাথে রাখা হয় (যেমন `/admin/v1/*`, `/api/v1/*`, `/open/v1/*`), **ক্লায়েন্টের কোনো ভার্সন হেডার লাগে না**:

- ভার্সনযুক্ত পাবলিক ইন্টারফেস সরাসরি সংশ্লিষ্ট ভার্সন কন্ট্রোলার ক্লাসে বাইন্ড হয় (`app/api/v1/controller/`)
- নতুন ভার্সন যোগ করতে নতুন `/api/vN` রুট গ্রুপ নিবন্ধন করুন, কন্ট্রোলার ভার্সন অনুযায়ী `app/api/vN/`-এ রাখুন
- পুরনো `v()` ডাইনামিক পার্সিং ও `ApiVersion` রিকোয়েস্ট হেডার মিডলওয়্যার দুটোই সরানো হয়েছে

### রেট লিমিট

Redis স্লাইডিং উইন্ডো অ্যালগরিদম ভিত্তিক, ডিফল্ট ৬০ বার/মিনিট/IP/রুট। সংবেদনশীল ইন্টারফেস আরও কঠোর:
- লগইন: ১০ বার/মিনিট
- রেজিস্টার: ৫ বার/মিনিট (ডিফল্ট বন্ধ, `REGISTRATION_ENABLED=1` দিয়ে চালু করতে হবে)

রেসপন্স হেডারে `X-RateLimit-Limit`, `X-RateLimit-Remaining`, `X-RateLimit-Reset` অন্তর্ভুক্ত। সীমা অতিক্রম করলে 429 রিটার্ন হয় এবং `Retry-After` সংযুক্ত থাকে।

### মিডলওয়্যার আর্কিটেকচার

গ্লোবাল মিডলওয়্যার সব রিকোয়েস্টে প্রযোজ্য, ক্রমানুসারে কার্যকর হয়:

```
Cors (CORS প্রাক-প্রক্রিয়াকরণ + প্রতিক্রিয়া হেডার)
  → SecurityFilter (HTTP পদ্ধতি সীমাবদ্ধতা/অনুরোধ বডির আকার/Content-Type যাচাই/XSS/SQL ইনজেকশন/পাথ ট্র্যাভার্সাল/কমান্ড ইনজেকশন/CSRF হামলা প্রতিরোধ)
  → RateLimit (Redis স্লাইডিং উইন্ডো রেট লিমিট + অ্যাকাউন্ট লক: ৫ বার লগইন ব্যর্থ → ১৫ মিনিট লক)
  → TracingId (চেইন ট্রেসিং আইডি)
```

রুট গ্রুপ মিডলওয়্যার: `/admin/v1`-এ `AdminAuth` (JWT প্রমাণীকরণ + ব্ল্যাকলিস্ট) → `AdminPermission` (RBAC অনুমোদন) → `OperationLog` (POST/PUT/DELETE স্বয়ংক্রিয় লগ, সোর্স-এন্ড শনাক্তকরণ সহ); `/open/v1`-এ `OpenApiAuth`; TMS ট্র্যাকিং কলব্যাকে `TrackingSignature`। ভাষা `app/common/I18n.php` থেকে `Accept-Language` দিয়ে নির্ধারিত হয়, এটি মিডলওয়্যার নয়।

`/health`, `/api/docs` এবং `/install` পাবলিক এন্ডপয়েন্ট, শুধুমাত্র `Cors → SecurityFilter → RateLimit → TracingId` মধ্য দিয়ে যায়।

নিরাপত্তা বর্ধিতকরণ:
- **অ্যাকাউন্ট লক**: একটানা ৫ বার লগইন ব্যর্থ হলে অ্যাকাউন্ট স্বয়ংক্রিয়ভাবে ১৫ মিনিট লক হয়, লক অবস্থায় লগইন 429 রিটার্ন করে
- **কনকারেন্ট সেশন সীমা**: একজন ব্যবহারকারীর সর্বোচ্চ ৩টি সক্রিয় টোকেন, বেশি হলে সবচেয়ে পুরনো টোকেন স্বয়ংক্রিয়ভাবে ব্ল্যাকলিস্টে যায়
- **security.txt**: `GET /.well-known/security.txt` RFC 9116 স্ট্যান্ডার্ড নিরাপত্তা যোগাযোগ তথ্য প্রদান করে
- **Nginx নিরাপত্তা কনফিগারেশন**: `nginx-security.conf` দেখুন, সম্পূর্ণ রিভার্স প্রক্সি নিরাপত্তা শক্তিশালীকরণ উদাহরণ প্রদান করে

### প্রমাণীকরণ

লগইন ও রেজিস্টারের আগে **ক্লিক ক্যাপচা** যাচাই পাস করতে হবে:

1. ক্লায়েন্ট `POST /api/v1/captcha/generate` রিকোয়েস্ট করে ক্যাপচা ছবি (base64 PNG) ও টেক্সট টার্গেট তালিকা পায়
2. ব্যবহারকারী ক্রমানুসারে ছবির সংশ্লিষ্ট টেক্সট অবস্থানে ক্লিক করে, ক্লিক কোঅর্ডিনেট সংগ্রহ করে `[{x, y}, ...]`
3. লগইনের সময় `captcha_key` ও `clicks` একসাথে সাবমিট করে, সার্ভার প্রথমে ক্যাপচা তারপর ক্রেডেনশিয়াল যাচাই করে

```http
POST /api/v1/auth/login
Content-Type: application/json

{
  "username": "admin",
  "password": "******",
  "captcha_key": "abc123...",
  "clicks": [{"x": 120, "y": 85}, {"x": 210, "y": 140}, {"x": 95, "y": 170}]
}
```

অ্যাডমিন পরবর্তী ইন্টারফেসে JWT প্রমাণীকরণ প্রয়োজন:

```http
Authorization: Bearer <token>
```

লগইন সফল হলে access_token রিটার্ন হয়, ২ ঘণ্টা বৈধ; আরও refresh_token রিটার্ন হয়, ১৪ দিন বৈধ।

লগআউটের সময় টোকেন Redis ব্ল্যাকলিস্টে যায়, বৈধতা সময়ের মধ্যে পুনরায় ব্যবহার করা যায় না। POST /admin/v1/profile/logout

### সংবেদনশীল অপারেশনের দ্বিতীয় নিশ্চিতকরণ

ইউজার, রোল, পারমিশন ইত্যাদি সংবেদনশীল অপারেশন মুছে ফেলতে রিকোয়েস্ট বডিতে বর্তমান লগইন করা ব্যবহারকারীর `password` পাঠিয়ে দ্বিতীয় নিশ্চিতকরণ করতে হয়:

```http
DELETE /admin/v1/user/{id}
Content-Type: application/json
Authorization: Bearer <token>

{ "password": "******" }
```

### CI/CD

GitHub Actions কন্টিনিউয়াস ইন্টিগ্রেশন পাইপলাইন: `.github/workflows/ci.yml`, পাঁচটি জব:

| জব | বিষয়বস্তু |
|------|------|
| `php` (PHP 8.3 / 8.4 ম্যাট্রিক্স, MySQL 8 + Redis 7 সার্ভিস সহ) | composer যাচাই ও নিরাপত্তা অডিট → `php -l` → **PHPStan** (level 5 + baseline) → **PHP CS Fixer** (dry-run) → সম্পূর্ণ `install.sql` ইমপোর্ট → **PHPUnit** (ইন্টিগ্রেশন কেস সহ) → pcov কভারেজ সংগ্রহ → কভারেজ থ্রেশহোল্ড (সামগ্রিক ≥ 4%, `app/service` ≥ 10%, ধাপে ধাপে কঠোর করা হবে) |
| `flutter` | `flutter analyze` + `flutter test` (`continue-on-error: true`, পরিবেশ স্থিতিশীল হলে কঠোর করা হবে) |
| `docs` | `bash scripts/doc-stats.sh --check`: README ও docs-এ `stats:key=value` অ্যানোটেশন সোর্স কোডের প্রকৃত গণনার সঙ্গে মেলে কিনা যাচাই করে (কন্ট্রোলার/সার্ভিস/মডেল/টেবিল/টেস্ট সংখ্যা ইত্যাদি), বিচ্যুতি হলে রেড |
| `e2e` | প্রকৃত webman সার্ভিস চালু → স্বাস্থ্য পরীক্ষা → HTTP কোর চেইন স্মোক + অ্যাডমিন API কভারেজ |
| `release` | `main`-এ push এবং উপরোক্ত জব পাস হলে patch+1 অনুযায়ী tag দিয়ে Release প্রকাশ (নিচে দেখুন) |

> ফ্রন্টএন্ড স্ট্যাটিক চেকের পরিধি: CI এখন শুধু Flutter চালায়; Angular/React (`tsc --noEmit`) ও HarmonyOS (`hvigorw assembleHap`) স্থানীয়ভাবে বা পরে যোগ করা জবে চালাতে হবে।

### রিলিজ প্রক্রিয়া (ভার্সন ইনক্রিমেন্ট)

`main`-এ push করার পর php / docs / e2e চেক সবগুলো পাস হলে, `ci.yml`-এর `release` জব স্বয়ংক্রিয়ভাবে সর্বশেষ tag-এর **patch+1** অনুযায়ী নতুন ভার্সন tag তৈরি ও push করে (`v1.1.4` → `v1.1.5`), এরপর একই নামে GitHub Release তৈরি করে (`--generate-notes` দিয়ে পরিবর্তনের বিবরণ স্বয়ংক্রিয়ভাবে তৈরি)।

- **ট্রিগার**: শুধু `main`-এ push (PR ট্রিগার করে না; tag push ব্রাঞ্চ ফিল্টারের সঙ্গে মেলে না, তাই এই ওয়ার্কফ্লো পুনরাবৃত্তভাবে ট্রিগার হয় না)
- **আইডেম্পোটেন্ট**: রিমোটে একই নামের tag বা release আগেই থাকলে (সমান্তরাল CI / ম্যানুয়ালি দেওয়া) স্বয়ংক্রিয়ভাবে স্কিপ করে, এরর দেয় না
- **লোকাল প্রিভিউ**: `bash scripts/bump-version.sh --check` পরবর্তী ভার্সন নম্বর প্রিন্ট করে (শুধু পড়ে, রিমোটে লেখে না)

### ডাটাবেস ব্যাকআপ

`database/backup/` ডিরেক্টরি:

- `backup.sh` — mysqldump + gzip ব্যাকআপ, ৩০ দিনের আগের পুরনো ব্যাকআপ স্বয়ংক্রিয় পরিষ্কার
- `restore.sh` — ইন্টারঅ্যাক্টিভ রিস্টোর, উপলব্ধ ব্যাকআপ তালিকা থেকে বেছে নেওয়া যায়

### Nginx নিরাপত্তা কনফিগারেশন

প্রোডাকশন ডিপ্লয়মেন্টে `nginx-security.conf` দেখে রিভার্স প্রক্সি নিরাপত্তা শক্তিশালীকরণ কনফিগার করুন।
