## 3. কলাবোরেশন মোড

### 3.1 সাধারণ নিয়ম (রুট CLAUDE.md অনুসরণ)

- **SendMessage-First**: agent-দের মধ্যে SendMessage দিয়ে সরাসরি যোগাযোগ, পোলিং নয়, শেয়ার্ড মিউটেবল স্টেট নেই;
- **নেমিং বাধ্যতামূলক**: প্রতিটি agent-কে নাম দিতে হবে (`name: "role"`);
- **একবার spawn**: স্বাধীন সাব-টাস্ক একবারে ব্যাকগ্রাউন্ডে চালু, Lead থেমে ফলাফলের অপেক্ষা করে, স্ট্যাটাস পোলিং নয়;
- **মেসেজ বাধ্যতামূলক**: প্রতিটি prompt-এ লিখুন «শেষ হলে কাকে SendMessage করবে, কী পাঠাবে»।

### 3.2 তিন ধরনের অর্কেস্ট্রেশন টপোলজি

| মোড | ফ্লো | ব্যবহারের দৃশ্য |
|------|------|----------|
| **Pipeline** | Lead → আর্কিটেক্ট → ব্যাকএন্ড → টেস্ট → রিভিউ | সিকোয়েন্সিয়াল ডিপেন্ডেন্সিসহ ফিচার ডেভেলপমেন্ট (নতুন মডিউল, ক্রস-মডিউল ডেটা ফ্লো) |
| **Fan-out** | Lead → A, B, C → Lead সামারি | পারস্পরিক স্বাধীন প্যারালাল কাজ (মাল্টি-পেজ, মাল্টি-মডিউল রিসার্চ) |
| **Supervisor** | Lead ↔ সদস্য একাধিক রাউন্ড | ধারাবাহিক কোঅর্ডিনেশন প্রয়োজন এমন জটিল কাজ (মাইক্রোসার্ভিস স্প্লিট, বড় স্কেল রিফ্যাক্টর) |

### 3.3 টাস্ক রাউটিং টেবিল

| টাস্ক টাইপ | অর্কেস্ট্রেশন | অংশগ্রহণকারী রোল |
|----------|------|----------|
| নতুন মডিউল / নতুন ফিচার (যেমন DMS、BI গভীরীকরণ) | pipeline | Lead → আর্কিটেক্ট(টেবিল ডিজাইন) → ব্যাকএন্ড → টেস্ট → রিভিউ |
| ইঞ্জিন-লেভেল অ্যালগরিদম (ডাবল-এন্ট্রি / বেতন / MRP) | pipeline + TDD | Lead → বিজনেস ইঞ্জিন বিশেষজ্ঞ(ডিজাইন) → টেস্ট(বাউন্ডারি কেস আগে) → রিভিউ |
| ফ্রন্টএন্ড পেজ (Flutter / HarmonyOS প্যারালাল) | fan-out | Lead → ফ্রন্টএন্ড×2 + ব্যাকএন্ড(API অ্যালাইনমেন্ট) প্যারালাল → Lead সামারি |
| ক্রস-মডিউল ডেটা ফ্লো (ক্রয়→ইনভেন্টরি→AP ইত্যাদি) | pipeline | Lead → আর্কিটেক্ট → ব্যাকএন্ড → টেস্ট → রিভিউ |
| মাইক্রোসার্ভিস স্প্লিট / বড় স্কেল রিফ্যাক্টর | supervisor | Lead ↔ আর্কিটেক্ট + ব্যাকএন্ড + রিভিউ একাধিক রাউন্ড |
| নিরাপত্তা / পারফরম্যান্স স্পেশাল | সিঙ্গেল-থ্রেড ডিপ ডাইভ | Lead → সিকিউরিটি/DevOps ইঞ্জিনিয়ার → রিভিউ |
| Bug ফিক্স (সিঙ্গেল ফাইল / 1-2 লাইন) | টিমে নয় | Lead সরাসরি হ্যান্ডল, বা ১টি agent দিয়ে শেষ |
| তিন ব্রাঞ্চ পার্থক্য / ভার্সন রিলিজ | pipeline | Lead → এডিশন কোঅর্ডিনেটর → টেস্ট(ক্রস-ব্রাঞ্চ রিগ্রেশন) → রিভিউ |

### 3.4 কোয়ালিটি গেট (সাবমিটের আগে অপরিহার্য, রিভিউয়ার পাহারা দেয়)

```
phpunit            # 137 টেস্ট / 805 অ্যাসারশন সবুজ, নতুন কেস পরিবর্তনের সাথে জমা
phpstan            # baseline এর বাইরে নতুন সমস্যা অনুমোদিত নয়
php-cs-fixer       # --dry-run পাস
composer audit     # উচ্চ ঝুঁকির ডিপেন্ডেন্সি দুর্বলতা নেই
```

ডেটাবেস জড়িত পরিবর্তন অবশ্যই আর্কিটেক্টের মধ্য দিয়ে যেতে হবে (163 টেবিল, schema-এর একমাত্র সত্যের উৎস database/install.sql); ফ্রন্টএন্ড জড়িত পরিবর্তনে Flutter `flutter analyze` 0 error / 0 warning চালাতে হবে।

## 5. বাস্তবায়ন ধাপ

1. **রোল ডেফিনিশন পূরণ**: `.claude/agents/` এ ইতিমধ্যে planner / sparc / testing / swarm / consensus আছে, `business-engineer`、`frontend-flutter`、`frontend-harmonyos`、`researcher`、`edition-coordinator` পাঁচটি ডেফিনিশন অনুপস্থিত; বিদ্যমান YAML/MD ফরম্যাট অনুযায়ী প্রতিটির জন্য একটি ফাইল যোগ করলেই মাউন্ট সম্পন্ন;
2. **রাউটিং স্থিরকরণ**: §3.3 রাউটিং টেবিল `.claude-flow/hooks` এর routing লজিকে লিখুন, `UserPromptSubmit` হুক স্বয়ংক্রিয়ভাবে টাস্ক সংশ্লিষ্ট রোলে পাঠাবে;
3. **মেমরি ডোমেইন বিভাগ**: `.claude-flow` এ `agentScopes` চালু আছে (`defaultScope: project`), `backend / frontend / ops / security` চার ডোমেইনে সংরক্ষণ সুপারিশ করা হয়, ফাইন্যান্স ইঞ্জিন কনটেক্সট দিয়ে ফ্রন্টএন্ড টাস্ক দূষণ এড়াতে;
4. **পাইলট রান**: একটি ক্রস-মডিউল টাস্ক বেছে নিন (যেমন DMS গভীরীকরণ বা BI কানবান ইটারেশন) §3.3 রাউটিং অনুযায়ী সম্পূর্ণ এক রাউন্ড চালান, মেসেজ চেইন ও গেট ভেরিফাই করে প্রসারিত করুন।
