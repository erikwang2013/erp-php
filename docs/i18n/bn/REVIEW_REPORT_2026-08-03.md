## দ্বিতীয় রাউন্ডের সমস্যা বিবরণ (মেরামত হয়েছে)

#### 🔴 N1. CI কনফিগ `working-directory` অবাস্তব `service/` ডিরেক্টরিতে নির্দেশ করছে

**ফাইল**: `.github/workflows/ci.yml`

CI workflow-এর **সব ধাপের** `working-directory` `service/`-তে নির্দেশ করছে:
```yaml
- name: Install dependencies
  working-directory: service    # ❌ এই ডিরেক্টরিটির অস্তিত্ব নেই
  run: composer install --no-interaction
```

প্রজেক্ট রুটের composer.json/vendor `/home/wwwroot/erp-php/`-তে আছে, `service/` ডিরেক্টরি নেই, ফলে **GitHub Actions CI সম্পূর্ণভাবে চালানো যায় না**।

একই সমস্যা composer ক্যাশ key-তে: `hashFiles('service/composer.lock')` হওয়া উচিত `hashFiles('composer.lock')`।

**মেরামত**: সব `working-directory: service` লাইন মুছে ক্যাশ পাথ সংশোধন।

- **মাল্টি-লেয়ার সিকিউরিটি মিডলওয়্যার চেইন**: Locale → Cors → SecurityFilter → RateLimit → Auth → Permission → OpsLog (9টি মিডলওয়্যার)
- **WAF-গ্রেড অ্যাটাক ডিটেকশন**: XSS (5 প্যাটার্ন)、SQL ইনজেকশন (6 প্যাটার্ন)、পাথ ট্রাভার্সাল (3 প্যাটার্ন)、কমান্ড ইনজেকশন (4 প্যাটার্ন)、ক্ষতিকর ফাইল আপলোড (2 প্যাটার্ন)
- **অ্যাটাক এসকেলেশন ও ব্লক**: 5 বার/60 সেকেন্ড ট্রিগার → Redis অস্থায়ী ব্ল্যাকলিস্ট 15 মিনিট
- **রেট লিমিট**: Redis + Lua অ্যাটমিক স্লাইডিং উইন্ডো, লগইন (10 বার/মিনিট)、রেজিস্ট্রেশন (5 বার/মিনিট)
- **JWT ব্ল্যাকলিস্ট**: Token সক্রিয়ভাবে অকার্যকর করার সাপোর্ট
- **অপারেশন লগ**: রাইট অপারেশন সম্পূর্ণ রেকর্ড, password/token/secret ইত্যাদি সংবেদনশীল ফিল্ড স্বয়ংক্রিয় ডিসেনসিটাইজেশন
- **পাসওয়ার্ড হ্যাশ**: একীভূতভাবে `password_hash(PASSWORD_BCRYPT)` ব্যবহার
- **CSRF Origin/Referer চেক**: SecurityFilter রাইট অপারেশনে ক্রস-ডোমেন যাচাই করে
- **security.txt (RFC 9116)**: `/.well-known/security.txt` কনফিগার করা
- **সিকিউরিটি রেসপন্স হেডার**: CSP, X-Frame-Options, X-Content-Type-Options, Referrer-Policy, Permissions-Policy
- **Content-Type বাধ্যতামূলক যাচাই**: POST/PUT-কে অবশ্যই `application/json` বা `application/x-www-form-urlencoded` ঘোষণা করতে হবে
- **রিকোয়েস্ট বডি সাইজ লিমিট**: 10MB সীমা
- **HTTP মেথড হোয়াইটলিস্ট**: শুধু GET/POST/PUT/DELETE/OPTIONS অনুমোদিত

## ১০. সিদ্ধান্ত

প্রজেক্টের সামগ্রিক কোয়ালিটি **ভালো**। P0 সিকিউরিটি সমস্যা (ব্যাচ অ্যাসাইনমেন্ট প্রোটেকশন、কনফিগ হার্ডকোডিং) আগের রাউন্ডে সমাধান ও ভেরিফাই হয়েছে।

**এই রাউন্ডের নতুন তিনটি মূল সমস্যা**:

1. **CI কনফিগ `service/` পাথ এরর** — সব CI ধাপ সম্পূর্ণভাবে চালানো যায় না, বর্তমানে সবচেয়ে জরুরি সমস্যা (10 মিনিটে মেরামতযোগ্য)
2. **সার্ভিস লেয়ার মারাত্মক অনুপস্থিত** — 72টি Controller-এ মাত্র 3টি Service, বিজনেস লজিক রিকোয়েস্ট হ্যান্ডলিং-এর সাথে কাপলড, সবচেয়ে বড় আর্কিটেকচার টেকনিক্যাল ডেব্ট
3. **Dockerfile-এ Redis এক্সটেনশন নেই** — Docker পরিবেশে RateLimit/Session/ব্ল্যাকলিস্ট ফাংশন প্রভাবিত

CI পাথ সমস্যা (P0) মেরামতের পর, Service লেয়ার আর্কিটেকচার নিয়ম প্রতিষ্ঠা করে পরবর্তী ফিচার ইটারেশনে ধাপে ধাপে বিজনেস লজিক Controller থেকে Service-এ মাইগ্রেট করার পরামর্শ।
