## 1. ডিপ ডিফেন্স ওভারভিউ

সিস্টেম 7-স্তরের ডিপ ডিফেন্স মডেল ব্যবহার করে, বাইরে থেকে ভিতরে স্তরে স্তরে ক্ষতিকর রিকোয়েস্ট ফিল্টার করে, নিশ্চিত করে যেকোনো এক স্তর ব্যর্থ হলেও পরবর্তী প্রতিরক্ষা লাইন বাকি থাকে।

সম্পূর্ণ মিডলওয়্যার চেইন নিম্নলিখিত ক্রমে এক্সিকিউট হয় (`config/middleware.php` দেখুন):

```
请求 → Cors → SecurityFilter → RateLimit → [路由组中间件: AdminAuth → AdminPermission → OperationLog] → Controller
```

| স্তর | মিডলওয়্যার/মেকানিজম | সুরক্ষার লক্ষ্য |
|----|--------|---------|
| 1 | SecurityFilter | XSS / SQL ইনজেকশন / পাথ ট্রাভার্সাল / কমান্ড ইনজেকশন / CSRF অ্যাটাক ইন্টারসেপ্ট |
| 2 | Cors | ক্রস-অরিজিন সিকিউরিটি + রেসপন্স সিকিউরিটি হেডার ইনজেকশন |
| 3 | RateLimit | Redis স্লাইডিং উইন্ডো রেট লিমিট, ব্রুট ফোর্স প্রতিরোধ |
| 4 | AdminAuth | JWT অথ + ব্ল্যাকলিস্ট লগআউট |
| 5 | AdminPermission | RBAC method.path গ্রানুলারিটি অনুমোদন |
| 6 | OperationLog | অপারেশন অডিট + সোর্স এন্ড ট্রেসিং |
| 7 | ডেটা এনক্রিপশন | Hashids ID অবস্কিউরেশন + Encryptable DB এনক্রিপশন + EncryptionService ট্রান্সমিশন এনক্রিপশন |

ফ্রন্টএন্ড তিন স্তরে (Flutter) আলাদা ইনপুট ভ্যালিডেশন আছে, ব্যাকএন্ড কোনো বিশ্বাস করে না, প্রতিটি স্তর স্বাধীনভাবে প্রতিরক্ষা করে।

## 2. অ্যাটাক ডিটেকশন ইঞ্জিন

### 2.0 HTTP মেথড সীমাবদ্ধতা

SecurityFilter সব অ্যাটাক ডিটেকশনের আগে প্রথমে HTTP মেথড যাচাই করে, শুধু নিম্নলিখিত স্ট্যান্ডার্ড মেথড অনুমোদিত:

```
GET, POST, PUT, DELETE, OPTIONS, HEAD
```

নন-স্ট্যান্ডার্ড মেথড (যেমন TRACE、CONNECT、PATCH、কাস্টম মেথড ইত্যাদি) সরাসরি **405 Method Not Allowed** রিটার্ন করে, রেসপন্স বডি খালি HTML, পরবর্তী অ্যাটাক ডিটেকশন বা বিজনেস লজিকে প্রবেশ করে না।

এটি ডিপ ডিফেন্সের প্রথম প্রতিরক্ষা লাইন, কার্যকরভাবে ব্লক করে:
- TRACE ক্রস-সাইট ট্রেসিং অ্যাটাক (XST)
- CONNECT টানেল প্রক্সি অপব্যবহার
- নন-স্ট্যান্ডার্ড WebDAV মেথড প্রোবিং
- অটোমেটেড স্ক্যানারের HTTP মেথড এনুমারেশন

### 2.1 XSS ক্রস-সাইট স্ক্রিপ্টিং

সব রেজেক্স `SecurityFilter::PATTERNS['XSS']` থেকে আসে, কেস-ইনসেনসিটিভ ম্যাচিং।

| ডিটেকশন প্যাটার্ন | রেজেক্স | প্রতিরোধ করা অ্যাটাক |
|----------|------|-----------|
| স্ক্রিপ্ট ট্যাগ | `<\s*\/?\s*s\s*c\s*r\s*i\s*p\s*t\b` | `<script>`, `<script >`, `< script>` ইত্যাদি স্পেস সহ ভ্যারিয়েন্ট |
| ইভেন্ট অ্যাট্রিবিউট | `\bon\w+\s*=\s*[\"\']?\s*(?:javascript\|vbscript):` | `onclick="javascript:..."` ইত্যাদি ইনলাইন ইভেন্ট |
| JS সিউডো-প্রোটোকল | `(?:javascript\|vbscript)\s*:\s*(?:[^\s]*\s*)?(?:eval\|alert\|prompt\|confirm\|document\.cookie\|location\s*=)` | `javascript:eval(...)`, `javascript:alert(1)` ইত্যাদি |
| Data URI XSS | `data\s*:\s*text\s*\/\s*html\s*(?:;base64)?\s*,` | `data:text/html,<script>`, `data:text/html;base64,...` ইত্যাদি |
| টেমপ্লেট ইনজেকশন | `\{\{.*?\}\}` | `{{constructor}}`, `{{7*7}}` ইত্যাদি সার্ভার-সাইড/Angular/Vue টেমপ্লেট ইনজেকশন |

### 2.2 SQL ইনজেকশন

| ডিটেকশন প্যাটার্ন | রেজেক্স | প্রতিরোধ করা অ্যাটাক |
|----------|------|-----------|
| UNION কম্বাইন্ড কোয়েরি | `\bUNION\s+(?:ALL\s+)?SELECT\b` | `UNION SELECT`, `UNION ALL SELECT` ডেটা এক্সফিলট্রেশন |
| OR সর্বদা-সত্য ইনজেকশন | `(?:[\"\']\s*OR\s+[\"\']?\s*\d+\s*=\s*\d+\|[\"\']\s*OR\s+[\"\']?1[\"\']?\s*=\s*[\"\']?1)` | `' OR 1=1--`, `" OR '1'='1'` |
| টেবিল স্ট্রাকচার ধ্বংস | `\b(?:DROP\|ALTER\|TRUNCATE)\s+(?:TABLE\|DATABASE\|INDEX\|VIEW)\b` | `DROP TABLE users`, `TRUNCATE TABLE logs` |
| স্টোরড প্রসিডিউর কল | `\b(?:xp_cmdshell\|sp_executesql\|sp_addsrvrolemember)\b` | MSSQL এক্সটেন্ডেড স্টোরড প্রসিডিউর কমান্ড এক্সিকিউশন |
| মেটাডেটা প্রোবিং | `\b(?:INFORMATION_SCHEMA\|sys\.(?:tables\|columns\|databases)\|pg_class\|sqlite_master\|mysql\.(?:user\|db))\b` | MySQL/PG/SQLite/MSSQL ডেটাবেস স্ট্রাকচার প্রোবিং |
| কমেন্ট বাইপাস | `(?:[\"\'])\s*(?:--\|#)\s*[\"\']?\s*(?:OR\|AND\|SELECT\|INSERT\|UPDATE\|DELETE\|DROP)` | `'-- OR SELECT`, `'# AND UPDATE` কমেন্ট বাইপাস |

### 2.3 পাথ ট্রাভার্সাল

| ডিটেকশন প্যাটার্ন | রেজেক্স | প্রতিরোধ করা অ্যাটাক |
|----------|------|-----------|
| ডিরেক্টরি ব্যাকট্র্যাকিং | `\.\.[\/\\\\]{2,}` | `../`, `..\`, `....//` মাল্টি-লেভেল ডিরেক্টরি ব্যাকট্র্যাকিং |
| সংবেদনশীল ফাইল প্রোবিং | `\/(?:etc\/(?:passwd\|shadow\|hosts)\|proc\/self\|boot\.ini\|win\.ini\|WEB-INF\|\.env\|\.git\/)` | `/etc/passwd`, `/proc/self/environ`, `.env`, `.git/HEAD` ইত্যাদি |
| নাল বাইট ট্রাঙ্কেশন | `%00` | `../../../etc/passwd%00.jpg` এক্সটেনশন যাচাই বাইপাস |

### 2.4 কমান্ড ইনজেকশন

| ডিটেকশন প্যাটার্ন | রেজেক্স | প্রতিরোধ করা অ্যাটাক |
|----------|------|-----------|
| পাইপ/সেমিকোলন কমান্ড | `[;\|&]\s*(?:ls\|cat\|rm\|wget\|curl\|nc\|bash\|sh\|cmd\|powershell\|python\|perl)\b` | `;cat /etc/passwd`, `\|bash` |
| ব্যাকটিক রিপ্লেসমেন্ট | `` `[^`]*\b(?:cat\|ls\|id\|whoami\|pwd\|rm\|wget\|curl)\b[^`]*` `` | `` `cat /etc/passwd` `` |
| $() রিপ্লেসমেন্ট | `\$\(\s*(?:cat\|ls\|id\|whoami\|rm\|wget\|curl)\b` | `$(whoami)`, `$(cat flag)` |
| রিমোট ডাউনলোড পাইপ | `(?:wget\|curl)\s+.*(?:\b-o\b\|\b-O\b\|pipe\|bash\|python).*\bhttps?:\/\/` | `wget URL -O - \| bash`, `curl URL \| python` |

### 2.5 CSRF ক্রস-সাইট রিকোয়েস্ট ফোরজারি

যাচাই লজিক `SecurityFilter::checkCsrf()`-এ ইমপ্লিমেন্ট করা:

```php
// 仅 POST/PUT/DELETE 触发校验
// Origin 头和 Referer 均为空 → 放行（非浏览器客户端）
// Origin 非空 → 解析 Origin 域名与 Host 比对
```

তুলনা নিয়ম:
- Host-এর `www.` প্রিফিক্স সরিয়ে Origin-এর ডোমেইনের সাথে সঠিক তুলনা
- Host যদি Origin-এর প্যারেন্ট ডোমেইন হয় (যেমন `Origin: app.example.com`, `Host: example.com` — `str_contains($originHost, '.' . $hostOnly)` ট্রিগার করে), ছেড়ে দেওয়া হয়
- সঠিক ম্যাচ নয় এবং সাবডোমেইনও নয় → 403 রিটার্ন, CSRF অ্যাটাক হিসেবে চিহ্নিত

দ্রষ্টব্য: নন-ব্রাউজার ক্লায়েন্ট (যেমন curl যাতে Origin/Referer নেই) সরাসরি ছেড়ে দেওয়া হয়, CSRF সুরক্ষা শুধু ব্রাউজার পরিবেশে কার্যকর।

### 2.6 ক্ষতিকর ফাইল আপলোড

| ডিটেকশন প্যাটার্ন | রেজেক্স | প্রতিরোধ করা অ্যাটাক |
|----------|------|-----------|
| ডাবল এক্সটেনশন ভান | `\.(?:php\d?\|phtml\|phar\|cgi\|pl\|py\|jsp\|asp)x?\.(?:png\|jpg\|gif\|pdf)` | `shell.php.png`, `shell.phar.jpg` হোয়াইটলিস্ট বাইপাস |
| PHP এক্সটেনশন | `\.php\s*$/m` | রিকোয়েস্ট প্যারামিটারে সরাসরি `.php` পাথ পাস করা |

## 3. অ্যাটাক এসকেলেশন ও IP ব্ল্যাকলিস্ট

SecurityFilter-এ বিল্ট-ইন অ্যাটাক এসকেলেশন মেকানিজম আছে, একই IP-এর অব্যাহত স্ক্যানিং অ্যাটাক প্রতিরোধ করে।

### এসকেলেশন ফ্লো

```
第 1 次扫描命中 → Redis INCR security_escalate:{ip} = 1, TTL=60s
第 2 次扫描命中 → INCR → 2
...
第 5 次扫描命中 → INCR → 5
    → 触发封禁: SETEX security_ban:{ip} 900 1
    → 清除计数器 DEL security_escalate:{ip}
    → 写入安全日志: [SECURITY] IP banned 15min
```

### ব্লক পিরিয়ডে আচরণ

প্রতিটি রিকোয়েস্ট SecurityFilter-এ প্রবেশের সময় প্রথমে `isBanned()` চেক করে:

```php
if (Redis::get("security_ban:{$ip}")) {
    return response('<h1>403 Forbidden</h1>', 403);
}
```

ব্লক করা IP-এর সব রিকোয়েস্ট (বৈধ রিকোয়েস্টসহ) 15 মিনিটের মধ্যে সরাসরি 403 রিটার্ন পায়, পরবর্তী বিজনেস লজিক সম্পূর্ণভাবে স্কিপ করে।

### কনফিগ কনস্ট্যান্ট

| কনস্ট্যান্ট | মান | অর্থ |
|------|-----|------|
| ESCALATE_LIMIT | 5 | 60 সেকেন্ড উইন্ডোতে ট্রিগার কাউন্ট থ্রেশহোল্ড |
| ESCALATE_WINDOW | 60 | কাউন্টার উইন্ডো (সেকেন্ড) |
| BAN_DURATION | 900 | ব্ল্যাকলিস্ট স্থায়িত্ব (সেকেন্ড), অর্থাৎ 15 মিনিট |

### সিকিউরিটি লগ

ফাইল অবস্থান: `runtime/logs/security.log`

লগ ফরম্যাট উদাহরণ:
```
2026-05-20 14:32:11 [SECURITY] XSS attack blocked | IP: 192.168.1.100 | Path: /admin/user | Field: body.username | Source: body | Payload: <script>alert(1)</script>
2026-05-20 14:32:15 [SECURITY] IP banned 15min | IP: 192.168.1.100 | Triggers: 5
```

### রিকোয়েস্ট বডি সাইজ লিমিট

`Content-Length > 10MB` সরাসরি 413 Payload Too Large রিটার্ন, DoS বিশাল রিকোয়েস্ট বডি অ্যাটাক প্রতিরোধ।

### Content-Type যাচাই

POST/PUT রিকোয়েস্ট-কে **অবশ্যই** `Content-Type` হিসেবে `application/json` বা `application/x-www-form-urlencoded` ঘোষণা করতে হবে, অন্যথায় 415 Unsupported Media Type রিটার্ন হয়। ফাইল আপলোড রিকোয়েস্ট (file ফিল্ডসহ) এই চেক স্কিপ করে।

## 4. রেসপন্স সিকিউরিটি হেডার

সব হেডার `Cors` মিডলওয়্যারে ইনজেক্ট হয়, `$response->withHeaders()` দিয়ে প্রতিটি রেসপন্সে যুক্ত হয়।

| হেডার | মান | কাজ |
|----|-----|------|
| Access-Control-Allow-Origin | `*` | যেকোনো উৎসের ক্রস-অরিজিন অনুমতি (ইন্টারনাল নেটওয়ার্ক অ্যাডমিন ব্যাকএন্ড সিনারিও) |
| Access-Control-Allow-Methods | `GET,POST,PUT,DELETE,OPTIONS` | অনুমোদিত মেথড সেট |
| Access-Control-Allow-Headers | `Authorization,Content-Type,API-Version` | অনুমোদিত কাস্টম হেডার |
| Access-Control-Max-Age | `86400` | প্রি-ফ্লাইট রিকোয়েস্ট ক্যাশ 24 ঘণ্টা |
| X-Content-Type-Options | `nosniff` | ব্রাউজার MIME স্নিফিং নিষিদ্ধ |
| X-Frame-Options | `DENY` | সব iframe এমবেড নিষিদ্ধ, ক্লিকজ্যাকিং প্রতিরোধ |
| X-XSS-Protection | `1; mode=block` | ব্রাউজার বিল্ট-ইন XSS ফিল্টার সক্রিয় ও পেজ রেন্ডার ব্লক |
| Referrer-Policy | `strict-origin-when-cross-origin` | একই অরিজিনে সম্পূর্ণ URL, ক্রস-অরিজিনে শুধু ডোমেইন |
| Permissions-Policy | `camera=(), microphone=(), geolocation=()` | পুরো সাইটে ক্যামেরা/মাইক্রোফোন/লোকেশন API নিষিদ্ধ |

OPTIONS প্রি-ফ্লাইট রিকোয়েস্ট সরাসরি 204 খালি রেসপন্স রিটার্ন করে, পরবর্তী মিডলওয়্যার চেইনে প্রবেশ করে না।

### 4.2 Content-Security-Policy (CSP)

অন্যান্য সিকিউরিটি হেডারের সাথে Cors মিডলওয়্যারে ইনজেক্ট হয়, ডিপ ডিফেন্স প্রদান করে, ব্রাউজার লোড ও এক্সিকিউট করতে পারা রিসোর্স উৎস সীমাবদ্ধ করে।

| হেডার | মান | কাজ |
|----|-----|------|
| Content-Security-Policy | `default-src 'self'; script-src 'self' 'unsafe-inline' 'unsafe-eval'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; font-src 'self'; connect-src 'self'; frame-ancestors 'none'; base-uri 'self'; form-action 'self'` | স্ক্রিপ্ট/স্টাইল/ইমেজ/কানেকশন/ফ্রেম/ফর্ম ইত্যাদি রিসোর্স উৎস সীমাবদ্ধ |
| X-Permitted-Cross-Domain-Policies | `none` | Adobe Flash/PDF ইত্যাদি ক্রস-ডোমেইন পলিসি ফাইল লোড নিষিদ্ধ |

CSP পলিসির মূল পয়েন্ট:
- `default-src 'self'`：ডিফল্ট শুধু একই অরিজিন রিসোর্স অনুমোদিত
- `script-src 'self' 'unsafe-inline' 'unsafe-eval'`：একই অরিজিন স্ক্রিপ্ট + ইনলাইন স্ক্রিপ্ট (Flutter Web-এর জন্য প্রয়োজন)+ eval (Flutter Web ডিবাগের জন্য প্রয়োজন)
- `frame-ancestors 'none'`：যেকোনো পেজে iframe এমবেড নিষিদ্ধ, X-Frame-Options: DENY-এর সাথে ডাবল নিশ্চয়তা
- `base-uri 'self'`：`<base>` ট্যাগ শুধু একই অরিজিনে নির্দেশ করতে পারে
- `form-action 'self'`：ফর্ম শুধু একই অরিজিনে সাবমিট করতে পারে

## 5. রেট লিমিট পলিসি

### অ্যালগরিদম

Redis Sorted Set স্লাইডিং উইন্ডো + Lua অ্যাটমিক স্ক্রিপ্ট, মূল অপারেশন:

```lua
-- 1. 清理窗口外的旧记录
redis.call('ZREMRANGEBYSCORE', KEYS[1], 0, windowStart)
-- 2. 检查当前窗口计数
local count = redis.call('ZCARD', KEYS[1])
-- 3. 超限则返回 {0, count}，未超限则 ZADD 并返回 {1, count+1}
if count >= limit then return {0, count} end
redis.call('ZADD', KEYS[1], now, now . '.' . random)  -- 随机后缀避免同毫秒覆盖
redis.call('EXPIRE', KEYS[1], window + 10)
```

Lua স্ক্রিপ্ট Redis সার্ভারে সিঙ্গেল-থ্রেডে এক্সিকিউট হয়, **স্বাভাবিকভাবে অ্যাটমিক**, TOCTOU (Time-of-check to Time-of-use) রেস কন্ডিশন দূর করে।

### রেট লিমিট কনফিগ

| রাউট | সীমা | উইন্ডো | সিনারিও |
|------|------|------|------|
| ডিফল্ট (সব রাউট) | 60 বার/মিনিট | 60s | জেনেরিক API |
| `/api/auth/login` | 10 বার/মিনিট | 60s | লগইন (ব্রুট ফোর্স প্রতিরোধ) |
| `/api/auth/register` | 5 বার/মিনিট | 60s | রেজিস্ট্রেশন (ব্যাচ রেজিস্ট্রেশন প্রতিরোধ; ডিফল্ট বন্ধ, `REGISTRATION_ENABLED=1` দিয়ে চালু করতে হবে) |

### রেসপন্স হেডার

রেট লিমিট ট্রিগার হলে HTTP 429 ও JSON বডি রিটার্ন হয়:
```json
{"code": 429, "message": "请求过于频繁，请稍后再试", "data": []}
```

সব রেসপন্স (সাধারণ রেসপন্সসহ) নিম্নলিখিত হেডার বহন করে:

| হেডার | ব্যাখ্যা |
|----|------|
| X-RateLimit-Limit | বর্তমান উইন্ডোতে অনুমোদিত সর্বোচ্চ রিকোয়েস্ট সংখ্যা |
| X-RateLimit-Remaining | বর্তমান উইন্ডোতে অবশিষ্ট রিকোয়েস্ট সংখ্যা |
| X-RateLimit-Reset | উইন্ডো রিসেটের Unix টাইমস্ট্যাম্প |
| Retry-After | শুধু রেট লিমিটে বহন করে, অপেক্ষার সুপারিশকৃত সেকেন্ড |

### ডিগ্রেডেশন পলিসি

Redis অস্বাভাবিক হলে (কানেকশন টাইমআউট、অনুপলব্ধ ইত্যাদি) **fail-open**:

```php
try {
    $result = Redis::eval($lua, ...);
} catch (\Throwable $e) {
    return $handler($request); // Redis down, 放行所有请求
}
```

স্বল্প সময় রেট লিমিট সুরক্ষা হারালেও স্বাভাবিক বিজনেস রিকোয়েস্ট ব্লক করা হয় না।

### 5.4 অ্যাকাউন্ট লক মেকানিজম

লগইন ইন্টারফেস রেট লিমিটের উপর অতিরিক্ত **অ্যাকাউন্ট লক** মেকানিজম যোগ করে, নির্দিষ্ট ইউজারকে লক্ষ্য করে টার্গেটেড ব্রুট ফোর্স প্রতিরোধ করে।

**লক ফ্লো**:

```
登录失败 → Redis INCR account_lockout:{userId} TTL=900s
连续 5 次失败 → Redis SETEX account_locked:{userId} 900 1
            → 返回 429 "账号已被锁定，请15分钟后再试"
            → 清除计数器 DEL account_lockout:{userId}
```

**লক পিরিয়ডে আচরণ**:

লক পিরিয়ডে সব লগইন রিকোয়েস্ট সরাসরি 429 রিটার্ন পায়, পাসওয়ার্ড যাচাই করা হয় না, ব্রুট ফোর্স প্রচেষ্টা সম্পূর্ণভাবে ব্লক হয়।

**কনফিগ কনস্ট্যান্ট**:

| কনস্ট্যান্ট | মান | অর্থ |
|------|-----|------|
| MAX_LOGIN_ATTEMPTS | 5 | সর্বোচ্চ ধারাবাহিক ব্যর্থতার সংখ্যা |
| LOCKOUT_DURATION | 900 | লক স্থায়িত্ব (সেকেন্ড), অর্থাৎ 15 মিনিট |

দ্রষ্টব্য: অ্যাকাউন্ট লক `userId`-এর উপর ভিত্তি করে, IP নয়, তাই আক্রমণকারী IP বদলালে লক বাইপাস করতে পারে না। IP রেট লিমিটের (10 বার/মিনিট) সাথে মিলে ডাবল সুরক্ষা গঠন করে:
- IP স্তরে: 10 বার/মিনিট রেট লিমিট ডিস্ট্রিবিউটেড ব্রুট ফোর্স ব্লক করে
- অ্যাকাউন্ট স্তরে: 5 বার ব্যর্থ লক টার্গেটেড ব্রুট ফোর্স ব্লক করে

## 6. অথ ও অনুমোদন

### 6.1 JWT অথ

AdminAuth মিডলওয়্যারে ইমপ্লিমেন্ট, অথ প্রয়োজন রাউট গ্রুপে মাউন্ট করা।

**প্যারামিটার কনফিগ** (`config/plugin/erikwang2013/jwt/jwt`, `.env` থেকে ইনজেক্ট):

| প্যারামিটার | মান | ব্যাখ্যা |
|------|-----|------|
| অ্যালগরিদম | HS256 | HMAC-SHA256 সিমেট্রিক সিগনেচার |
| কী | `JWT_SECRET` | এনভায়রনমেন্ট ভেরিয়েবল ইনজেকশন, প্রোডাকশনে পরিবর্তন প্রয়োজন |
| access_token TTL | 7200s (2h) | `JWT_TTL` |
| refresh_token TTL | 1209600s (14d) | `JWT_REFRESH_TTL` |
| ইস্যুয়ার | `open-admin` | `JWT_ISSUER` |
| অডিয়েন্স | `open-admin` | `JWT_AUDIENCE` |

**Token এক্সট্রাকশন**: `Authorization: Bearer <token>` হেডার থেকে এক্সট্রাক্ট, `Bearer ` প্রিফিক্স স্ট্রিপ করে মূল JWT পাওয়া যায়।

**অথ ফ্লো**:
1. খালি token → সরাসরি 401 `{"code": 401, "message": "未登录"}`
2. Redis ব্ল্যাকলিস্ট `jwt_blacklist:{md5(token)}` চেক → হিট → 401 `Token已失效，请重新登录`
3. JWT decode → ব্যর্থ (মেয়াদোত্তীর্ণ/সিগনেচার মিলছে না) → 401 `Token已过期或无效`
4. সফল → `$request->adminId` এবং `$request->adminUsername` ইনজেক্ট

**ব্ল্যাকলিস্ট মেকানিজম**: ইউজার লগআউট করলে `md5(token)` Redis-এ লেখা হয়, TTL JWT-এর অবশিষ্ট মেয়াদে সেট হয়। Redis ব্যর্থ হলে ব্ল্যাকলিস্ট চেক স্কিপ হয় (fail-open), তখন লগআউট করা Token স্বল্প সময় ব্যবহারযোগ্য থাকে, কিন্তু JWT-এর নিজস্ব স্বল্প মেয়াদ (2h) ফলব্যাক সুরক্ষা হিসেবে থাকে।

### 6.2 কনকারেন্ট সেশন সীমাবদ্ধতা

Token লিক হলে মাল্টি-ডিভাইস অপব্যবহার রোধ করতে, সিস্টেম একই ইউজারের একই সময়ে বৈধ Token সংখ্যা সীমাবদ্ধ করে।

**সীমাবদ্ধতার লজিক**:

```
登录成功 → 签发新 Token
         → 查询当前用户有效 Token 数量: Redis SCARD user_tokens:{userId}
         → 若数量 >= 3（MAX_CONCURRENT_SESSIONS）:
            → 按创建时间升序排列，移除最旧的 Token:
              Redis SREM user_tokens:{userId} <oldest_token_id>
              Redis SETEX jwt_blacklist:{md5(oldest_token)} TTL remaining
         → 将新 Token 加入集合: Redis SADD user_tokens:{userId} <new_token_id>
            Redis SET user_token:{token_id} {userId} EX {TTL}
```

**কনফিগ কনস্ট্যান্ট**:

| কনস্ট্যান্ট | মান | অর্থ |
|------|-----|------|
| MAX_CONCURRENT_SESSIONS | 3 | একই ইউজারের সর্বোচ্চ কনকারেন্ট Token সংখ্যা |

**লগআউট-ফোর্সড সিনারিও**: ইউজার ৪র্থ ডিভাইসে লগইন করলে, ১ম ডিভাইসের Token জোর করে ব্ল্যাকলিস্টে যোগ হয়, পরবর্তী রিকোয়েস্ট 401 "Token已失效，请重新登录" রিটার্ন পায়।

লগআউটে, বর্তমান Token সেট থেকে সরানো হয়। Token স্বাভাবিকভাবে মেয়াদোত্তীর্ণ হলে Redis key স্বয়ংক্রিয়ভাবে অকার্যকর হয়, সেটের সদস্য স্বাভাবিকভাবে কমে যায়।

### 6.3 RBAC পারমিশন মডেল

AdminPermission মিডলওয়্যারে ইমপ্লিমেন্ট।

**ডেটা মডেল**: User -> Role -> Permission তিন-স্তর সম্পর্ক

- `erik_admin_user` (ইউজার টেবিল)
- `erik_admin_user_role` (ইউজার-রোল সম্পর্ক টেবিল)
- `erik_admin_role` (রোল টেবিল)
- `erik_admin_role_permission` (রোল-পারমিশন সম্পর্ক টেবিল)
- `erik_admin_permission` (পারমিশন টেবিল)

**পারমিশন টাইপ**:
| type | অর্থ | উদাহরণ |
|------|------|------|
| 1 | মেনু পারমিশন | বাম নেভিগেশনের দৃশ্যমানতা নিয়ন্ত্রণ |
| 2 | বাটন পারমিশন | পেজের ভিতরের অপারেশন বাটন নিয়ন্ত্রণ (নতুন/সম্পাদনা/মুছে ফেলা) |
| 3 | API পারমিশন | ব্যাকএন্ড ইন্টারফেস কল নিয়ন্ত্রণ |

API পারমিশন চিহ্ন ফরম্যাট: `{method}.{path}`

উদাহরণ:
- `post.admin/user` — ইউজার তৈরি
- `put.admin/user` — ইউজার সম্পাদনা
- `delete.admin/user` — ইউজার মুছে ফেলা
- `get.admin/user` — ইউজার তালিকা দেখা

**অনুমোদন ফ্লো**:
1. `$request->adminId` খালি → ছেড়ে দেওয়া (রাউটে অথ প্রিফিক্স কনফিগ করা নেই)
2. ইউজার → রোল (স্ট্যাটাস=0-এর নিষ্ক্রিয় রোল স্কিপ)→ পারমিশন তালিকা পাওয়া
3. সুপার অ্যাডমিন (`slug = '*'`) → সরাসরি ছেড়ে দেওয়া
4. `strtolower(method) . '.' . trim(path, '/')` গঠন → পারমিশন তালিকার সাথে তুলনা
5. ম্যাচ ব্যর্থ → 403 `{"code": 403, "message": "无权限访问"}`

**দ্বিতীয় কনফার্মেশন**: BaseController `confirmPassword()` মেথড প্রদান করে, সংবেদনশীল অপারেশন (ইউজার মুছে ফেলা、ডেটা এক্সপোর্ট ইত্যাদি) Controller স্তরে বর্তমান পাসওয়ার্ড ইনপুটের অতিরিক্ত প্রয়োজন, সেশন হাইজ্যাকের পরে অননুমোদিত অপারেশন প্রতিরোধ করে।

## 7. অডিট লগ

### 7.1 অপারেশন লগ

OperationLog মিডলওয়্যার POST / PUT / DELETE রিকোয়েস্টে স্বয়ংক্রিয়ভাবে অপারেশন লগ রেকর্ড করে। GET রিকোয়েস্ট রেকর্ড হয় না।

**রেকর্ড ফিল্ড**:

| ফিল্ড | উৎস | ব্যাখ্যা |
|------|------|------|
| id | SnowflakeService::generate() | গ্লোবাল ইউনিক ID |
| user_id | `$request->adminId` | অপারেটরের ID, লগইন না থাকলে 0 |
| action | `$request->method()` | method-এর সমতুল্য |
| method | `$request->method()` | POST / PUT / DELETE |
| path | `$request->path()` | রিকোয়েস্ট পাথ |
| ip | `$request->getRealIp()` | ক্লায়েন্টের প্রকৃত IP |
| source | detectSource() | ক্লায়েন্ট সোর্স প্ল্যাটফর্ম |
| input | রিকোয়েস্ট বডি (ডিসেনসিটাইজড JSON) | অপারেশনের সাবমিট ডেটা |
| created_at | `date('Y-m-d H:i:s')` | অপারেশন সময় |

**সংবেদনশীল ফিল্ড ফিল্টার**: রিকোয়েস্ট বডি রিকার্সিভভাবে ট্রাভার্স, নিম্নলিখিত ফিল্ডের মান `***` দিয়ে প্রতিস্থাপন:

`password`, `old_password`, `new_password`, `new_password_confirmation`, `token`, `secret`, `access_token`, `refresh_token`

**সোর্স এন্ড ডিটেকশন** (`detectSource()`): প্রায়োরিটি অনুযায়ী:

1. প্রথমে `X-Client-Platform` কাস্টম হেডার পড়ে (নেটিভ ক্লায়েন্ট স্পষ্টভাবে ঘোষণা করে)
2. ডিগ্রেড হয়ে User-Agent স্ট্রিং থেকে অনুমান (`detectSource()` মেথড ডিটেকশন অর্ডার):

| প্ল্যাটফর্ম | UA কীওয়ার্ড |
|------|----------|
| iPadOS | `iPad` |
| macOS | `Macintosh`, `Mac OS` |
| Windows | `Windows` |
| Linux | `Linux` |
| iOS | `iPhone`, `iOS`, `CFNetwork` |
| Android | `Android` |
| HarmonyOS | `HarmonyOS`, `OpenHarmony` |
| Web | ফলব্যাক ডিফল্ট মান |

**ফল্ট টলারেন্স**: লগ লেখার অস্বাভাবিকতা বিজনেস রিকোয়েস্ট ব্লক করে না (`catch (\Throwable)` নীরবে গিলে ফেলে)।

### 7.2 সিকিউরিটি লগ

**ফাইল অবস্থান**: `runtime/logs/security.log`

**রেকর্ড কনটেন্ট**:
- অ্যাটাক ইন্টারসেপ্ট লগ: অ্যাটাক ক্যাটাগরি、IP、পাথ、ফিল্ড、সোর্স、payload টুকরা (প্রথম 200 অক্ষর)
- IP ব্লক নোটিফিকেশন: ব্লক করা IP、ট্রিগার সংখ্যা

লগ পারমিশন `FILE_APPEND | LOCK_EX` ব্যবহার করে, কনকারেন্ট সেফ রাইটিং নিশ্চিত করে।

## 8. ডেটা সুরক্ষা

সিস্টেম তিন-স্তরের ডেটা সুরক্ষা পলিসি ব্যবহার করে, ডেটা প্রবাহের তিনটি পর্যায়ের সাথে মিলে।

### 8.1 ট্রান্সমিশন লেয়ার — EncryptionService

`EncryptionService` `erikwang2013/encryption` প্যাকেজ ব্যবহার করে, API রিকোয়েস্ট/রেসপন্সের সংবেদনশীল ফিল্ড এনক্রিপ্ট/ডিক্রিপ্ট করে।

**টেকনিক্যাল বিবরণ**:
- অ্যালগরিদম: `aes-256-cbc-hmac` (বিল্ট-ইন HMAC সিগনেচার টেম্পার প্রতিরোধ)
- কী: `ENCRYPTION_KEY` এনভায়রনমেন্ট ভেরিয়েবল, স্বয়ংক্রিয়ভাবে 32 বাইটে অ্যালাইন
- ব্যবহার: ক্লায়েন্ট ও API-র মধ্যে ফোন নম্বর、আইডি কার্ড নম্বর ইত্যাদি ফিল্ড ট্রান্সফারে

**ডিসেনসিটাইজেশন টুল মেথড**:
- `maskPhone('13812341234')` → `138****1234`
- `maskEmail('abc@example.com')` → `a***@example.com` (ইউজারনেম 2 অক্ষরের বেশি) বা `a**@example.com`

### 8.2 স্টোরেজ লেয়ার — Encryptable Cast

`AdminUser` মডেল `Erikwang2013\Encryptable\Encryptable` Eloquent cast ব্যবহার করে, সংশ্লিষ্ট ফিল্ড:

- `email` → Encryptable-তে cast, স্বয়ংক্রিয় এনক্রিপ্ট/ডিক্রিপ্ট
- `phone` → Encryptable-তে cast, স্বয়ংক্রিয় এনক্রিপ্ট/ডিক্রিপ্ট  
- `id_card` → Encryptable-তে cast, স্বয়ংক্রিয় এনক্রিপ্ট/ডিক্রিপ্ট

ডেটাবেসে লেখার সময় স্বয়ংক্রিয়ভাবে সাইফারটেক্সটে এনক্রিপ্ট হয়, পড়ার সময় স্বয়ংক্রিয়ভাবে প্লেইনটেক্সটে ডিক্রিপ্ট হয়। ডেটাবেস স্টোরেজ কলাম টাইপ `VARCHAR(500)`, সাইফারটেক্সট base64 ফরম্যাটে সংরক্ষিত।

**কী সিস্টেম**: ট্রান্সমিশন লেয়ার এনক্রিপশন (`ENCRYPTION_KEY`) থেকে আলাদাভাবে `ENCRYPTABLE_KEY` ব্যবহার করে, একটি কী লিক হলে অন্য স্তর অকার্যকর হয় না।

কী রোটেশন: `ENCRYPTION_PREVIOUS_KEYS` এনভায়রনমেন্ট ভেরিয়েবল ঐতিহাসিক কী তালিকা সাপোর্ট করে (কমা-বিভক্ত), পুরনো ডেটা পড়ার সময় ঐতিহাসিক কী দিয়ে ডিক্রিপ্ট করার চেষ্টা, লেখার সময় বর্তমান কী দিয়ে পুনরায় এনক্রিপ্ট।

### 8.3 ডিসপ্লে লেয়ার — ID অবস্কিউরেশন ও ডিসেনসিটাইজেশন

**Hashids ID অবস্কিউরেশন**: `HashidsService` `erikwang2013/hashids` প্যাকেজ ব্যবহার করে।

- বাহ্যিক API-তে রিটার্ন হওয়া ডেটাবেস BIGINT ID hash স্ট্রিংয়ে এনকোড হয় (যেমন `xK3mN9qR2pL7wV8b`)
- ক্লায়েন্ট রিকোয়েস্টে hash স্ট্রিং পাস করে, ব্যাকএন্ড স্বয়ংক্রিয়ভাবে মূল ID-তে ডিকোড করে
- সল্ট মান `HASHIDS_SALT` এনভায়রনমেন্ট ভেরিয়েবল থেকে ইনজেক্ট, সল্ট ভিন্ন হলে এনকোড/ডিকোড ফলাফল সম্পূর্ণ ভিন্ন
- hash সর্বনিম্ন দৈর্ঘ্য 16 অক্ষর, 62-অক্ষরের আলফানিউমেরিক ক্যারেক্টার সেট ব্যবহার করে
- BaseController `encodeId()`, `decodeId()`, `encodeIds()` সুবিধাজনক মেথড প্রদান করে

**এক্সপোর্ট ডিসেনসিটাইজেশন**: Excel/PDF এক্সপোর্টে (ExportController), সংবেদনশীল ফিল্ড একীভূতভাবে ডিসেনসিটাইজড:
- ফোন নম্বর: `138****1234`
- ইমেইল: `a***@example.com`
- আইডি কার্ড: সম্পূর্ণ ঢাকা `********`

- `openssl rand -base64 32` দিয়ে কী জেনারেট করার পরামর্শ

## 10. security.txt (RFC 9116)

সিস্টেম `/.well-known/security.txt`-এ RFC 9116 স্ট্যান্ডার্ড মেনে সিকিউরিটি যোগাযোগ তথ্য এন্ডপয়েন্ট প্রদান করে, সিকিউরিটি রিসার্চাররা ভুলনেট পেলে দ্রুত রিপোর্ট চ্যানেল খুঁজতে পারে।

**অ্যাক্সেস পদ্ধতি**:

```
GET /.well-known/security.txt
```

**রেসপন্স কনটেন্ট**:

```text
Contact: mailto:security@erik.xyz
Expires: 2027-05-20T00:00:00.000Z
Preferred-Languages: zh, en
Canonical: https://erik.xyz/.well-known/security.txt
Policy: https://erik.xyz/security-policy
```

**ফিল্ড ব্যাখ্যা**:

| ফিল্ড | ব্যাখ্যা |
|------|------|
| Contact | সিকিউরিটি ভুলনেট রিপোর্ট যোগাযোগের উপায় |
| Expires | ফাইলের মেয়াদোত্তীর্ণ সময়, নিয়মিত আপডেট প্রয়োজন |
| Preferred-Languages | পছন্দের যোগাযোগ ভাষা |
| Canonical | এই ফাইলের ক্যানোনিকাল URL |
| Policy | সিকিউরিটি পলিসি/ভুলনেট ডিসক্লোজার পলিসি লিংক |

এই এন্ডপয়েন্ট রেট লিমিট、অথ ইত্যাদি মিডলওয়্যার সীমাবদ্ধতায় আটকায় না, যেকেউ সরাসরি অ্যাক্সেস করতে পারে।

## 11. Nginx সিকিউরিটি কনফিগ

প্রজেক্ট `docs/nginx-security.conf` প্রোডাকশন পরিবেশের Nginx রিভার্স প্রক্সির সিকিউরিটি হার্ডেনিং রেফারেন্স কনফিগ হিসেবে প্রদান করে।

**অন্তর্ভুক্ত সিকিউরিটি ব্যবস্থা**:

| কনফিগ আইটেম | কাজ |
|--------|------|
| `server_tokens off` | Nginx ভার্সন নম্বর লুকায় |
| `client_max_body_size 10m` | রিকোয়েস্ট বডি সাইজ সীমাবদ্ধ, SecurityFilter-এর সাথে সমন্বিত |
| `limit_req_zone` | Nginx স্তরে রিকোয়েস্ট ফ্রিকোয়েন্সি সীমাবদ্ধতা |
| `limit_conn_zone` | কনকারেন্ট কানেকশন সংখ্যা সীমাবদ্ধতা |
| `add_header` সিকিউরিটি হেডার | Nginx স্তরে X-XSS-Protection ইত্যাদি সিকিউরিটি হেডার যুক্ত |
| `if ($request_method)` | Nginx স্তরে নন-স্ট্যান্ডার্ড HTTP মেথড প্রত্যাখ্যান |
| SSL/TLS কনফিগ | আধুনিক TLS 1.2/1.3 কনফিগ, দুর্বল সাইফার স্যুট নিষিদ্ধ |
| ব্যাকএন্ড হেডার লুকানো | `proxy_hide_header` দিয়ে webman ভার্সন ইত্যাদি সংবেদনশীল হেডার সরানো |

**ব্যবহার পদ্ধতি**: `docs/nginx-security.conf`-এর কনফিগ আপনার Nginx server ব্লকে মার্জ করুন, প্রকৃত ডোমেইন ও সার্টিফিকেট পাথ অনুযায়ী সামঞ্জস্য করুন।

## 12. থ্রেট মডেল

### 12.1 সুরক্ষিত থ্রেট

| থ্রেট টাইপ | অ্যাটাক ভেক্টর | প্রতিরক্ষা স্তর |
|----------|---------|---------|
| HTTP মেথড অপব্যবহার | TRACE/TRACK XST অ্যাটাক、CONNECT টানেল প্রক্সি、WebDAV মেথড প্রোবিং | SecurityFilter 405 মেথড হোয়াইটলিস্ট (GET/POST/PUT/DELETE/OPTIONS/HEAD) |
| টার্গেটেড ব্রুট ফোর্স | নির্দিষ্ট ইউজারকে বারবার পাসওয়ার্ড চেষ্টা | অ্যাকাউন্ট লক (5 বার ব্যর্থ 15 মিনিট লক) + RateLimit (লগইন 10/min) + Captcha |
| ব্রুট ফোর্স | ডিস্ট্রিবিউটেড IP বারবার ইউজারনেম/পাসওয়ার্ড চেষ্টা | RateLimit (লগইন 10/min) + Captcha |
| XSS ক্রস-সাইট স্ক্রিপ্টিং | `<script>`, onerror, javascript: | SecurityFilter (5 প্যাটার্ন) + X-XSS-Protection রেসপন্স হেডার + CSP |
| SQL ইনজেকশন | UNION SELECT, OR 1=1, কমেন্ট বাইপাস | SecurityFilter (6 প্যাটার্ন) + Eloquent ORM প্যারামিটারাইজড কোয়েরি |
| CSRF ক্রস-সাইট রিকোয়েস্ট ফোরজারি | ক্ষতিকর সাইটের পক্ষ থেকে রিকোয়েস্ট | SecurityFilter Origin/Referer যাচাই |
| পাথ ট্রাভার্সাল | `../../etc/passwd` | SecurityFilter পাথ ট্রাভার্সাল প্যাটার্ন + UploadController এক্সটেনশন হোয়াইটলিস্ট |
| কমান্ড ইনজেকশন | `;ls`, `` `whoami` ``, `$(cat ...)` | SecurityFilter (4 প্যাটার্ন) |
| সেশন হাইজ্যাক | JWT Token চুরি | JWT স্বল্প মেয়াদ (2h) + ব্ল্যাকলিস্ট লগআউট + সংবেদনশীল অপারেশনে দ্বিতীয় পাসওয়ার্ড কনফার্মেশন |
| ID এনুমারেশন | সংখ্যাসূচক ID ট্রাভার্স করে ডেটার পরিমাণ অনুমান | Hashids র্যান্ডম স্ট্রিংয়ে অবস্কিউরেশন |
| ডেটা লিক | DB এক্সফিলট্রেশন / ম্যান-ইন-দ্য-মিডল / লগ লিক | তিন-স্তর এনক্রিপশন/ডিসেনসিটাইজেশন + OperationLog সংবেদনশীল ফিল্ড ফিল্টার |
| DoS অ্যাটাক | বিশাল রিকোয়েস্ট বডি / উচ্চ ফ্রিকোয়েন্সি রিকোয়েস্ট | রিকোয়েস্ট বডি 10MB সীমা + RateLimit 60/min + IP ব্ল্যাকলিস্ট |
| প্রিভিলেজ এসকেলেশন | নিম্ন-অনুমতি ইউজার ম্যানেজমেন্ট ইন্টারফেস অ্যাক্সেস | RBAC method.path গ্রানুলারিটি অনুমোদন |
| ফাইল আপলোড অ্যাটাক | shell.php.png ডাবল এক্সটেনশন | SecurityFilter ক্ষতিকর ফাইল ডিটেকশন |

### 12.2 পরিচিত সীমাবদ্ধতা

| সীমাবদ্ধতা | প্রভাবের সুযোগ | প্রশমন ব্যবস্থা |
|------|---------|---------|
| CSRF সুরক্ষা শুধু ব্রাউজারে কার্যকর | নন-ব্রাউজার ক্লায়েন্ট (curl, Postman, মোবাইল App) Origin/Referer চেক বাইপাস করতে পারে | নন-ব্রাউজার ক্লায়েন্ট স্বাভাবিকভাবেই CSRF অ্যাটাকের শিকার নয়; JWT অথ-এর উপর নির্ভর করে Cookie প্রতিস্থাপন |
| Redis অনুপলব্ধ হলে রেট লিমিট ও ব্ল্যাকলিস্ট fail-open-এ ডিগ্রেড | আক্রমণকারী রেট লিমিট ও উচ্চ-ফ্রিকোয়েন্সি ইন্টারসেপ্ট বাইপাস করতে পারে | Redis উপলব্ধতা মনিটরিং অ্যালার্ম; JWT স্বল্প মেয়াদ ফলব্যাক |
| স্বাধীন WAF ইঞ্জিন নেই | SecurityFilter `@preg_match` রেজেক্স ম্যাচিং ব্যবহার করে, ডেডিকেটেড WAF রুল ইঞ্জিন নয় | প্রোডাকশনে Nginx ModSecurity বা Cloudflare WAF অগ্রবর্তী করার পরামর্শ |
| JWT স্টেটলেস, সক্রিয়ভাবে অকার্যকর করা যায় না | Token মেয়াদোত্তীর্ণ হওয়ার আগে সার্ভার থেকে সক্রিয়ভাবে রিভোক করা যায় না (ব্ল্যাকলিস্ট ছাড়া) | ব্ল্যাকলিস্ট + স্বল্প 2h TTL ঝুঁকির উইন্ডো কমায় |
| IP ব্ল্যাকলিস্ট শুধু মেমরিতে সংরক্ষিত | Redis রিস্টার্ট হলে ব্ল্যাকলিস্ট হারায় | Ban সময় মাত্র 15 মিনিট, প্রভাব সীমিত |
| অ্যাডমিন এন্ডপয়েন্টে বিশেষ রেট লিমিট নেই | অ্যাডমিন ইন্টারফেস সাধারণ ইন্টারফেসের সাথে 60/min ডিফল্ট সীমা ভাগ করে | অ্যাডমিন অপারেশন ফ্রিকোয়েন্সি স্বাভাবিকভাবেই কম, আপাতত আলাদা করা লাগবে না |
| `@preg_match` এরর দমন | বিকৃত রেজেক্স ইনপুটে নীরবে অকার্যকর | `preg_last_error()` দিয়ে মনিটরিং যোগ করা যায়, বর্তমানে ইমপ্লিমেন্ট করা নেই |
