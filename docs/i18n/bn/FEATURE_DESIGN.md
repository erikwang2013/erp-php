## 1. সিস্টেম ওভারভিউ

ওপেন-ইআরপি সিস্টেম (open-erp) webman v2 + Flutter ভিত্তিক ফুল-স্ট্যাক এন্টারপ্রাইজ রিসোর্স প্ল্যানিং সিস্টেম, সিস্টেম ম্যানেজমেন্ট, ক্রয়-স্টক-বিক্রয়, ফাইন্যান্স, CRM, অ্যাপ্রুভাল ওয়ার্কফ্লো, মেসেজ নোটিফিকেশন, প্রজেক্ট ম্যানেজমেন্ট, হিউম্যান রিসোর্স, উৎপাদন ম্যানুফ্যাকচারিং, কাস্টম রিপোর্ট চৌদ্দটি বড় ব্যবসায়িক ডোমেইন কভার করে।

### 1.1 ডিজাইন লক্ষ্য
- মনোলিথ ডিপ্লয়মেন্ট, মডিউলার ডিজাইন
- সব ID snowflake দিয়ে তৈরি + hashids এনক্রিপশনে ট্রান্সমিশন
- সংবেদনশীল ডেটা ডুয়াল-লেয়ার এনক্রিপশন (ট্রান্সমিশন লেয়ার AES-256-CBC + স্টোরেজ লেয়ার AES-128-ECB)
- মুভিং ওয়েটেড এভারেজ কস্ট অ্যাকাউন্টিং
- ক্রস-মডিউল স্বয়ংক্রিয় লিংকেজ (ক্রয়→AP, বিক্রয়→AR, রসিদ-পেমেন্ট→রাইট-অফ)

### 1.2 টেকনিক্যাল কনস্ট্রেইন্ট
- PHP 8.3+, MySQL 8.0+, Redis 7, Elasticsearch 8
- টেবিল প্রিফিক্স erp_, প্রাইমারি কী BIGINT নন-অটোইনক্রিমেন্ট
- API ভার্সন রিকোয়েস্ট হেডার API-Version দিয়ে নিয়ন্ত্রিত
- JWT অথেনটিকেশন + RBAC পারমিশন
- গ্লোবাল ফাংশনে \ প্রিফিক্স নেই

## 2. সিস্টেম ম্যানেজমেন্ট মডিউল

### 2.1 ইউজার ম্যানেজমেন্ট
- অ্যাডমিন CRUD, ব্যাচ সক্রিয়/নিষ্ক্রিয়, ব্যাচ সফট ডিলিট সাপোর্ট
- Excel ব্যাচ ইমপোর্ট (লাইন-বাই-লাইন ভ্যালিডেশন+এরর রিপোর্ট)
- পাসওয়ার্ড bcrypt হ্যাশ, পাসওয়ার্ড পরিবর্তনে পুরনো পাসওয়ার্ড কনফার্মেশন
- ডিলিট অপারেশনে বর্তমান ইউজারের পাসওয়ার্ড দ্বিতীয় কনফার্মেশন
- মোবাইল/ইমেইল/আইডি কার্ড নম্বর এনক্রিপ্টেড স্টোরেজ, লিস্টে স্বয়ংক্রিয় ডিসেন্সিটাইজেশন

### 2.2 রোল পারমিশন (RBAC)
- রোল CRUD, slug ইউনিক আইডেন্টিফায়ার
- পারমিশন ট্রি (সীমাহীন লেভেল parent_id সেলফ-রেফারেন্স), টাইপ: মেনু/বাটন/API
- পারমিশন আইডেন্টিফায়ার ফরম্যাট: {method}.{path} (যেমন get.admin/product, post.admin/user/batch/destroy)
- রোল-পারমিশন ম্যানি-টু-ম্যানি সম্পর্ক
- সুপার অ্যাডমিন(super_admin) সব পারমিশন চেক স্কিপ করে
- AdminPermission মিডলওয়্যার Redis-এ পারমিশন ক্যাশ (TTL=60s)

### 2.3 সিস্টেম কনফিগ
- কী-ভ্যালু স্টোরেজ, গ্রুপ সাপোর্ট
- ভ্যালু টাইপ: string|int|bool|json|array

### 2.4 অপারেশন অডিট
- সব POST/PUT/DELETE অপারেশন স্বয়ংক্রিয় রেকর্ড
- রেকর্ড: অপারেটর, অ্যাকশন, মেথড, পাথ, IP, প্যারামিটার (সংবেদনশীল ফিল্ড ডিসেন্সিটাইজড), সময়
- 8 প্ল্যাটফর্ম সোর্স অটো ডিটেকশন (Web/Flutter/HarmonyOS/API ইত্যাদি)
- শুধুমাত্র কোয়েরি সাপোর্ট, ডিলিট/মডিফাই করা যায় না

### 2.5 নিরাপত্তা সুরক্ষা
- 18 স্তরের ডিফেন্স-ইন-ডেপথ (বিস্তারিত SECURITY.md দেখুন)
- SecurityFilter: HTTP মেথড রেস্ট্রিকশন + XSS/SQL ইনজেকশন/পাথ ট্রাভার্সাল/কমান্ড ইনজেকশন/CSRF ইন্টারসেপশন
- RateLimit: Redis স্লাইডিং উইন্ডো রেট লিমিট (Lua অ্যাটমিক, 60 বার/মিনিট)
- ক্লিক ক্যাপচা (লগইন/রেজিস্ট্রেশন বাধ্যতামূলক)
- অ্যাকাউন্ট লক: ৫ বার ব্যর্থ হলে ১৫ মিনিট লক
- কনকারেন্ট সেশন লিমিট: একই ইউজারের সর্বোচ্চ ৩টি Token
- CSP হেডার, security.txt (RFC 9116)
- poster-php সংবেদনশীল অপারেশনে র্যান্ডম দ্বিতীয় ভেরিফিকেশন

## 3. পণ্য ও বেস ডেটা

### 3.1 পণ্য ম্যানেজমেন্ট
- পণ্য প্রোফাইল: কোড(ইউনিক)、নাম、বারকোড、স্পেসিফিকেশন、বেস ইউনিট、ছবি、বিবরণ
- মাল্টি-স্পেক SKU: একই পণ্যের অধীনে একাধিক SKU, প্রতিটির নিজস্ব কোড、বারকোড、স্পেক অ্যাট্রিবিউট(JSON)
- মাল্টি-ইউনিট কনভার্সন: বেস ইউনিট ↔ অক্সিলিয়ারি ইউনিট, কনভার্সন রেট
- প্রাইস স্ট্র্যাটেজি: ক্রয় মূল্য、পাইকারি মূল্য、খুচরা মূল্য、কাস্টমার লেভেল মূল্য
- পণ্য ক্যাটাগরি: সীমাহীন লেভেল ট্রি স্ট্রাকচার, ড্র্যাগ সর্টিং সাপোর্ট
- ব্র্যান্ড ম্যানেজমেন্ট: ব্র্যান্ড নাম、Logo、বিবরণ

### 3.2 গুদাম ও লোকেশন
- মাল্টি-গুদাম ম্যানেজমেন্ট (নাম、কোড、ঠিকানা、দায়িত্বপ্রাপ্ত)
- প্রতিটি গুদামে মাল্টি-লোকেশন (কোড গুদামের মধ্যে ইউনিক)
- গুদামের যোগাযোগ নম্বর এনক্রিপ্টেড স্টোরেজ

### 3.3 সাপ্লায়ার/কাস্টমার
- সাপ্লায়ার প্রোফাইল: কোড、নাম、যোগাযোগ ব্যক্তি、ফোন/ইমেইল(এনক্রিপ্টেড)、ঠিকানা、ব্যাংক তথ্য
- কাস্টমার প্রোফাইল: কোড、নাম、কাস্টমার লেভেল、ক্রেডিট সীমা
- কাস্টমার লেভেল: নাম、ডিফল্ট ডিসকাউন্ট রেট

## 4. ক্রয় মডিউল

### 4.1 ক্রয় প্রসেস
আবেদন → অনুমোদন → অর্ডার → রিসিভ → সেটেলমেন্ট

### 4.2 ক্রয় আবেদন
- ডিপার্টমেন্ট/ব্যক্তি ক্রয় প্রয়োজনীয়তা জমা দেয়
- স্ট্যাটাস: অপেক্ষমাণ অনুমোদন → অনুমোদিত/প্রত্যাখ্যাত → অর্ডারে রূপান্তরিত
- অ্যাপ্রুভার অপারেশন সাপোর্ট

### 4.3 ক্রয় অর্ডার
- সাপ্লায়ার、পণ্য বিস্তারিত (পরিমাণ、ইউনিট মূল্য、টাকার অঙ্ক) সংযুক্ত
- স্ট্যাটাস: অপেক্ষমাণ রিভিউ → রিভিউড → আংশিক রিসিভ → রিসিভড → বাতিল
- ক্রয় আবেদনের ভিত্তিতে তৈরি করা যায়, সরাসরিও তৈরি করা যায়

### 4.4 ক্রয় রিসিভ (ক্রস-মডিউল লিংকেজ)
- অর্ডার অনুযায়ী রিসিভ, ব্যাচ রিসিভ সাপোর্ট
- রিসিভের সময় স্বয়ংক্রিয় ট্রিগার:
  1. InventoryService.stockIn() → রিয়েল-টাইম ইনভেন্টরি আপডেট + মুভিং ওয়েটেড এভারেজ পুনঃগণনা
  2. FinanceService.createAp() → AP রেকর্ড তৈরি
  3. অর্ডারের রিসিভড পরিমাণ ও স্ট্যাটাস আপডেট
- লোকেশন、ব্যাচ নম্বর রেকর্ড সাপোর্ট

### 4.5 ক্রয় রিটার্ন
- সাপ্লায়ারে ফেরত, স্টক-আউট রিভার্সাল তৈরি
- রিসিভ ফর্মের সাথে লিংক

### 4.6 সাপ্লায়ার সেটেলমেন্ট
- সাপ্লায়ার অনুযায়ী সামারি: ক্রয় পরিমাণ、পরিশোধিত、পরিশোধযোগ্য
- সেটেলমেন্ট স্ট্যাটাস: আনসেটেলড/আংশিক সেটেলড/সেটেলড

## 5. বিক্রয় মডিউল

### 5.1 বিক্রয় প্রসেস
কোটেশন → অর্ডার → ডেলিভারি → সেটেলমেন্ট

### 5.2 কোটেশন
- কাস্টমারকে মূল্য জানানো, সেলস অর্ডারে রূপান্তর সাপোর্ট
- স্ট্যাটাস: ড্রাফ্ট → কোটেড → অর্ডারে রূপান্তরিত → মেয়াদোত্তীর্ণ

### 5.3 সেলস অর্ডার
- কাস্টমার、পণ্য বিস্তারিত (পরিমাণ、ইউনিট মূল্য、ডিসকাউন্ট) সংযুক্ত
- স্ট্যাটাস: অপেক্ষমাণ রিভিউ → রিভিউড → আংশিক ডেলিভারি → ডেলিভারড → বাতিল
- ডিসকাউন্ট অঙ্ক সাপোর্ট

### 5.4 সেলস ডেলিভারি (ক্রস-মডিউল লিংকেজ)
- অর্ডার অনুযায়ী ডেলিভারি, ব্যাচ ডেলিভারি সাপোর্ট
- ডেলিভারির সময় স্বয়ংক্রিয় ট্রিগার:
  1. InventoryService.stockOut() → ইনভেন্টরি কমানো (মুভিং ওয়েটেড এভারেজ কস্ট ব্যবহার)
  2. FinanceService.createAr() → AR রেকর্ড তৈরি
  3. অর্ডারের ডেলিভারড পরিমাণ ও স্ট্যাটাস আপডেট

### 5.5 সেলস রিটার্ন
- কাস্টমার রিটার্ন, স্টক-ইন রিভার্সাল তৈরি

### 5.6 কাস্টমার সেটেলমেন্ট ও মুনাফা
- কাস্টমার অনুযায়ী সামারি: বিক্রয় পরিমাণ、প্রাপ্ত、প্রাপ্য
- সেলস মুনাফা: অর্ডার/পণ্য/কাস্টমার ডাইমেনশনে হিসাব

## 6. ইনভেন্টরি মডিউল

### 6.1 ইনভেন্টরি ম্যানেজমেন্ট
- রিয়েল-টাইম ইনভেন্টরি: গুদাম+লোকেশন+ব্যাচ+SKU চার-ডাইমেনশনাল নির্ভুলতা
- ইন/আউট স্টক ফ্লো: সব ইনভেন্টরি পরিবর্তন ইউনিফাইড রেকর্ড (দিক、পরিমাণ、কস্ট প্রাইস、সোর্স ডকুমেন্ট নম্বর)
- ব্যাচ ট্র্যাকিং: উৎপাদন তারিখ、মেয়াদ শেষ তারিখ
- সিরিয়াল নম্বর ট্র্যাকিং: ইউনিক সিরিয়াল নম্বর, ইন/আউট স্টকে স্ট্যাটাস রেকর্ড (স্টকে/আউট)

### 6.2 কস্ট অ্যাকাউন্টিং
- মুভিং ওয়েটেড এভারেজ মেথড
- সূত্র: নতুন গড় = (মূল ইনভেন্টরি মোট মূল্য + এইবার ইন স্টক মোট মূল্য) / (মূল ইনভেন্টরি পরিমাণ + এইবার ইন স্টক পরিমাণ)
- প্রতিটি ইন স্টকে স্বয়ংক্রিয় পুনঃগণনা, আউট স্টক বর্তমান গড় মূল্যে কস্ট
- সম্পূর্ণ কস্ট রেকর্ড চেইন (পরিবর্তনের আগের গড় → পরিবর্তনের পরের গড়)

### 6.3 ইনভেন্টরি ট্রান্সফার
- গুদামের মধ্যে/লোকেশনের মধ্যে ট্রান্সফার
- স্ট্যাটাস: অপেক্ষমাণ ট্রান্সফার → আউট করা হয়েছে → ইন নেওয়া হয়েছে → সম্পন্ন
- স্বয়ংক্রিয় আউট/ইন স্টক ফ্লো তৈরি

### 6.4 কাউন্ট ম্যানেজমেন্ট
- প্ল্যান কাউন্ট (গুদাম/ক্যাটাগরি অনুযায়ী) + ডাইনামিক কাউন্ট (SKU অনুযায়ী)
- বুক ভ্যালু পরিমাণ vs প্রকৃত কাউন্ট পরিমাণ রেকর্ড
- কাউন্ট পার্থক্য স্বয়ংক্রিয়ভাবে সারপ্লাস/শর্টেজ ইন/আউট স্টক ফ্লো তৈরি

### 6.5 ইনভেন্টরি অ্যালার্ট
- SKU+গুদাম অনুযায়ী উপরে/নিচে সীমা সেট
- নিম্ন সীমার নিচে/উর্ধ্ব সীমার উপরে গেলে স্বয়ংক্রিয় অ্যালার্ট লগ রেকর্ড

## 7. ফাইন্যান্স মডিউল

### 7.1 অ্যাকাউন্টিং সাবজেক্ট
- সাবজেক্ট ট্রি: অ্যাসেট/লায়াবিলিটি/ইকুইটি/ইনকাম/এক্সপেন্স পাঁচটি বড় ক্যাটাগরি
- সাবজেক্ট কোড ইউনিক
- ব্যালেন্স দিক: ডেবিট/ক্রেডিট

### 7.2 জার্নাল ভাউচার
- ভাউচার নম্বর、তারিখ、সারাংশ
- ডাবল-এন্ট্রি: প্রতিটি এন্ট্রিতে ডেবিট অঙ্ক ও ক্রেডিট অঙ্ক থাকে (ডেবিট=ক্রেডিট আবশ্যক)
- স্ট্যাটাস: ড্রাফ্ট → রিভিউড

### 7.3 জেনারেল লেজার
- অ্যাকাউন্টিং সাবজেক্ট+অ্যাকাউন্টিং পিরিয়ড (বছর/মাস) অনুযায়ী সামারি
- রেকর্ড: পিরিয়ড শুরুর ডেবিট/ক্রেডিট ব্যালেন্স、এই পিরিয়ডের ডেবিট/ক্রেডিট অকুরেন্স、পিরিয়ড শেষের ডেবিট/ক্রেডিট ব্যালেন্স
- পিরিয়ড শেষের ব্যালেন্স = পিরিয়ড শুরুর ব্যালেন্স ± এই পিরিয়ডের অকুরেন্স (সাবজেক্ট ব্যালেন্স দিক অনুযায়ী)
- ভাউচার রিভিউর পর স্বয়ংক্রিয় আপডেট
- বছর/মাস/সাবজেক্ট ফিল্টার সাপোর্ট

### 7.4 সাবসিডিয়ারি লেজার
- নির্দিষ্ট সাবজেক্টের প্রতিটি ভাউচার এন্ট্রি লাইন-বাই-লাইন রেকর্ড
- অন্তর্ভুক্ত: ভাউচার নম্বর、দিক(ডেবিট/ক্রেডিট)、অঙ্ক、ব্যালেন্স、সারাংশ、তারিখ
- সাবজেক্ট+তারিখ রেঞ্জ কোয়েরি সাপোর্ট
- ভাউচার এন্ট্রির সাথে সিঙ্ক আপডেট

### 7.5 ব্যালেন্স শিট
- অ্যাকাউন্টিং পিরিয়ড অনুযায়ী তৈরি (মাসিক/বার্ষিক)
- স্বয়ংক্রিয় জেনারেল লেজার ব্যালেন্স সামারি:
  - অ্যাসেট ক্যাটাগরি সাবজেক্ট(1) → মোট অ্যাসেট = কারেন্ট অ্যাসেট + নন-কারেন্ট অ্যাসেট
  - লায়াবিলিটি ক্যাটাগরি সাবজেক্ট(2) → মোট লায়াবিলিটি = কারেন্ট লায়াবিলিটি + নন-কারেন্ট লায়াবিলিটি
  - ইকুইটি ক্যাটাগরি সাবজেক্ট(3) → ওনার্স ইকুইটি
  - আইডেন্টিটি: অ্যাসেট = লায়াবিলিটি + ওনার্স ইকুইটি
- স্ন্যাপশট সেভ সাপোর্ট (JSON সম্পূর্ণ ডেটা)
- স্ন্যাপশট না থাকলে স্বয়ংক্রিয় জেনারেল লেজার থেকে তৈরি

### 7.6 ক্যাশ ফ্লো স্টেটমেন্ট
- অ্যাকাউন্টিং পিরিয়ড অনুযায়ী তৈরি (মাসিক/বার্ষিক)
- তিন ক্যাটাগরি:
  - অপারেটিং অ্যাক্টিভিটি ক্যাশ ফ্লো (বিক্রয় রসিদ - ক্রয় পেমেন্ট - খরচ ব্যয়)
  - ইনভেস্টিং অ্যাক্টিভিটি ক্যাশ ফ্লো
  - ফাইন্যান্সিং অ্যাক্টিভিটি ক্যাশ ফ্লো
- পিরিয়ড শুরুর/শেষের ক্যাশ ব্যালেন্স = সব ব্যাংক অ্যাকাউন্টের পিরিয়ড শুরুর/শেষের ব্যালেন্স সমষ্টি
- স্বয়ংক্রিয় ক্যাশ ও ব্যাংক জার্নাল সামারি করে তৈরি
- স্ন্যাপশট সেভ সাপোর্ট (JSON সম্পূর্ণ ডেটা)

### 7.7 AR/AP
- ক্রয় রিসিভ/সেলস ডেলিভারি থেকে স্বয়ংক্রিয় তৈরি
- AR: টাইপ=প্রাপ্য, কাস্টমার লিংক, সোর্স=সেলস ডেলিভারি ফর্ম
- AP: টাইপ=পরিশোধযোগ্য, সাপ্লায়ার লিংক, সোর্স=ক্রয় রিসিভ ফর্ম
- স্ট্যাটাস: রাইট-অফ হয়নি → আংশিক রাইট-অফ → রাইট-অফ সম্পন্ন
- একই সোর্স ডকুমেন্ট থেকে বারবার তৈরি করা যায় না (আইডেমপোটেন্ট প্রোটেকশন)

### 7.8 রসিদ ম্যানেজমেন্ট
- মাল্টি-অ্যাকাউন্ট (নগদ/ব্যাংক/WeChat/Alipay)
- রিভিউর পর স্বয়ংক্রিয় ব্যাংক অ্যাকাউন্ট ব্যালেন্স ও ক্যাশ জার্নাল আপডেট
- রাইট-অফ: AR রেকর্ড নির্বাচন, রাইট-অফ অঙ্ক ইনপুট (রাইট-অফ না হওয়া ব্যালেন্সের বেশি নয়)
- আংশিক রাইট-অফ স্ট্যাটাস স্বয়ংক্রিয় ফ্লো

### 7.9 পেমেন্ট ম্যানেজমেন্ট
- রসিদের মতোই লজিক, দিক বিপরীত
- AP রেকর্ড রাইট-অফ

### 7.10 ক্যাশ ও ব্যাংক জার্নাল
- অ্যাকাউন্ট+তারিখ অনুযায়ী প্রতিটি ইনকাম/ব্যয় রেকর্ড
- পরিবর্তনের পরের ব্যালেন্স রেকর্ড
- ব্যাংক অ্যাকাউন্ট ব্যালেন্স রিয়েল-টাইম আপডেট

### 7.11 খরচ রিইমবার্সমেন্ট
- প্রসেস: সাবমিট → অনুমোদন → পেমেন্ট
- খরচ সাবজেক্ট লিংক
- পেমেন্টের পর স্বয়ংক্রিয় পেমেন্ট ফর্ম + জার্নাল তৈরি

### 7.12 লাভ-লস স্টেটমেন্ট
- মাস অনুযায়ী সামারি: অপারেটিং ইনকাম、অপারেটিং কস্ট、খরচ、মুনাফা
- ডেটা স্ন্যাপশট স্টোরেজ (year+month ইউনিক)

### 7.13 স্থায়ী সম্পদ অবচয়
- অ্যাসেট পূর্ণ লাইফসাইকেল ম্যানেজমেন্ট: ক্রয় → ব্যবহার → অবচয় → নিষ্পত্তি
- অবচয় মেথড: স্ট্রেইট-লাইন ((মূল্য-আনুমানিক অবশিষ্ট) / ব্যবহারের মাস সংখ্যা)
- মাসিক অবচয় গণনা, স্বয়ংক্রিয় অবচয় রেকর্ড তৈরি
- রেকর্ড: মূল্য、আনুমানিক অবশিষ্ট、ব্যবহারের বছর、মাসিক অবচয় অঙ্ক、সঞ্চিত অবচয়、নেট ভ্যালু

### 7.14 ট্যাক্স ম্যানেজমেন্ট
- মাল্টি-ট্যাক্স সাপোর্ট: ভ্যাট/কর্পোরেট ইনকাম ট্যাক্স/ব্যক্তিগত ইনকাম ট্যাক্স/স্ট্যাম্প ডিউটি
- ট্যাক্স রেট নমনীয় কনফিগারেশন
- ক্রয়/বিক্রয় ডকুমেন্টের সাথে লিংক, স্বয়ংক্রিয় ট্যাক্স অঙ্ক রেকর্ড

### 7.15 মাল্টি-কারেন্সি
- কারেন্সি ম্যানেজমেন্ট: CNY/USD/EUR/JPY ইত্যাদি
- হোম কারেন্সি আইডেন্টিফায়ার
- এক্সচেঞ্জ রেট কার্যকর তারিখ অনুযায়ী ম্যানেজমেন্ট
- ফরেন কারেন্সি কনভার্সন সাপোর্ট

### 7.16 বাজেট ম্যানেজমেন্ট
- বার্ষিক বাজেট প্রণয়ন: কস্ট সেন্টার+সাবজেক্ট+মাস অনুযায়ী প্রণয়ন
- বাজেট vs প্রকৃত তুলনামূলক বিশ্লেষণ
- এক্সিকিউশন রেট হিসাব + পার্থক্য বিশ্লেষণ
- স্ট্যাটাস: ড্রাফ্ট → অনুমোদিত → চলমান → বন্ধ

### 7.17 কস্ট সেন্টার/প্রফিট সেন্টার
- ট্রি লেভেল স্ট্রাকচার
- কস্ট সংগ্রহ + খরচ বণ্টন
- প্রফিট সেন্টার স্বাধীন অ্যাকাউন্টিং

## 8. CRM মডিউল

### 8.1 কাস্টমার ম্যানেজমেন্ট
- কাস্টমার প্রোফাইল বেস ডেটা কাস্টমারের সাথে লিংক
- কাস্টমারের অধীনে একাধিক যোগাযোগ ব্যক্তি (প্রাইমারি যোগাযোগ চিহ্ন)
- যোগাযোগ ব্যক্তির ফোন/ইমেইল এনক্রিপ্টেড স্টোরেজ

### 8.2 ফলো-আপ রেকর্ড
- ফলো-আপ মাধ্যম: ফোন/ভিজিট/ইমেইল/মেসেজ/অন্যান্য
- ফলো-আপ কনটেন্ট、পরবর্তী ফলো-আপ প্ল্যান、পরবর্তী ফলো-আপ সময় রেকর্ড
- কাস্টমার、যোগাযোগ ব্যক্তি、সুযোগের সাথে লিংক

### 8.3 মার্কেটিং ক্যাম্পেইন
- ক্যাম্পেইনের পূর্ণ লাইফসাইকেল: প্ল্যান → চলমান → সম্পন্ন → বাতিল
- মাল্টি-চ্যানেল: ইমেইল/এসএমএস/ফোন/ইভেন্ট/সোশ্যাল মিডিয়া
- অংশগ্রহণকারী কাস্টমার ট্র্যাকিং, কনভার্সন রেট স্ট্যাটিসটিক্স
- বাজেট vs প্রকৃত খরচ তুলনা

### 8.4 সার্ভিস টিকেট
- টিকেট ম্যানেজমেন্ট: অপেক্ষমাণ → প্রসেসিং → সমাধানকৃত → বন্ধ
- প্রায়োরিটি: নিম্ন/মধ্যম/উচ্চ/জরুরি
- ক্যাটাগরি: টেকনিক্যাল সাপোর্ট/অভিযোগ/পরামর্শ/রিটার্ন-এক্সচেঞ্জ/অন্যান্য
- হ্যান্ডলার অ্যাসাইনমেন্ট + রিপ্লাই (পাবলিক/অভ্যন্তরীণ নোট)
- সমাধান রেট স্ট্যাটিসটিক্স

### 8.5 কাস্টমার অ্যানালিটিক্স রিপোর্ট
- ৬টি মূল মেট্রিক: নতুন কাস্টমার/সক্রিয় কাস্টমার/রিটেনশন রেট/গড় অর্ডার ভ্যালু/CLV/টিকেট সমাধান রেট
- রিপোর্ট স্বয়ংক্রিয় তৈরি (JSON ডেটা স্ন্যাপশট)
- মাসিক/ত্রৈমাসিক/বার্ষিক সাপোর্ট

### 8.6 সেলস ফানেল
- স্টেজ কনফিগ: প্রাথমিক যোগাযোগ(10%) → প্রয়োজনীয়তা নিশ্চিতকরণ(30%) → কোটেশন সলিউশন(50%) → বিজনেস নেগোসিয়েশন(70%) → ডিল(100%) → লস্ট(0%)
- সুযোগ: কাস্টমার、বর্তমান স্টেজ、আনুমানিক অঙ্ক、ডিল প্রোবাবিলিটি、প্রত্যাশিত ডিল তারিখ、দায়িত্বপ্রাপ্ত
- সুযোগ স্ট্যাটাস: লস্ট/চলমান/ডিল
- স্টেজ মুভমেন্ট ট্র্যাকিং

### 8.7 কাস্টমার পাবলিক পুল
- কাস্টমার পাবলিক পুল: বরাদ্দকৃত নয় বা সময়সীমা অতিক্রম করে ফলো-আপ না হওয়া কাস্টমার স্বয়ংক্রিয়ভাবে পাবলিক পুলে প্রবেশ করে
- রিসাইকেল রুল: কাস্টমার লেভেল অনুযায়ী ফলো-আপ ছাড়া স্বয়ংক্রিয় রিসাইকেল দিন সেট
- প্রতি ব্যক্তির সর্বোচ্চ ক্লেইম সংখ্যা সীমা, কাস্টমার রিসোর্স অবক্ষেপণ প্রতিরোধ
- ক্লেইম/রিলিজ/রিসাইকেল অপারেশনে সব ফ্লো রেকর্ড
- সেলস টিমের সক্রিয়তা বৃদ্ধি, কাস্টমার অবক্ষেপণ এড়ানো

### 8.8 CRM কোটেশন ম্যানেজমেন্ট
- বিক্রয় মডিউল থেকে স্বাধীন CRM অভ্যন্তরীণ কোটেশন প্রসেস
- স্ট্যাটাস: ড্রাফ্ট → পাঠানো হয়েছে → কাস্টমার নিশ্চিত → কন্ট্রাক্টে রূপান্তরিত → মেয়াদোত্তীর্ণ
- কোটেশন বৈধতা সময়কাল সাপোর্ট
- সরাসরি কন্ট্রাক্টে রূপান্তর সাপোর্ট (`to-contract`)
- কাস্টমার ও সুযোগের সাথে লিংক

### 8.9 কন্ট্রাক্ট ম্যানেজমেন্ট
- কন্ট্রাক্ট পূর্ণ লাইফসাইকেল: ড্রাফ্ট → অপেক্ষমাণ অনুমোদন → অনুমোদিত → চলমান → সম্পন্ন/সমাপ্ত
- কাস্টমার、সুযোগ、কোটেশনের সাথে লিংক
- কন্ট্রাক্ট বিস্তারিত: পণ্য/পরিমাণ/ইউনিট মূল্য/অঙ্ক
- স্বাক্ষর তারিখ、শুরু/শেষ তারিখ রেকর্ড
- কন্ট্রাক্ট শর্তাবলী কনটেন্ট (TEXT বড় ফিল্ড)
- দায়িত্বপ্রাপ্ত বরাদ্দ

## 9. অ্যাপ্রুভাল ওয়ার্কফ্লো মডিউল

### 9.1 ওয়ার্কফ্লো ডেফিনিশন
- ওয়ার্কফ্লো নাম、বিবরণ、প্রযোজ্য মডিউল
- মাল্টি-নোড অ্যাপ্রুভাল চেইন কনফিগ
- প্রতিটি নোডে অ্যাপ্রুভার/অ্যাপ্রুভাল রোল、অ্যাপ্রুভাল স্ট্র্যাটেজি (কাউন্টারসাইন/অর-সাইন) নির্ধারণ

### 9.2 অ্যাপ্রুভাল প্রসেস
- বিজনেস ডকুমেন্ট সাবমিট অনুমোদন → স্বয়ংক্রিয় অ্যাপ্রুভাল ইনস্ট্যান্স তৈরি
- পূর্বনির্ধারিত নোড অনুযায়ী ফ্লো, প্রতিটি নোডের অ্যাপ্রুভার পর্যায়ক্রমে হ্যান্ডল
- অ্যাপ্রুভাল অপারেশন: সাবমিট(বিজনেস মডিউল থেকে শুরু)、অনুমোদন、প্রত্যাখ্যান、প্রত্যাহার
- অ্যাপ্রুভাল ফলাফল কলব্যাক বিজনেস মডিউলে ডকুমেন্ট স্ট্যাটাস আপডেট
- আমার অ্যাপ্রুভাল লিস্ট: অপেক্ষমাণ/সম্পন্ন

### 9.3 অ্যাপ্রুভাল রেকর্ড
- সম্পূর্ণ অ্যাপ্রুভাল চেইন ট্র্যাকিং: প্রতিটি ধাপে অ্যাপ্রুভার、অপারেশন、মন্তব্য、সময় রেকর্ড
- অ্যাপ্রুভাল ইনস্ট্যান্স বিজনেস ডকুমেন্ট নম্বরের সাথে লিংক

- অ্যাটেনডেন্স কোয়েরি: এমপ্লয়ি+তারিখ রেঞ্জ অনুযায়ী কোয়েরি
- অ্যাটেনডেন্স রুল: কাজের সময়、দেরি/আগে-চলে-যাওয়া থ্রেশহোল্ড

### 12.4 লিভ ম্যানেজমেন্ট

- অ্যাপ্রুভাল প্রসেস: সাবমিট → ডিপার্টমেন্ট হেড অনুমোদন → পাস/প্রত্যাখ্যান

- বেতন প্রদান: মাস অনুযায়ী বেতন ফর্ম তৈরি, এমপ্লয়ির সাথে লিংক
- প্রদান স্ট্যাটাস: অপেক্ষমাণ প্রদান → প্রদানকৃত

## 13. উৎপাদন ম্যানুফ্যাকচারিং মডিউল

### 13.1 BOM (বিল অফ ম্যাটেরিয়াল)
- BOM ডেফিনিশন: প্যারেন্ট পণ্য、সাব-ম্যাটেরিয়াল、স্ট্যান্ডার্ড ব্যবহারের পরিমাণ、ইউনিট、প্রসেস
- BOM লেভেল: মাল্টি-লেভেল BOM এক্সপেনশন সাপোর্ট
- ভার্সন ম্যানেজমেন্ট: BOM রিভিশন রেকর্ড

### 13.2 প্রোডাকশন অর্ডার
- প্রোডাকশন অর্ডার CRUD: পণ্য、প্ল্যান পরিমাণ、প্ল্যান শুরু/শেষ তারিখ
- স্ট্যাটাস: উৎপাদন অপেক্ষমাণ → উৎপাদনে → উৎপাদন শেষ → বন্ধ
- শুরু/সমাপ্তি অপারেশন: প্রকৃত শুরু/শেষ সময় রেকর্ড
- প্রোডাকশন বিস্তারিত: ম্যাটেরিয়াল রিকুইজিশন তালিকা (BOM এক্সপেনশন ভিত্তিক)

### 13.3 প্রসেস রাউটিং
- প্রসেস রাউটিং ডেফিনিশন: পণ্য、প্রসেস সিকোয়েন্স、প্রতিটি প্রসেসের স্ট্যান্ডার্ড কাজের সময়
- BOM ও ওয়ার্কস্টেশনের সাথে লিংক

### 13.4 ওয়ার্কস্টেশন
- ওয়ার্কস্টেশন CRUD: নাম、কোড、টাইপ、ক্যাপাসিটি、স্ট্যাটাস
- প্রসেস রাউটিং প্রসেসের সাথে লিংক

### 13.5 MRP (ম্যাটেরিয়াল রিকোয়ারমেন্ট প্ল্যানিং)
- MRP প্ল্যান: সেলস অর্ডার/প্রোডাকশন প্ল্যান + BOM ভিত্তিতে ম্যাটেরিয়াল ডিমান্ড হিসাব
- স্বয়ংক্রিয় ক্রয় সুপারিশ (কাঁচামাল অপর্যাপ্ত হলে) এবং উৎপাদন সুপারিশ (আধা-সমাপ্ত পণ্য অপর্যাপ্ত হলে) তৈরি
- MRP বিস্তারিত: ম্যাটেরিয়াল、গ্রস ডিমান্ড、ইনভেন্টরি উপলব্ধ পরিমাণ、নেট ডিমান্ড、সুপারিশ অর্ডার পরিমাণ
- প্ল্যান স্ট্যাটাস: ড্রাফ্ট → তৈরি হয়েছে → ক্রয়/উৎপাদন সুপারিশ জারি হয়েছে

## 16. ইন্টারন্যাশনালাইজেশন (i18n)

### 16.1 ভাষা অটো ডিটেকশন
- রিকোয়েস্ট হেডার `Accept-Language` স্বয়ংক্রিয় শনাক্ত (zh-CN → চীনা, en → ইংরেজি)
- Locale মিডলওয়্যার গ্লোবাল মিডলওয়্যার চেইনের প্রথম অবস্থানে এক্সিকিউট হয়
- ফলব্যাক চেইন: বর্তমান ভাষা → কনফিগার করা fallback_locale → মূল key রিটার্ন

### 16.2 ট্রান্সলেশন ফাইল
- ডিরেক্টরি: `resource/translations/{locale}/`
- সাধারণ মেসেজ: `common.php` (৪১টি key: সফল/ব্যর্থ/তৈরি/আপডেট/ডিলিট/ভ্যালিডেশন ইত্যাদি)
- মডিউল নাম: `modules.php` (৬৯টি key: পণ্য/ক্রয়/বিক্রয়/ইনভেন্টরি/ফাইন্যান্স/CRM ইত্যাদি)
- ভ্যালিডেশন রুল: `validation.php` (১১টি রুল + ১০টি ফিল্ড লেবেল)

### 16.3 ব্যবহারের পদ্ধতি
- কন্ট্রোলারে: `$this->trans('created')`
- গ্লোবাল ফাংশন: `__('modules.product')`、`__m('finance')`
- মডিউল নাম: `__('modules.product')` → পণ্য / Product
