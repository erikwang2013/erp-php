## ثالثًا: تقييم الحماية الأمنية

### 3.1 الإجراءات الأمنية المنفذة ✅

```
طبقة الشبكة   → Nginx: تحديد معدل/حد جسم الطلب/حد الاتصالات/رؤوس أمنية/منع الملفات الحساسة
طبقة الوسائط → SecurityFilter: XSS/SQLi/اجتياز المسار/حقن الأوامر/كشف الملفات الخبيثة/CSRF(تحقق Origin)
         → RateLimit: نافذة منزلقة ذرية Lua (الافتراضي 60 مرة/دقيقة، تسجيل الدخول 10، التسجيل 5)
         → AdminAuth: مصادقة JWT + قائمة سوداء + تقييد الجلسات (بحد أقصى 3 Tokens)
         → AdminPermission: تفويض RBAC بدقة method.path (تخزين مؤقت 60s)
         → Cors: CSP/X-Frame/X-Content-Type/Referrer-Policy/Permissions-Policy
         → OperationLog: تصفية الحقول الحساسة + try-catch
طبقة التطبيق → EncryptionService: تشفير نقل AES-256-CBC + إخفاء phone/email
         → تأكيد كلمة المرور الثانية للعمليات الحساسة
طبقة البيانات → Encryptable: تشفير وفك تلقائي لحقول PII (email/phone/id_card)
         → قفل صف متشائم (lockForUpdate) لمنع البيع الزائد المتزامن
         → خوارزمية تكلفة المتوسط المتحرك المرجح (دقة بمستوى المحاسبة)
المصادقة     → تجزئة bcrypt لكلمات المرور + قفل الحساب (5 فشلات/15 دقيقة)
نظام المعرفات → معرّفات موزعة Snowflake + إخفاء خارجي Hashids
الامتثال     → security.txt (RFC 9116)
```

### 3.3 المشكلات الأمنية

#### ❌ P0-1 — المفاتيح الافتراضية غير معدلة

المفاتيح في `.env` ما زالت بالقيم الافتراضية، يجب استبدالها في الإنتاج:

| متغير المفتاح | القيمة الافتراضية |
|----------|--------|
| `JWT_SECRET_KEY` | `open-admin-jwt-secret-change-in-production` |
| `ENCRYPTION_KEY` | `open-admin-api-encryption-key32b` |
| `ENCRYPTABLE_KEY` | `open-admin-db-encryption-key-32b` |
| `HASHIDS_SALT` | `open-admin-hashids-salt-2026` |

**الضرر**: يستطيع المهاجم تزوير JWT Token وفك تشفير بيانات API/قاعدة البيانات.  
**الإصلاح**: `openssl rand -hex 32` لتوليد مفاتيح عشوائية بطول 64 حرفًا.

#### ❌ P0-2 — composer.lock متجاهَل في .gitignore

**المشكلة**: البيئات المختلفة تثبت إصدارات مختلفة من التبعيات، وعدم تطابق بين CI والإنتاج. توصي Composer رسميًا بإرسال ملف lock.  
**الإصلاح**: إزالة `composer.lock` من `.gitignore` وإرساله.

#### ⚠️ P1-1 — CSP يستخدم `unsafe-inline`

```php
// app/middleware/Cors.php:36
'script-src \'self\' \'unsafe-inline\''
'style-src \'self\' \'unsafe-inline\''
```

السماح بتنفيذ البرامج النصية/الأنماط المضمنة يضعف حماية XSS. يُنصح بالتبديل إلى CSP nonce.

#### ⚠️ P1-2 — الجلسة تستخدم مشغل الملفات

```php
// config/session.php
'type' => 'file'       // تنافس أقفال في العمليات المتعددة
'secure' => false      // يجب تفعيله في بيئة HTTPS
```

يُنصح بالتبديل إلى Redis في الإنتاج، وتفعيل ملف تعريف ارتباط آمن عبر `SESSION_SECURE=true`.

#### ⚠️ P1-3 — غياب .dockerignore

حاليًا `COPY . .` يحزم `.env` و`runtime/` و`.git/` وغيرها داخل الصورة. يجب إنشاء `.dockerignore`.

#### ⚠️ P2 — CORS `Allow-Origin: *` + تعطيل المصادقة الأمنية لـ ES

- حرف البدل في CORS يسمح بالوصول من أي مصدر
- في `docker-compose.yml` قيمة `xpack.security.enabled: "false"`
