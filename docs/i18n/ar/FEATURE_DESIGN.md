## 1. نظرة عامة على النظام

نظام إدارة موارد المؤسسات المفتوح (open-erp) هو نظام تخطيط موارد مؤسسي متكامل مبني على webman v2 + Flutter، ويغطي أربعة عشر مجالًا تجاريًا رئيسيًا: إدارة النظام، المشتريات والمبيعات والمخزون، المالية، CRM، سير عمل الموافقات، إشعارات الرسائل، إدارة المشاريع، الموارد البشرية، التصنيع، والتقارير المخصصة.

### 1.1 أهداف التصميم
- نشر أحادي، تصميم معياري
- جميع المعرفات تُولَّد عبر snowflake + تشفير نقل hashids
- تشفير مزدوج للبيانات الحساسة (طبقة النقل AES-256-CBC + طبقة التخزين AES-128-ECB)
- احتساب تكلفة المتوسط المتحرك المرجح
- ترابط تلقائي عبر الوحدات (الشراء←المستحقات، المبيعات←المستحقات، المقبوضات والمدفوعات←التقييد)

### 1.2 القيود التقنية
- PHP 8.3+, MySQL 8.0+, Redis 7, Elasticsearch 8
- بادئة الجداول erp_، المفتاح الأساسي BIGINT غير تلقائي التزايد
- إصدار API يتحكم عبر رأس الطلب API-Version
- مصادقة JWT + صلاحيات RBAC
- الدوال العامة بدون بادئة \

## 2. وحدة إدارة النظام

### 2.1 إدارة المستخدمين
- CRUD للمسؤولين، دعم التمكين/التعطيل الجماعي والحذف الناعم الجماعي
- استيراد جماعي عبر Excel (تحقق سطرًا بسطر + تقرير أخطاء)
- كلمات المرور bcrypt، وتغيير كلمة المرور يتطلب تأكيد كلمة المرور الأصلية
- عمليات الحذف تتطلب تأكيدًا ثانويًا بكلمة مرور المستخدم الحالي
- تخزين مشفر لأرقام الهاتف/البريد الإلكتروني/رقم الهوية، مع إخفاء تلقائي في القوائم

### 2.2 صلاحيات الأدوار (RBAC)
- CRUD للأدوار، معرّف فريد slug
- شجرة الصلاحيات (parent_id مرجع ذاتي بمستويات غير محدودة)، الأنواع: قائمة/زر/API
- تنسيق معرّف الصلاحية: {method}.{path} (مثل get.admin/product، post.admin/user/batch/destroy)
- علاقة متعدد-لمتعدد بين الدور والصلاحية
- المدير الفائق (super_admin) يتجاوز جميع فحوصات الصلاحيات
- وسيط AdminPermission يخزّن الصلاحيات في Redis (TTL=60s)

### 2.3 إعدادات النظام
- تخزين أزواج مفتاح-قيمة، دعم المجموعات
- أنواع القيم: string|int|bool|json|array

### 2.4 تدقيق العمليات
- تسجيل تلقائي لجميع عمليات POST/PUT/DELETE
- التسجيل: منفذ العملية، الإجراء، الطريقة، المسار، IP، المعاملات (مع إخفاء الحقول الحساسة)، الوقت
- كشف تلقائي لمصدر 8 منصات (Web/Flutter/HarmonyOS/API وغيرها)
- يدعم الاستعلام فقط، لا يمكن الحذف/التعديل

### 2.5 الحماية الأمنية
- دفاع متعمق من 18 طبقة (انظر التفاصيل في SECURITY.md)
- SecurityFilter: تقييد طرق HTTP + اعتراض XSS/حقن SQL/اجتياز المسارات/حقن الأوامر/CSRF
- RateLimit: نافذة منزلقة لتحديد المعدل عبر Redis (Lua ذري، 60 مرة/دقيقة)
- كابتشا النقر (إجبارية لتسجيل الدخول/التسجيل)
- قفل الحساب: 5 محاولات فاشلة تقفل 15 دقيقة
- تقييد الجلسات المتزامنة: 3 رموز كحد أقصى لنفس المستخدم
- رؤوس CSP، و security.txt (RFC 9116)
- تحقق ثانوي عشوائي للعمليات الحساسة عبر poster-php

## 3. المنتجات والبيانات الأساسية

### 3.1 إدارة المنتجات
- ملف المنتج: الكود (فريد)، الاسم، الباركود، المواصفات، الوحدة الأساسية، الصورة، الوصف
- SKU متعدد المواصفات: عدة SKU تحت نفس المنتج، لكل منها كود وباركود وخصائص مواصفات مستقلة (JSON)
- تحويل وحدات متعددة: الوحدة الأساسية ↔ الوحدات المساعدة، معدل التحويل
- استراتيجية الأسعار: سعر الشراء، سعر الجملة، سعر التجزئة، سعر مستوى العميل
- تصنيفات المنتجات: بنية شجرية بمستويات غير محدودة، دعم سحب وإفلات للترتيب
- إدارة العلامات التجارية: اسم العلامة التجارية، الشعار، الوصف

### 3.2 المستودعات والمواقع
- إدارة مستودعات متعددة (الاسم، الكود، العنوان، المسؤول)
- مواقع متعددة لكل مستودع (الكود فريد داخل المستودع)
- تخزين مشفر لرقم هاتف المستودع

### 3.3 الموردون/العملاء
- ملف المورد: الكود، الاسم، جهة الاتصال، الهاتف/البريد الإلكتروني (مشفر)، العنوان، المعلومات البنكية
- ملف العميل: الكود، الاسم، مستوى العميل، حد الائتمان
- مستوى العميل: الاسم، معدل الخصم الافتراضي
- دعم البحث النصي الكامل عبر ES للموردين/العملاء

## 4. وحدة المشتريات

### 4.1 تدفق المشتريات
طلب ← موافقة ← أمر ← استلام ← تسوية

### 4.2 طلب الشراء
- تقديم القسم/الموظف لاحتياجات الشراء
- الحالة: بانتظار الموافقة ← تمت الموافقة/مرفوض ← تم تحويله إلى أمر
- دعم عمليات المعتمدين

### 4.3 أمر الشراء
- ربط المورد، تفاصيل المنتجات (الكمية، سعر الوحدة، المبلغ)
- الحالة: بانتظار المراجعة ← تمت المراجعة ← استلام جزئي ← تم الاستلام ← تم الإلغاء
- يمكن إنشاؤه بناءً على طلب الشراء، أو مباشرة

### 4.4 استلام الشراء (ترابط عبر الوحدات)
- الاستلام حسب الأمر، دعم الاستلام بالدفعات
- يفعّل تلقائيًا عند الاستلام:
  1. InventoryService.stockIn() ← تحديث المخزون الفوري + إعادة احتساب المتوسط المتحرك المرجح
  2. FinanceService.createAp() ← توليد سجل مستحق الدفع
  3. تحديث الكمية المستلمة وحالة الأمر
- دعم تسجيل الموقع ورقم الدفعة

### 4.5 إرجاع الشراء
- إرجاع للمورد، توليد إلغاء خروج من المخزون
- ربط بسند الاستلام

### 4.6 تسوية الموردين
- التجميع حسب المورد: مبلغ الشراء، المدفوع، المستحق
- حالة التسوية: غير مسوّى/مسوّى جزئيًا/مسوّى

## 5. وحدة المبيعات

### 5.1 تدفق المبيعات
عرض سعر ← أمر ← شحن ← تسوية

### 5.2 عرض السعر
- عرض السعر للعميل، دعم التحويل إلى أمر مبيعات
- الحالة: مسودة ← تمت التسعيرة ← تم التحويل إلى أمر ← منتهي

### 5.3 أمر المبيعات
- ربط العميل، تفاصيل المنتجات (الكمية، سعر الوحدة، الخصم)
- الحالة: بانتظار المراجعة ← تمت المراجعة ← شحن جزئي ← تم الشحن ← تم الإلغاء
- دعم مبالغ الخصم

### 5.4 شحن المبيعات (ترابط عبر الوحدات)
- الشحن حسب الأمر، دعم الشحن بالدفعات
- يفعّل تلقائيًا عند الشحن:
  1. InventoryService.stockOut() ← خصم المخزون (باستخدام تكلفة المتوسط المتحرك المرجح)
  2. FinanceService.createAr() ← توليد سجل مستحق القبض
  3. تحديث الكمية المشحونة وحالة الأمر

### 5.5 إرجاع المبيعات
- إرجاع من العميل، توليد إلغاء إدخال للمخزون

### 5.6 تسوية العملاء والربح الإجمالي
- التجميع حسب العميل: مبلغ المبيعات، المقبوض، المستحق
- الربح الإجمالي للمبيعات: يُحتسب حسب أبعاد الأمر/المنتج/العميل

## 6. وحدة المخزون

### 6.1 إدارة المخزون
- المخزون الفوري: دقة رباعية الأبعاد مستودع+موقع+دفعة+SKU
- سجلات الإدخال والإخراج: تسجيل موحّد لجميع تغييرات المخزون (الاتجاه، الكمية، سعر التكلفة، رقم مستند المصدر)
- تتبع الدفعات: تاريخ الإنتاج، تاريخ الانتهاء
- تتبع الأرقام التسلسلية: أرقام تسلسلية فريدة، تسجيل الحالة عند الإدخال والإخراج (في المخزون/تم الإخراج)

### 6.2 احتساب التكلفة
- طريقة المتوسط المتحرك المرجح
- الصيغة: المتوسط الجديد = (إجمالي قيمة المخزون الأصلي + إجمالي قيمة الإدخال الحالي) / (كمية المخزون الأصلي + كمية الإدخال الحالي)
- إعادة احتساب تلقائية عند كل إدخال، والإخراج يُحتسب بالمتوسط الحالي
- سلسلة سجلات تكلفة كاملة (المتوسط قبل التغيير ← المتوسط بعد التغيير)

### 6.3 تحويل المخزون
- التحويل بين المستودعات/المواقع
- الحالة: بانتظار التحويل ← تم الإخراج ← تم الإدخال ← مكتمل
- توليد تلقائي لسجلات إدخال/إخراج التحويل

### 6.4 إدارة الجرد
- جرد مخطط (حسب المستودع/التصنيف) + جرد ديناميكي (حسب SKU)
- تسجيل الكمية الدفترية مقابل الكمية الفعلية
- فروق الجرد تولّد تلقائيًا سجلات فائض/عجز المخزون

### 6.5 تنبيهات المخزون
- ضبط الحدين الأدنى والأعلى حسب SKU+المستودع
- تسجيل تلقائي لسجل التنبيه عند الانخفاض عن الحد الأدنى/الارتفاع فوق الحد الأعلى

## 7. وحدة المالية

### 7.1 الحسابات المحاسبية
- شجرة الحسابات: خمس فئات رئيسية أصول/خصوم/حقوق/إيرادات/مصاريف
- كود الحساب فريد
- اتجاه الرصيد: مدين/دائن

### 7.2 سندات القيد
- رقم السند، التاريخ، الملخص
- القيد المزدوج: كل قيد يشمل مبلغ مدين ومبلغ دائن (المدين = الدائن إلزاميًا)
- الحالة: مسودة ← تمت المراجعة

### 7.3 الدفتر العام
- التجميع حسب الحساب المحاسبي + الفترة المحاسبية (سنة/شهر)
- التسجيل: رصيد مدين/دائن افتتاحي، حركة مدين/دائن للفترة، رصيد مدين/دائن ختامي
- الرصيد الختامي = الرصيد الافتتاحي ± حركة الفترة (حسب اتجاه رصيد الحساب)
- تحديث تلقائي بعد مراجعة السند
- دعم الفلترة حسب السنة/الشهر/الحساب

### 7.4 الدفتر الفرعي
- تسجيل كل قيد من سندات الحساب المحدد سطرًا بسطر
- يشمل: رقم السند، الاتجاه (مدين/دائن)، المبلغ، الرصيد، الملخص، التاريخ
- دعم الاستعلام حسب الحساب + نطاق التاريخ
- مزامنة التحديث مع قيود السندات

### 7.5 الميزانية العمومية
- التوليد حسب الفترة المحاسبية (شهري/سنوي)
- تجميع تلقائي لأرصدة الدفتر العام:
  - حسابات الأصول (1) ← إجمالي الأصول = الأصول المتداولة + الأصول غير المتداولة
  - حسابات الخصوم (2) ← إجمالي الخصوم = الخصوم المتداولة + الخصوم غير المتداولة
  - حسابات الحقوق (3) ← حقوق المالكين
  - المعادلة: الأصول = الخصوم + حقوق المالكين
- دعم حفظ اللقطة (بيانات JSON كاملة)
- عند عدم وجود لقطة يُولَّد تلقائيًا من الدفتر العام

### 7.6 قائمة التدفقات النقدية
- التوليد حسب الفترة المحاسبية (شهري/سنوي)
- ثلاثة تصنيفات:
  - التدفقات النقدية من الأنشطة التشغيلية (مقبوضات المبيعات - مدفوعات المشتريات - مصاريف)
  - التدفقات النقدية من الأنشطة الاستثمارية
  - التدفقات النقدية من الأنشطة التمويلية
- الرصيد النقدي الافتتاحي/الختامي = إجمالي الأرصدة الافتتاحية/الختامية لجميع الحسابات البنكية
- توليد تلقائي بتجميع دفتر اليومية النقدية والبنكية
- دعم حفظ اللقطة (بيانات JSON كاملة)

### 7.7 المستحقات والمستحقات
- توليد تلقائي من استلام الشراء/شحن المبيعات
- مستحق القبض: النوع=مستحق قبض، مرتبط بالعميل، المصدر=سند شحن المبيعات
- مستحق الدفع: النوع=مستحق دفع، مرتبط بالمورد، المصدر=سند استلام الشراء
- الحالة: غير مقيّد ← مقيّد جزئيًا ← مقيّد
- لا يمكن توليد مستندات المصدر نفسها بشكل مكرر (حماية التكافؤ)

### 7.8 إدارة المقبوضات
- حسابات متعددة (نقدي/بنكي/WeChat/Alipay)
- تحديث تلقائي لرصيد الحساب البنكي ودفتر اليومية النقدية بعد المراجعة
- التقييد: اختيار سجلات المستحقات، وإدخال مبلغ التقييد (لا يتجاوز الرصيد غير المقيّد)
- انتقال تلقائي لحالة التقييد الجزئي

### 7.9 إدارة المدفوعات
- نفس منطق المقبوضات، بالاتجاه المعاكس
- تقييد سجلات المستحقات

### 7.10 دفتر اليومية النقدية والبنكية
- تسجيل كل إيراد ومصروف حسب الحساب + التاريخ
- تسجيل الرصيد بعد التغيير
- تحديث فوري لرصيد الحساب البنكي

### 7.11 تسديد المصاريف
- التدفق: تقديم ← موافقة ← تحويل
- ربط بحساب المصاريف
- توليد تلقائي لسند دفع + إدخال دفتر اليومية بعد التحويل

### 7.12 بيان الأرباح
- التجميع الشهري: الإيرادات التشغيلية، تكلفة التشغيل، المصاريف، الربح
- تخزين لقطة البيانات (فريد حسب year+month)

### 7.13 إهلاك الأصول الثابتة
- إدارة دورة حياة الأصول الكاملة: اقتناء ← استخدام ← إهلاك ← تصرف
- طريقة الإهلاك: القسط الثابت ((القيمة الأصلية - القيمة المتبقية) / عدد أشهر الاستخدام)
- استحقاق شهري للإهلاك، توليد تلقائي لسجلات الإهلاك
- التسجيل: القيمة الأصلية، القيمة المتبقية، العمر الافتراضي، الإهلاك الشهري، الإهلاك المتراكم، القيمة الصافية

### 7.14 إدارة الضرائب
- دعم أنواع ضرائب متعددة: ضريبة القيمة المضافة/ضريبة دخل الشركات/ضريبة الدخل الشخصي/الطابع
- إعداد مرن لمعدلات الضرائب
- الربط مع مستندات الشراء/البيع، تسجيل مبلغ الضريبة تلقائيًا

### 7.15 العملات المتعددة
- إدارة العملات: CNY/USD/EUR/JPY وغيرها
- علامة العملة المحلية
- إدارة أسعار الصرف حسب تاريخ السريان
- دعم تحويل العملات الأجنبية

### 7.16 إدارة الميزانيات
- إعداد الميزانية السنوية: الإعداد حسب مركز التكلفة + الحساب + الشهر
- تحليل مقارنة الميزانية مقابل الفعلي
- احتساب نسبة التنفيذ + تحليل الفروق
- الحالة: مسودة ← تمت الموافقة ← قيد التنفيذ ← مغلقة

### 7.17 مراكز التكلفة/الأرباح
- بنية هرمية شجرية
- تجميع التكاليف + توزيع المصاريف
- محاسبة مستقلة لمراكز الأرباح

## 8. وحدة CRM

### 8.1 إدارة العملاء
- ملف العميل مرتبط بعميل البيانات الأساسية
- جهات اتصال متعددة تحت العميل (مع تمييز جهة الاتصال الأساسية)
- تخزين مشفر لهاتف/بريد جهة الاتصال

### 8.2 سجلات المتابعة
- طرق المتابعة: هاتف/زيارة/بريد/رسالة/أخرى
- تسجيل محتوى المتابعة، خطة المتابعة التالية، وقت المتابعة التالية
- ربط العميل وجهة الاتصال والفرصة

### 8.3 الحملات التسويقية
- دورة حياة الحملة الكاملة: مخطط ← جارٍ ← مكتمل ← ملغي
- قنوات متعددة: بريد/رسائل نصية/هاتف/فعاليات/تواصل اجتماعي
- تتبع العملاء المشاركين، إحصائيات معدل التحويل
- مقارنة الميزانية مقابل الإنفاق الفعلي

### 8.4 تذاكر الخدمة
- إدارة التذاكر: بانتظار المعالجة ← قيد المعالجة ← تم الحل ← مغلقة
- الأولوية: منخفضة/متوسطة/عالية/عاجلة
- التصنيف: دعم فني/شكوى/استفسار/استبدال وإرجاع/أخرى
- تعيين المعالج + الردود (عامة/مذكرة داخلية)
- إحصائيات معدل الحل

### 8.5 تقارير تحليل العملاء
- 6 مؤشرات أساسية: عملاء جدد/عملاء نشطون/معدل الاحتفاظ/متوسط قيمة الطلب/CLV/معدل حل التذاكر
- توليد تلقائي للتقارير (لقطة بيانات JSON)
- دعم شهري/ربع سنوي/سنوي

### 8.6 قمع المبيعات
- إعداد المراحل: اتصال أولي (10%) ← تأكيد الحاجة (30%) ← خطة العرض السعري (50%) ← تفاوض تجاري (70%) ← إتمام (100%) ← خسارة الصفقة (0%)
- الفرص: العميل، المرحلة الحالية، المبلغ المقدّر، احتمال الإتمام، تاريخ الإتمام المتوقع، المسؤول
- حالة الفرصة: خسارة/قيد التقدم/تمت
- تتبع انتقال المراحل

### 8.7 بركة العملاء العامة
- بركة العملاء العامة: العملاء غير المخصصين أو غير المتابعين خلال المهلة يدخلون البركة تلقائيًا
- قواعد الاسترداد: ضبط أيام الاسترداد التلقائي حسب مستوى العميل عند عدم المتابعة
- حد أقصى لعدد الاستلام لكل شخص، لمنع ركود موارد العملاء
- عمليات الاستلام/التحرير/الاسترداد جميعها مسجلة بالتدفق
- تعزيز نشاط فريق المبيعات، وتجنب ركود العملاء

### 8.8 إدارة عروض أسعار CRM
- تدفق عروض أسعار داخلي في CRM مستقل عن وحدة المبيعات
- الحالة: مسودة ← تم الإرسال ← تأكيد العميل ← تم التحويل إلى عقد ← منتهي
- دعم فترة صلاحية العرض
- دعم التحويل المباشر إلى عقد (`to-contract`)
- ربط العميل والفرصة

### 8.9 إدارة العقود
- دورة حياة العقد الكاملة: مسودة ← بانتظار الموافقة ← تمت الموافقة ← قيد التنفيذ ← مكتمل/منتهي
- ربط العميل والفرصة وعرض السعر
- تفاصيل العقد: المنتج/الكمية/سعر الوحدة/المبلغ
- تسجيل تاريخ التوقيع وتاريخي البدء/الانتهاء
- محتوى شروط العقد (حقل نص كبير TEXT)
- تعيين المسؤول

## 9. وحدة سير عمل الموافقات

### 9.1 تعريف سير العمل
- اسم سير العمل، الوصف، الوحدة المنطبقة
- إعداد سلسلة موافقة متعددة العقد
- كل عقد يحدد المعتمد/دور الموافقة واستراتيجية الموافقة (توقيع جماعي/توقيع أي)

### 9.2 تدفق الموافقة
- تقديم مستند الأعمال للموافقة ← إنشاء تلقائي لحالة الموافقة
- التدفق وفق العقد المحددة مسبقًا، ويعالج معتمد كل عقد بالتسلسل
- عمليات الموافقة: تقديم (يبدأ من وحدة الأعمال)، موافقة، رفض، سحب
- استدعاء نتيجة الموافقة لوحدة الأعمال لتحديث حالة المستند
- قائمة موافقاتي: بانتظار الموافقة/تمت الموافقة

### 9.3 سجلات الموافقة
- تتبع كامل لسلسلة الموافقة: كل خطوة تسجل المعتمد والعملية والرأي والوقت
- ربط حالة الموافقة برقم مستند الأعمال

## 11. وحدة إدارة المشاريع

### 11.1 إدارة المشاريع
- CRUD للمشاريع: الاسم، الوصف، الحالة، تاريخا البدء والانتهاء، المسؤول
- حالة المشروع: قيد التخطيط ← قيد التنفيذ ← مكتمل ← مؤرشف
- إدارة أعضاء المشروع: إضافة/إزالة أعضاء المشروع

### 11.2 إدارة المهام
- CRUD للمهام: العنوان، الوصف، الأولوية، الحالة، تاريخ الاستحقاق
- ربط المشروع، دعم المهام الرئيسية والفرعية
- حالة المهمة: بانتظار البدء ← قيد التنفيذ ← مكتملة ← مغلقة
- توزيع المهام: تعيين المسؤول

### 11.3 سجلات ساعات العمل
- إدخال ساعات العمل حسب المهمة: التاريخ، المدة، الوصف
- تجميع إحصائيات ساعات العمل حسب المشروع

## 12. وحدة الموارد البشرية

### 12.1 الهيكل التنظيمي
- إدارة الأقسام: بنية شجرية، اسم القسم، الكود، المسؤول، القسم الأب
- إدارة المناصب: اسم المنصب، الكود، القسم التابع، الحالة

### 12.2 إدارة الموظفين
- ملف الموظف: الكود، الاسم، الجنس، رقم الهاتف (مشفر)، البريد الإلكتروني (مشفر)، تاريخ الالتحاق، القسم، المنصب
- الحالة: على رأس العمل/مغادر
- ربط بحساب مستخدم النظام

### 12.3 إدارة الحضور
- البصمة: بصمة الدخول وبصمة الخروج، تسجيل الوقت
- استعلام الحضور: حسب الموظف + نطاق التاريخ
- قواعد الحضور: ساعات العمل، عتبات التأخر/الانصراف المبكر

### 12.4 إدارة الإجازات
- CRUD للإجازات: النوع (عارضة/مرضية/سنوية وغيرها)، فترة البدء والانتهاء، السبب
- تدفق الموافقة: تقديم ← موافقة رئيس القسم ← قبول/رفض
- الحالة: بانتظار الموافقة ← تمت ← مرفوضة

### 12.5 إدارة الرواتب
- بنود الرواتب: الراتب الأساسي/الأداء/البدلات/بنود الخصم وغيرها، طريقة الاحتساب
- صرف الرواتب: توليد كشف راتب شهري، ربط بالموظف
- حالة الصرف: بانتظار الصرف ← تم الصرف

## 13. وحدة التصنيع

### 13.1 BOM (قائمة المواد)
- تعريف BOM: المنتج الأب، المواد الفرعية، الاستخدام القياسي، الوحدة، العملية
- مستويات BOM: دعم التوسع متعدد المستويات لـ BOM
- إدارة الإصدارات: سجل مراجعات BOM

### 13.2 أوامر الإنتاج
- CRUD لأوامر الإنتاج: المنتج، الكمية المخططة، تاريخا البدء/الانتهاء المخططان
- الحالة: بانتظار الإنتاج ← قيد الإنتاج ← مكتمل ← مغلق
- عمليتا البدء/الاكتمال: تسجيل وقت البدء/الانتهاء الفعلي
- تفاصيل الإنتاج: قائمة صرف المواد (بناءً على توسيع BOM)

### 13.3 المسارات
- تعريف المسارات: المنتج، تسلسل العمليات، الوقت القياسي لكل عملية
- ربط BOM ومحطات العمل

### 13.4 محطات العمل
- CRUD لمحطات العمل: الاسم، الكود، النوع، الطاقة الإنتاجية، الحالة
- ربط عمليات المسارات

### 13.5 MRP (تخطيط متطلبات المواد)
- خطة MRP: احتساب متطلبات المواد بناءً على أوامر المبيعات/خطط الإنتاج + BOM
- توليد تلقائي لاقتراحات الشراء (عند نقص المواد الخام) واقتراحات الإنتاج (عند نقص المنتجات نصف المصنعة)
- تفاصيل MRP: المادة، إجمالي الطلب، الكمية المتاحة من المخزون، الصافي المطلوب، كمية الطلب المقترحة
- حالة الخطة: مسودة ← تم التوليد ← تم إصدار اقتراحات الشراء/الإنتاج

### 14.1 تعريف التقارير

### 14.2 تنفيذ التقارير

- عرض النتائج: جدول أو رسم بياني (عبر عرض الواجهة)
- دعم التصدير

### 14.3 الجدولة الدورية
- مهام التقارير الدورية: تحديد التقرير، وتكرار التنفيذ (cron)، والمستلمين
- حالة الجدولة: مفعّلة/معطلة
- استعلام سجل التنفيذ

## 16. التدويل (i18n)

### 16.1 الكشف التلقائي للغة
- التعرف التلقائي عبر رأس الطلب `Accept-Language` (zh-CN ← الصينية، en ← الإنجليزية)
- وسيط Locale يُنفَّذ أولًا في سلسلة الوسائط العامة
- سلسلة التراجع: اللغة الحالية ← fallback_locale المكوّنة ← إرجاع المفتاح الأصلي

### 16.2 ملفات الترجمة
- الدليل: `resource/translations/{locale}/`
- الرسائل العامة: `common.php` (41 مفتاحًا: نجاح/فشل/إنشاء/تحديث/حذف/تحقق وغيرها)
- أسماء الوحدات: `modules.php` (69 مفتاحًا: منتجات/مشتريات/مبيعات/مخزون/مالية/CRM وغيرها)
- قواعد التحقق: `validation.php` (11 قاعدة + 10 تسميات حقول)

### 16.3 طرق الاستخدام
- داخل وحدات التحكم: `$this->trans('created')`
- الدوال العامة: `__('modules.product')`، `__m('finance')`
- أسماء الوحدات: `__('modules.product')` ← المنتج / Product
