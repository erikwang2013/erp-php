## 1. نظرة عامة

فوق قاعدة إدارة النظام الحالية في `service/`، نتوسع في ثلاث مجالات أعمال: المشتريات والمبيعات والمخزون (进销存)، والمالية، وCRM، لبناء نظام ERP كامل.
تُنشر جميع الأكواد بنشر أحادي تحت `service/app/`، وتُقسم الوحدات حسب الدلائل طبقيًا.

### 1.1 التخطيط المرحلي

| المرحلة | الوحدات | الوصف |
|------|------|------|
| المرحلة 1 | البيانات الأساسية للمنتج + المشتريات + المبيعات + المخزون + المالية + CRM | حلقة الأعمال الأساسية |
| المرحلة 2 | إدارة التصنيع + إدارة المشاريع | توسعات لاحقة |

### 1.2 الحزمة التقنية (استمرار الحالية)

- PHP 8.3+, webman v2, MySQL 8.0+
- المفتاح الأساسي BIGINT يولَّد عبر snowflake-php
- تشفير/فك تشفير معرفات طبقة API عبر hashids
- مصادقة JWT وتشفير البيانات الحساسة كلها عبر سلسلة حزم erikwang2013/*
- بادئة الجداول `erp_`، حذف ناعم، الدوال العامة بدون `\`

```

├── middleware/                # الوسائط العامة (موجودة 7)

│   ├── product/               # المنتج والبيانات الأساسية
│   ├── purchase/              # المشتريات
│   ├── sales/                 # المبيعات
│   ├── inventory/             # المخزون
│   ├── finance/               # المالية
│   └── crm/                   # CRM
├── controller/                # وحدات تحكم الأعمال
│   ├── product/               # البيانات الأساسية للمنتج
│   ├── purchase/              # المشتريات
│   ├── sales/                 # المبيعات
│   ├── inventory/             # المخزون
│   ├── finance/               # المالية
│   └── crm/                   # CRM
├── queue/                     # مهام قوائم الانتظار (موجودة + قوائم أعمال)
```

### 2.1 مسؤوليات الطبقات

| الطبقة | موقع الملف | المسؤولية |
|----|----------|------|
| Controller | `app/controller/{module}/` | التحقق من المعاملات، تنسيق الاستجابات، استدعاء Service |
| Service | `app/service/{module}/` | منطق الأعمال، الربط بين الوحدات، إدارة المعاملات |
| Model | `app/model/` | نماذج البيانات، العلاقات، نطاقات الاستعلام، trait encryptable |

## 3. قائمة وظائف الوحدات

### 3.1 المنتج والبيانات الأساسية

| الوظيفة | الوصف |
|------|------|
| ملف المنتج | اسم المنتج، الرمز، الباركود، التصنيف (شجري)، العلامة التجارية، سمات المواصفات |
| SKU متعدد المواصفات | نفس المنتج بمواصفات متعددة، لكل منها SKU وباركود وسعر مستقل |
| تحويل وحدات متعدد | معدل تحويل الوحدة الأساسية ↔ الوحدة المساعدة |
| استراتيجيات الأسعار | سعر الشراء، سعر الجملة، سعر التجزئة، سعر مستوى العميل |
| إدارة التصنيفات | شجرة تصنيفات غير محدودة المستويات، تدعم السحب للترتيب |
| إدارة العلامات التجارية | CRUD للعلامات التجارية |
| إدارة المستودعات | مستودعات متعددة، لكل مستودع مواقع متعددة |
| إدارة المواقع | مواقع التخزين تحت المستودع، الرمز فريد |
| ملف الموردين | الاسم، جهة الاتصال، الهاتف، العنوان، الحساب البنكي، معدل الضريبة |
| ملف العملاء | الاسم، جهة الاتصال، الهاتف، العنوان، مستوى العميل، حد الائتمان |

### 3.2 وحدة المشتريات

| الوظيفة | الوصف |
|------|------|
| طلب الشراء | تقديم الأقسام/الأفراد لاحتياجات الشراء، يدعم سير الموافقات |
| أمر الشراء | بناءً على الطلب أو الإنشاء المباشر، يربط المورد والمنتج والكمية والسعر الوحدوي |
| استلام الشراء | الاستلام حسب الأمر، توليد مستند إدخال، يدعم الاستلام على دفعات |
| إرجاع الشراء | الإرجاع إلى المورد، توليد مستند إخراج للقيود |
| تسوية المورد | تجميع مبلغ الشراء والمدفوع والمستحق حسب المورد + الفترة الزمنية |
| تسوية الشراء | تقييد استلام الشراء مع الدفعات |

### 3.3 وحدة المبيعات

| الوظيفة | الوصف |
|------|------|
| عرض الأسعار | عرض أسعار للعميل، يدعم التحويل إلى أمر مبيعات |
| أمر المبيعات | طلب العميل، يربط المنتج والكمية والسعر الوحدوي والخصم |
| شحن المبيعات | الشحن حسب الأمر، توليد مستند إخراج، يدعم الشحن على دفعات |
| إرجاع المبيعات | إرجاع العميل، توليد مستند إدخال للقيود |
| تسوية العميل | تجميع مبلغ المبيعات والمقبوض والمستحق حسب العميل + الفترة الزمنية |
| تسوية المبيعات | تقييد شحن المبيعات مع المقبوضات |
| هامش المبيعات | حساب هامش الربح حسب بُعد الأمر/المنتج/العميل |

### 3.4 وحدة المخزون

| الوظيفة | الوصف |
|------|------|
| المخزون الفوري | كمية المخزون ببعد المستودع+الموقع+الدفعة+SKU |
| تتبع الدفعات | تاريخ الإنتاج، تاريخ الانتهاء، رقم الدفعة |
| تتبع الأرقام التسلسلية | رقم تسلسلي فريد، يُسجل عند الإدخال والإخراج |
| سجلات الإدخال/الإخراج | سجل موحد لجميع تغييرات المخزون (رقم المصدر+النوع+الكمية+الاتجاه) |
| تحويل المخزون | تحويل بين المستودعات/المواقع، توليد مستندات تحويل إدخال/إخراج |
| مهام الجرد | جرد مخطط (حسب المستودع/التصنيف) + جرد ديناميكي (حسب SKU) |
| فروق الجرد | فائض/عجز الجرد يولّد تلقائيًا سجلات إدخال/إخراج |
| تنبيهات المخزون | ضبط حد أعلى وأدنى حسب SKU+المستودع، تنبيه عند الانخفاض عن الأدنى أو الارتفاع عن الأعلى |
| احتساب التكلفة | طريقة المتوسط المتحرك المرجح، إعادة حساب سعر التكلفة عند كل إدخال |

### 3.5 وحدة المالية

| الوظيفة | الوصف |
|------|------|
| الحسابات المحاسبية | شجرة الحسابات (أصول/خصوم/حقوق/إيرادات/مصاريف)، تدعم التخصيص |
| المستحقات والمطلوبات | تُولَّد تلقائيًا من مستندات المبيعات/المشتريات، تقييد يدوي |
| سند المقبوضات | استلام متعدد الحسابات، متعدد الطرق (نقد/بنك/وي شات/أليباي) |
| سند المدفوعات | دفع متعدد الحسابات، متعدد الطرق |
| التقييد | تقييد سندات المقبوضات مع المستحقات، وسندات المدفوعات مع المطلوبات |
| دفتر يومي النقد والبنك | تسجيل سجلات الإيرادات والمصروفات حسب الحساب + التاريخ |
| مصاريف السفر والخدمات | تقديم ← موافقة ← تحويل، مرتبط بالحساب |
| بيان الأرباح | تجميع الإيرادات/التكاليف/المصاريف/الأرباح شهريًا |

### 3.6 وحدة CRM

| الوظيفة | الوصف |
|------|------|
| إدارة العملاء | ملفات العملاء (مرتبطة ببيانات العملاء الأساسية) |
| إدارة جهات الاتصال | جهات اتصال متعددة تحت العميل |
| سجلات المتابعة | طريقة المتابعة، الوقت، المحتوى، خطة المتابعة التالية |

## 6. تدفق البيانات بين الوحدات

```
استلام الشراء → inventory_flow(إدخال) → inventory(+الكمية) → cost_record(إعادة حساب متوسط السعر)
       → finance_ar_ap(مطلوبات)

شحن المبيعات → inventory_flow(إخراج) → inventory(-الكمية) → cost_record(تسجيل التكلفة)
       → finance_ar_ap(مستحقات)

تقييد سند المقبوضات → finance_ar_ap(تحديث المقبوض) → cash_journal(تسجيل الإيراد)
تقييد سند المدفوعات → finance_ar_ap(تحديث المدفوع) → cash_journal(تسجيل المصروف)

فروق الجرد → inventory_flow(إدخال الفائض/إخراج العجز) → inventory(التعديل)

مصاريف السفر (بعد التحويل) → finance_payment(توليد تلقائي) → cash_journal(تسجيل المصروف)
```

طريقة التنفيذ: بعد اكتمال كل عملية أعمال تُثار الأحداث لتنشيط الإجراءات اللاحقة، دون استدعاء Service مباشرة بين الوحدات.

## 7. تصدير Excel/PDF

- تدعم جميع صفحات القوائم معامل `?export=excel`، لتوليد ملفات .xlsx منسقة
- تدعم لوحات المعلومات معامل `?export=pdf`، لإخراج تقارير PDF تحتوي رسومًا بيانية
- تُخفى الحقول الحساسة (المبالغ، أرقام الهواتف وغيرها) عند التصدير عبر استدعاء EncryptionService
- إعادة استخدام الفئة الأساسية ExportController الموجودة، ترث وحدات التحكم في كل وحدة وتنفذ تعريفات أعمدة التصدير الخاصة بها
