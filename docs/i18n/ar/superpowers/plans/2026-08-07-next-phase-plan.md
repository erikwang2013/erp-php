## 1. موقع المرحلة

سُلّمت خارطة الطريق P0~P3 بالكامل: 22 وحدة أعمال، 163 جدولًا، 121 وحدة تحكم، 24 خدمة، 161 نموذجًا، 12 وسيطًا؛
Flutter 96 صفحة + HarmonyOS 34 صفحة؛ التقييم الشامل 89/100. **لا تضيف هذه المرحلة مجالات أعمال جديدة**، بل تُكمل القدرات «المنفذة لكن غير المغلقة الحلقة»، وتعالج ديون الجودة، وتزيل انجراف التوثيق، لإنتاج **إصدار تطوري 1.1** قابل للصيانة طويلة الأمد.

ثلاثة أحكام أساسية (كلها مؤكدة بالعينة):

1. **قدرات كثيرة «موجودة لكن غير فعّالة»**: وسيط TenantScope و trait النموذج غير مسجلين في `config/middleware.php` (تعدد المستأجرين قشرة فارغة)؛
   قوائم الانتظار مزودة بمحركي redis/rabbitmq لكن `config/process.php` بلا عملية استهلاك؛ اتصالات WebSocket لا تتحقق من JWT؛
   إحصائيات OMS/WMS/TMS في لوحة معلومات Flutter قيم مزيفة مرمزة صلبًا، بينما نقاط النهاية الخلفية `/dashboard/oms|wms|tms` موجودة ولا تُستدعى؛
   الواجهة تستدعي نقطة نهاية إشعارات غير موجودة `/admin/notification/my/read` (الخلفية الفعلية `/admin/notification/read-all`).
2. **ديون الجودة والأمان**: 11 وحدة أعمال بلا أي اختبار؛ PHPStan بمستوى 5 لكن خط الأساس يكبت 974 خطأ؛ الاختبارات الـ 137 كلها وحدوية بحتة، بلا تكامل/E2E/تغطية؛
   `.env.docker` يحتوي مفاتيح ضعيفة كثيرة؛ CI فيه وظائف PHP فقط، بلا أي بوابة جودة للواجهة.
3. **انجراف منهجي في التوثيق**: أعداد الاختبارات 132/779→135/799→137/805 ثلاث نسخ غير متطابقة؛ ملحق FUNCTIONS.md يبعد بشدة عن القياس الفعلي؛
   أرقام EDITIONS.md متناقضة ذاتيًا؛ الفروع الثلاثة lite/standard/full متأخرة عن main بـ 20~41 التزامًا.

**المبدأ**: أولًا استكمال «المنفذ لكن غير المغلق الحلقة» (النقاط الميتة، TenantScope/قوائم الانتظار غير الموصولة، لوحة المعلومات المزيفة)، ثم إضافة الاختبارات وبوابات الجودة،

## 3. التخطيط المرحلي

حسب الأولوية في ثلاث دفعات (P0→P1→P2)، **كل فترة قابلة للنشر المستقل، وجميع معايير القبول قابلة للقياس الكمي**. إجمالي المدة نحو **8~9 أسابيع** (افتراض التوازي: وفق تقدير **2~3 مطورين بالتوازي + تعاون فريق agents**؛ إجمالي المهام نحو **77 يومًا فنيًا** — P0 ≈12.5 يومًا، P1 ≈29.5 يومًا، P2 ≈35 يومًا — إذا نُفذت تسلسليًا بفرد واحد فتحتاج نحو 15 أسبوعًا. مبرر التوازي: مهام الخلفية الصغيرة مثل A1/A4/A5 مستقلة وقابلة للتوازي؛ اختبارات B1 لكل وحدة قابلة للتقسيم إلى مهام فرعية متوازية؛ مجموعتا B/C وE/D يمكن تداخلهما عبر الفترات؛ مهام واجهة Flutter/HarmonyOS لا تحجب مهام الخلفية؛ الاعتماديات الصريحة بين المهام في §5).

**نظام الترقيم**: ترقيم مهام الفترات يطابق ترقيم فجوات §2 واحدًا لواحد (A1~A8 → A1~A6/A7-1/A7-2/A8-1، B1~B5 → B1~B5، C1~C6 → C1~C6، D1~D7 → D1~D5، E1~E6 → E1/E3/E4/E5، F2/F3 → F2/F3)؛ حيث تُدمج D6/D7 (معيارا وحدات التحكم والهجرات) في مهمة D3 موحدين، وتُدمج E2 (ادعاء README غير الحقيقي) في قبول E1، وتُدمج E6 (عمق التغطية) في A7-2، وF1 (إصدارات /api) مستبعدة صراحة هذه الفترة (انظر §6)؛ وهناك أيضًا مهمة i18n تقابل نتيجة الدراسة «Flutter i18n غير مكتمل»، وليست برقم في جدول الفجوات.

## 4. معايير القبول (ملخص، كلها قابلة للتحقق)

- **النقاط**: A1 نقطة نهاية الإشعارات، A2 `/dashboard/oms|wms|tms`، نقاط A7 عالية الأولوية — كلها قابلة للاستدعاء عبر curl مع JWT وتُرجع 200/بيانات أعمال.

- **CI**: جميع وظائف `.github/workflows/ci.yml` خضراء (مصفوفة PHP + تكامل + تغطية + flutter + تحقق التوثيق).
- **التوثيق**: مخرجات `scripts/doc-stats.sh` مطابقة لجميع أرقام docs (الانجراف يجعل CI أحمر).
- **الفروع**: `git rev-list --left-right --count main...lite|standard|full` كلها `0 0`.
- **الواجهة**: لا بقايا `${this.page}` بعلامات اقتباس مفردة في HarmonyOS؛ الحفاظ على الدخول عند الإقلاع البارد؛ الصفحات الأساسية تشغّل الخلفية في إنشاء/تعديل/حذف.
