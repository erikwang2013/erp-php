## 1. إدارة النظام

### 1.1 إدارة المستخدمين
- إدارة دورة الحياة الكاملة لحسابات المسؤولين (إنشاء/تعديل/حذف/تمكين/تعطيل)
- عمليات جماعية: حذف جماعي، تمكين/تعطيل جماعي
- استيراد مستخدمين جماعي عبر Excel، مع تحقق سطرًا بسطر + تقرير أخطاء
- تخزين كلمات المرور عبر bcrypt، وتغيير كلمة المرور يتطلب تأكيد كلمة المرور الأصلية
- العمليات الحساسة مثل الحذف تتطلب تأكيدًا ثانويًا بكلمة مرور المستخدم الحالي
- تخزين مشفّر لأرقام الهاتف/البريد الإلكتروني/أرقام الهوية، مع إخفاء تلقائي في القوائم

### 1.2 صلاحيات الأدوار (RBAC)
- إدارة الأدوار: إنشاء/تعديل/حذف، مع معرّف فريد slug
- شجرة الصلاحيات: بنية شجرية غير محدودة المستويات، ثلاثة أنواع — قائمة (ظهور في التنقل)، زر (عمليات داخل الصفحة)، API (وصول الواجهات)
- تنسيق معرّف الصلاحية: `{method}.{path}`، مثل `get.admin/product` و `post.admin/user/batch/destroy`
- علاقة متعدد-لمتعدد بين الدور والصلاحية، والمدير الفائق يتجاوز جميع فحوصات الصلاحيات
- وسيط AdminPermission يخزّن صلاحيات المستخدم في Redis (TTL=60s)

### 1.3 إعدادات النظام
- تخزين أزواج مفتاح-قيمة، مع دعم الإدارة حسب المجموعات
- أنواع القيم: نص/عدد صحيح/منطقي/JSON/مصفوفة

### 1.4 تدقيق العمليات
- تسجيل تلقائي لجميع عمليات POST/PUT/DELETE
- تسجيل: منفذ العملية، الإجراء، الطريقة، المسار، IP، المعاملات (مع إخفاء الحقول الحساسة)، الوقت
- كشف تلقائي لمصدر 8 منصات (Web/Flutter/HarmonyOS/API وغيرها)
- استعلام للقراءة فقط، لا يمكن الحذف أو التعديل

### 1.5 الحماية الأمنية
- حماية دفاعية من 7 طبقات: تقييد طرق HTTP، اعتراض XSS/حقن SQL/اجتياز المسارات/حقن الأوامر/CSRF
- كابتشا النقر (تحقق إجباري عند تسجيل الدخول/التسجيل)
- تحديد معدل نافذة منزلقة عبر Redis (Lua ذري، الافتراضي 60 مرة/دقيقة)
- قفل الحساب: 5 محاولات فاشلة تقفل الحساب 15 دقيقة
- تقييد الجلسات المتزامنة: 3 رموز صالحة كحد أقصى لنفس المستخدم
- رؤوس CSP، و security.txt (RFC 9116)
- تحقق ثانوي عشوائي للعمليات الحساسة (poster-php)

## 2. المنتجات والبيانات الأساسية

### 2.1 إدارة المنتجات
- ملف المنتج: الكود (فريد)، الاسم، الباركود، المواصفات، الوحدة الأساسية، الصورة، الوصف
- SKU متعدد المواصفات: عدة SKU تحت نفس المنتج، لكل منها كود وباركود وخصائص مواصفات مستقلة (JSON)
- تحويل وحدات متعددة: معدلات التحويل بين الوحدة الأساسية والوحدات المساعدة
- استراتيجية الأسعار: سعر الشراء، سعر الجملة، سعر التجزئة، سعر مستوى العميل
- دعم البحث النصي الكامل عبر ES

### 2.2 تصنيفات المنتجات
- بنية تصنيف شجرية غير محدودة المستويات
- دعم الترتيب، التمكين/التعطيل
- سحب وإفلات للترتيب

### 2.3 إدارة العلامات التجارية
- اسم العلامة التجارية، الشعار، الوصف، الترتيب

### 2.4 المستودعات والمواقع
- إدارة مستودعات متعددة (الاسم، الكود، العنوان، المسؤول، رقم الاتصال)
- مواقع متعددة لكل مستودع (الكود فريد داخل المستودع)

### 2.5 إدارة الموردين
- كود المورد، الاسم، جهة الاتصال، الهاتف/البريد الإلكتروني (مشفر)، العنوان
- معلومات الحساب البنكي (تخزين مشفر)، الرقم الضريبي، معدل الضريبة
- البحث النصي الكامل عبر ES

### 2.6 إدارة العملاء
- كود العميل، الاسم، مستوى العميل، حد الائتمان
- جهة الاتصال/الهاتف/البريد الإلكتروني (مشفر) / العنوان
- مستوى العميل: الاسم، معدل الخصم الافتراضي
- البحث النصي الكامل عبر ES

## 3. إدارة المشتريات

### 3.1 طلب الشراء
- تقديم القسم/الموظف لاحتياجات الشراء
- تدفق الموافقة: بانتظار الموافقة → تمت الموافقة/مرفوض → تم تحويله إلى أمر
- يمكن ربطه بمحرك سير عمل الموافقات

### 3.2 أمر الشراء
- ربط المورد، تفاصيل المنتجات (الكمية، سعر الوحدة، المبلغ)
- الحالة: بانتظار المراجعة → تمت المراجعة → استلام جزئي → تم الاستلام → تم الإلغاء
- يمكن إنشاؤه بناءً على الطلب، أو إنشاؤه مباشرة

### 3.3 استلام الشراء (تكامل عبر الوحدات)
- الاستلام حسب الأمر، مع دعم الدفعات
- الاستلام يفعّل تلقائيًا: ① الإدخال إلى المخزون (احتساب تكلفة المتوسط المتحرك المرجح) ② توليد سجل مستحق الدفع ③ تحديث الكمية المستلمة للأمر

### 3.4 إرجاع الشراء
- إرجاع للمورد، مع توليد إلغاء خروج من المخزون

### 3.5 تسوية الموردين
- التجميع حسب المورد: مبلغ الشراء، المدفوع، المستحق
- الحالة: غير مسوّى/مسوّى جزئيًا/مسوّى

## 4. إدارة المبيعات

### 4.1 عرض السعر
- عرض السعر للعميل، مع دعم التحويل إلى أمر مبيعات
- الحالة: مسودة → تمت التسعيرة → تم التحويل إلى أمر → منتهي

### 4.2 أمر المبيعات
- ربط العميل، تفاصيل المنتجات (الكمية، سعر الوحدة، الخصم)
- الحالة: بانتظار المراجعة → تمت المراجعة → شحن جزئي → تم الشحن → تم الإلغاء

### 4.3 شحن المبيعات (تكامل عبر الوحدات)
- الشحن حسب الأمر، مع دعم الدفعات
- الشحن يفعّل تلقائيًا: ① الخروج من المخزون (وفق تكلفة المتوسط المتحرك المرجح) ② توليد سجل مستحق القبض ③ تحديث الكمية المشحونة للأمر

### 4.4 إرجاع المبيعات
- إرجاع من العميل، مع توليد إلغاء إدخال للمخزون

### 4.5 تسوية العملاء والربح الإجمالي
- التجميع حسب العميل: مبلغ المبيعات، المقبوض، المستحق
- احتساب الربح الإجمالي حسب أبعاد الأمر/المنتج/العميل

### 4.6 التحكم بالائتمان للعميل (سُلّم في v1.4.0)
- إدارة حد الائتمان: صيانة حد الائتمان والاستخدام وقواعد الاعتراض لكل عميل
- الاعتراض قبل الأمر/الشحن: CreditControlService assertOrderCreate / assertDeliveryCreate / guard يرفض الأوامر المتجاوزة للحد ويعيد السبب

## 5. إدارة المخزون

### 5.1 المخزون الفوري
- دقة رباعية الأبعاد: مستودع + موقع + دفعة + SKU
- دعم مستودعات ومواقع متعددة
- استعلام فوري عن المخزون

### 5.2 سجلات الإدخال والإخراج
- تسجيل موحّد لجميع تغييرات المخزون (الاتجاه، الكمية، سعر التكلفة، رقم المصدر، الوقت)

### 5.3 تتبع الدفعات
- تاريخ الإنتاج، تاريخ الانتهاء، رقم الدفعة
- تسجيل الدفعة عند الإدخال والإخراج

### 5.4 تتبع الأرقام التسلسلية
- إدارة أرقام تسلسلية فريدة
- تسجيل الحالة عند الإدخال والإخراج (في المخزون/تم الإخراج)

### 5.5 احتساب التكلفة
- طريقة المتوسط المتحرك المرجح
- الصيغة: المتوسط الجديد = (إجمالي قيمة المخزون الأصلي + إجمالي قيمة الإدخال الحالي) / (كمية المخزون الأصلي + كمية الإدخال الحالي)
- إعادة احتساب تلقائي عند كل إدخال، والإخراج يُحتسب بالتكلفة وفق المتوسط الحالي

### 5.6 تحويل المخزون
- التحويل بين المستودعات/المواقع
- الحالة: بانتظار التحويل → تم الإخراج → تم الإدخال → مكتمل
- توليد تلقائي لسجلات الإخراج/الإدخال

### 5.7 إدارة الجرد
- جرد مخطط (حسب المستودع/التصنيف) + جرد ديناميكي (حسب SKU)
- تسجيل الكمية الدفترية مقابل الكمية الفعلية
- الفروق تولّد تلقائيًا سجلات فائض/عجز المخزون

### 5.8 تنبيهات المخزون
- ضبط الحدين الأدنى والأعلى حسب SKU + المستودع
- تسجيل تلقائي لسجل تنبيه عند الانخفاض عن الحد الأدنى/الارتفاع فوق الحد الأعلى

### 5.9 تتبع الدفعات/الأرقام التسلسلية والتنبيه بالصلاحية (سُلّم في v1.4.0)
- سلسلة التتبع: TraceService forward/backward للتتبع الأمامي/العكسي لمصير/مصدر الدفعة، وسجل الأرقام التسلسلية serial
- تنبيه الصلاحية: expiryAlert لتذكير الدفعات القريبة من الانتهاء والمنتهية

## 6. الإدارة المالية

### 6.1 المستحقات والمستحقات
- توليد تلقائي من استلام الشراء/شحن المبيعات
- الحالة: غير مقيّد → مقيّد جزئيًا → مقيّد
- حماية التكرار (idempotency) لنفس مستند المصدر

### 6.2 إدارة المقبوضات
- حسابات متعددة (نقدي/بنكي/WeChat/Alipay)
- تحديث تلقائي لرصيد الحساب والدفتر اليومي النقدي بعد المراجعة
- دعم تقييد سجلات المستحقات

### 6.3 إدارة المدفوعات
- نفس منطق المقبوضات، بالاتجاه المعاكس
- دعم تقييد سجلات المستحقات

### 6.4 دفتر اليومية النقدية والبنكية
- تسجيل التدفقات النقدية حسب الحساب + التاريخ
- تحديث فوري لرصيد الحساب البنكي

### 6.5 تسديد المصاريف
- التدفق: تقديم → موافقة → تحويل
- توليد تلقائي لسند دفع + إدخال دفتر اليومية بعد التحويل

### 6.6 بيان الأرباح
- التجميع الشهري: الإيرادات التشغيلية، تكلفة التشغيل، المصاريف، الربح
- تخزين كلقطة (فريد حسب year+month)

### 6.7 الأصول الثابتة
- دورة حياة الأصول الكاملة: الاقتناء → الاستخدام → الإهلاك → التصرف
- إهلاك القسط الثابت: (القيمة الأصلية - القيمة المتبقية) / عدد أشهر الاستخدام
- استحقاق شهري للإهلاك، مع توليد تلقائي لسجلات الإهلاك
- السجلات: القيمة الأصلية، القيمة المتبقية، العمر الافتراضي، الإهلاك الشهري، الإهلاك المتراكم، القيمة الصافية

### 6.8 إدارة الضرائب
- أنواع ضرائب متعددة: ضريبة القيمة المضافة/ضريبة دخل الشركات/ضريبة الدخل الشخصي/الطابع
- إعداد مرن لمعدلات الضرائب (بما في ذلك 4 معدلات ضريبية افتراضية في بيانات البذرة)
- الربط مع مستندات الشراء/البيع، وتسجيل مبلغ الضريبة تلقائيًا

### 6.9 العملات المتعددة
- إدارة العملات: CNY/USD/EUR/JPY (بما في ذلك 4 عملات افتراضية في بيانات البذرة)
- علامة العملة المحلية
- إدارة أسعار الصرف حسب تاريخ السريان

### 6.10 إدارة الميزانيات
- إعداد الميزانية السنوية: حسب مركز التكلفة + الحساب + الشهر
- تحليل مقارنة الميزانية مقابل الفعلي (نسبة التنفيذ + الفرق)
- الحالة: مسودة → تمت الموافقة → قيد التنفيذ → مغلقة

### 6.11 مراكز التكلفة/الأرباح
- بنية هرمية شجرية
- تجميع التكاليف + توزيع المصاريف
- محاسبة مستقلة لمراكز الأرباح

### 6.12 ترحيل الإقفال / محاسبة تعدد المنظمات / دمج القوائم (سُلّم في v1.4.0)
- ترحيل أرباح وخسائر الإقفال: تجميع حركة حسابات الأرباح والخسائر حسب الفترة (حسابات الإيراد − حسابات المصروف = الربح الصافي، status=calculated)
- الترحيل لا يولّد قيودًا (لغياب إعداد حساب «أرباح السنة» وقواعد منع الترحيل المكرر)، ولا توجد نقطة نهاية في وحدة التحكم — لم يُدرج في تسليم v1.4.0 ويُبقى كمهمة معلّقة
- محاسبة تعدد المنظمات: CompanyController / LedgerPeriodController لكيان محاسبي مستقل وفترة محاسبية (سُلّم في v1.4.0)
- محرك القوائم المدمجة (سُلّم في v1.4.0): ConsolidationService rateToBase/translateLedger لترحيل بأسعار إقفال الفترة (يُرفض عند غياب السعر)، وaddElimination للمقاصة بين الشركات التابعة (تحقق من توازن المدين والدائن)، وgenerateDraft لإخراج القائمة (تُقرأ اللقطة للفترات الصادرة، ويُعاد الحساب فوريًا من القيود المعتمدة عند غياب اللقطة)، وissue لمنع الإصدار المكرر، وlatest/list؛ وتُسجَّل النتيجة في FinanceConsolidationReport
- الاختبارات: PeriodCloseServiceTest 4 حالات + ConsolidationServiceTest 3 حالات

### 6.13 احتساب تكلفة المخزون والإنتاج (سُلّم في v1.4.0)
- صرف مواد الإنتاج وتجميع التكلفة: MaterialIssueController يُسجّل صرف المواد في المخزون، وCostEntryController + MfgCostService يجمعان المواد/العمالة/مصاريف التصنيع حسب أمر العمل
- قواعد القيود: MfgCostVoucherRule لقيد تكلفة الإتمام وترحيل الفروق (متصل بـ §12 أوامر العمل)

### 6.14 السندات والتسوية البنكية (سُلّم في v1.4.0)
- دورة حياة السند الكاملة: FinanceBillService store/update/endorse (التظهير)/discount (الخصم)/collect (التحصيل)/cash (الصرف)/reject + dueWarnings للتنبيه بالاستحقاق
- التسوية البنكية: BankReconService importStatement لاستيراد الحركات، وautoReconcile/manualReconcile/unreconcile للمقاصة، وreconReport لتقرير التسوية

### 6.15 مجمع فواتير المدخلات والفواتير الإلكترونية (سُلّم في v1.4.0)
- مجمع المدخلات: TaxInvoicePoolService registerOne/registerBatch/verify/check/deduct/deductStats؛ ويمر الفحص عبر MockTaxVerifier (وقناة مصلحة الضرائب الحقيقية نقطة تكيّف)
- الفواتير الإلكترونية: EInvoiceService issueInvoice/voidInvoice/issueLogs، عبر EInvoiceAdapter/MockEInvoiceAdapter (وقناة مصلحة الضرائب الحقيقية نقطة تكيّف)

## 7. CRM

### 7.1 إدارة العملاء
- ملف العميل (مرتبط بعميل البيانات الأساسية)
- إدارة جهات اتصال متعددة (مع تمييز جهة الاتصال الأساسية)
- تخزين مشفر لهاتف/بريد جهة الاتصال

### 7.2 سجلات المتابعة
- طرق المتابعة: هاتف/زيارة/بريد/رسالة/أخرى
- تسجيل محتوى المتابعة، خطة المتابعة التالية، ووقت المتابعة التالية
- الربط مع العميل وجهة الاتصال

### 7.3 الحملات التسويقية
- دورة حياة الحملة الكاملة: مخطط → جارٍ → مكتمل → ملغي
- قنوات متعددة: بريد/رسائل نصية/هاتف/فعاليات/تواصل اجتماعي
- تتبع العملاء المشاركين، وإحصائيات معدل التحويل
- مقارنة الميزانية مقابل الإنفاق الفعلي

### 7.4 تذاكر الخدمة
- إدارة التذاكر: بانتظار المعالجة → قيد المعالجة → تم الحل → مغلقة
- الأولوية: منخفضة/متوسطة/عالية/عاجلة
- التصنيف: دعم فني/شكوى/استفسار/استبدال وإرجاع/أخرى
- تعيين المعالج + الردود (عامة/مذكرة داخلية)

### 7.5 تقارير تحليل العملاء
- 6 مؤشرات أساسية: عملاء جدد/عملاء نشطون/معدل الاحتفاظ/متوسط قيمة الطلب/CLV/معدل حل التذاكر
- توليد تلقائي للتقارير (لقطة بيانات JSON)
- دعم شهري/ربع سنوي/سنوي

## تدفق البيانات عبر الوحدات

```
استلام الشراء → إدخال تلقائي للمخزون (تكلفة المتوسط المتحرك المرجح) → توليد سجل مستحق الدفع
شحن المبيعات → خروج تلقائي من المخزون → توليد سجل مستحق القبض
المقبوضات/المدفوعات → تقييد المستحقات/المستحقات → تحديث الدفتر اليومي
فروق الجرد → توليد تلقائي لسجلات إدخال/إخراج الفائض والعجز
تقديم الموافقة → توجيه محرك سير العمل → موافقة متدرجة → دفع الإشعارات
تحويل تسديد المصاريف → توليد تلقائي لسند دفع + إدخال دفتر اليومية
إهلاك الأصول → استحقاق شهري → توزيع التكلفة على مراكز التكلفة
حساب MRP → توسيع BOM → احتساب الصافي المطلوب → توليد اقتراحات الشراء/الإنتاج
موافقة الإجازة → تحديث حالة الحضور بعد الموافقة
اكتمال الإنتاج → إدخال تلقائي للمخزون (المنتجات النهائية) + خصم مخزون المواد الخام
سجلات ساعات العمل → التجميع في المهمة → التجميع في تكلفة المشروع
```

## 16. إدارة الطلبات (OMS)

### 16.1 إدارة الطلبات
- **استيراد الطلبات متعدد القنوات**: يدعم manual/web/mobile/api/marketplace/edi/pos
- **معلومات الطلب الموسعة**: رقم طلب القناة، المتجر، حالة التنفيذ، حالة الدفع، الأولوية
- **تخصيص المخزون**: احتساب ATP (الكمية القابلة للوعد) → حجز المخزون (قفل متشائم لمنع البيع الزائد)
- **تنسيق التنفيذ**: التخصيص → إنشاء التنفيذ → إرسال إلى WMS → انتقاء/تغليف → شحن TMS
- **إلغاء الطلب**: تحرير تلقائي لحجز المخزون

### 16.2 RMA الاستبدال والإرجاع
- إنشاء RMA (إرجاع/استبدال/إصلاح) → موافقة → إعادة → استلام وإدخال المخزون (stockIn) → استرداد
- دعم إدارة تكلفة شحن الإرجاع ومبلغ الاسترداد

### 16.3 إدارة القنوات
- كود القناة/الاسم/النوع (direct/marketplace/edi/pos)
- تكوين القناة (JSON)، حالة التمكين/التعطيل

## 17. إدارة المستودعات (WMS)

### 17.1 المناطق والمواقع
- **المناطق**: منطقة الاستلام/التخزين/الانتقاء/التغليف/الشحن/الإرجاع/الفحص
- **توسعة الموقع**: الممر → الرف → الطبقة → الخلية، بنية هرمية + باركود/حجم/وزن تحميل/ترتيب الانتقاء

### 17.2 تدفق الإدخال
- **ASN (إشعار وصول مسبق)**: المورد → الوصول المتوقع → الناقل → رقم التتبع
- **مهمة الاستلام**: استلام الرصيف → إدخال الكمية الفعلية → فحص الجودة
- **مهمة التخزين**: توليد تلقائي → تعيين → استراتيجية (fifo/zone_fixed/abc) → تأكيد التخزين (stockIn)

### 17.3 تدفق الإخراج
- **إدارة الموجات**: تجميع أوامر متعددة → موجة انتقاء/موجة شحن → أولوية
- **مهمة الانتقاء**: انتقاء حسب المستند/بالجملة/حسب المنطقة/حسب الموجة → تعيين → تأكيد (الكمية المنتقاة الفعلية)
- **مهمة التغليف**: نوع التغليف (box/bag/pallet) → الوزن/الأبعاد

## 18. إدارة النقل (TMS)

### 18.1 الناقلون
- كود الناقل/النوع (بريد سريع/شحن جزئي/شاحنة كاملة/جوي/بحري/سككي)
- خدمات الناقل: standard/express/overnight/2day/economy + مدة التسليم
- إعداد API: تجريد custom/shippo/afterShip/17track

### 18.2 إدارة رسوم الشحن
- **بطاقة الأسعار**: بلد المنشأ/الوجهة → شريحة الوزن → الرسوم الأساسية/لكل كجم/رسوم الوقود الإضافية
- **عملات متعددة**: CNY/USD/EUR وغيرها، مرتبطة بـ exchange_rate
- **مقارنة أسعار الشحن**: الاستعلام عن جميع الأسعار المتاحة حسب بلد الوجهة + الوزن، مرتبة تصاعديًا

### 18.3 الشحنات والتتبع
- **الشحنة**: خدمة الناقل → رقم التتبع → الحالة (بانتظار الشحن → تم الاستلام → قيد النقل → تم التسليم/غير طبيعي/مرتجع)
- **تتبع الشحنة**: استدعاء webhook → مزامنة تلقائية لحالة الشحنة
- **فاتورة الشحن**: إنشاء → تأكيد → دفع → توليد مستحق الدفع
