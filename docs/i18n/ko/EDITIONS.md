> doc-stats 검증에 참여하지 않습니다. Full 열의 숫자는 `scripts/doc-stats.sh`가 실측한 값(227 테이블 / 159 컨트롤러 / 23 업무 모듈)으로,

> **브랜치 사실**(2026-09-22 실측 `git branch -a` + `git ls-remote --heads origin`):
> 저장소 로컬과 원격 모두 `main` 한 개 브랜치만 남아 있고, `lite` / `standard` / `full` 세 브랜치는 **삭제되었습니다**
> (2026-08-31에 세 브랜치 공존을 실측했으며, 모두 2026-08-17 커밋 `eea90c0`에 멈춰 있고 서로 차이가 없었고 `main`보다 38개 커밋 뒤처져 있었습니다).

> 즉 버전 차이는 이제 커밋과 tag로만 추적할 수 있으며, 저장소에는 체크아웃할 버전 브랜치가 없습니다.

## v1.17.0 변경(2026-09-15)

> 버전 정체성은 그대로입니다: 저장소는 여전히 풀 버전(Full) 한 벌의 코드만 구현하며, Lite/Standard 열은 제품 계획값이고 해당 브랜치는 아카이브 동결되었습니다.

- **관리단이 두 벌에서 세 벌로**: Angular 22(`apps/angular/`)와 React 19 + Vite(`apps/react/`)가 추가되어 기존 Flutter 3.x Web(`apps/flutter/`)과 나란히 서며,
  세 단말이 동일한 `/admin/v1`, `/api/v1`, `/open/v1` 인터페이스를 공유합니다.
- **전 플랫폼 13개 로케일**(zh/en/ja/ko/de/fr/es/pt/ru/ar/hi/bn/id):
  - 백엔드 응답 메시지 `resource/translations/<locale>/` —— `zh_CN` 565건, 나머지 11개 로케일 각 544건, `en` 30건
    (기준: 세 파일의 리프 항목, `validation.php`의 `attributes` 필드 라벨은 포함·그룹 키는 불포함 —— `zh_CN`은 필드 라벨 21개를 번역했기 때문에 21건 많습니다. `en` 행은 "영어가 곧 key"로 사전이 거의 비어 있습니다)
  - 관리단 인터페이스: Angular 소스 사전 1456 키, React 1451 키 × 11개 신규 로케일; **로케일별 지연 로딩**으로 로케일마다 각각 하나의 chunk
  - 생성기: `scripts/gen-be-locales.mjs`(백엔드), `scripts/gen-fe-locales.mjs`(프론트엔드, `--app angular|react`)
  - 전환 진입점: 상단 바 **독립 globe 아이콘** + 개인 센터 드롭다운(양단 동일)
- **Flutter와 HarmonyOS는 여전히 중·영 2개 로케일**이며 이번 배치에는 포함되지 않았습니다.
- **아래 표에 미친 영향**: Full 열 163 테이블 / 122 컨트롤러 / 19 업무 모듈 → **227 / 159 / 23**;
  완성도 매트릭스에 「다국어(i18n)」 행이 추가되었습니다(모듈 행 44 → 45, 백엔드 API 39 → 40, 업무 로직 33 → 34);
  단, 2026-09-15 병합 매트릭스에서 중복된 「멀티테넌트」 행을 합친 뒤 모듈 행은 44로 되돌아갔습니다(백엔드 API 39, 업무 로직 33).
  위 문장은 v1.17.0 당시의 증분 기준이므로 그대로 둡니다.

## 브랜치 전략(2026-08-27부터)

> `lite` / `standard` / `full` 세 버전 브랜치에 적용되며, CI release 작업(멱등 버전 tag)과 일치합니다.
> **현황 보충(2026-09-22 실측)**: 세 브랜치는 삭제되었으므로, 이 절의 나머지 항목은 "아카이브 = 커밋과 tag"로 이해해야 하며
> 더 이상 체크아웃할 버전 브랜치가 없습니다.

- **`main`이 유일한 개발 소스**: 모든 기능 개발, 결함 수정, 의존성 업그레이드는 일괄 `main`에 병합하며, 커밋은 Lead가 통일적으로 수행합니다.
- **버전 브랜치는 아카이브만, 유지보수 없음**: `lite` / `standard` / `full`은 역사 아카이브 브랜치로 동결되어 신규 커밋을 받지 않고,
  `main` 증분도 동기화하지 않으며, 강제 업데이트나 푸시도 하지 않습니다(코드 라인 3개 유지 비용 방지); **동결 기간이 끝난 뒤 세 브랜치는 삭제되었고**,
  아카이브 내용은 `main` 이력의 `eea90c0`에 남아 있습니다.
- **버전 차이는 버전 tag로 기록**: 릴리스는 CI release 작업이 최신 tag 기준으로 `vX.Y.Z`를 멱등 생성합니다
  (`scripts/bump-version.sh` 참고). 각 버전 간 기능 차이는 브랜치 코드 라인이 아니라 tag와 위 기능 비교표를 기준으로 합니다.
- **검증**: `main`의 CI가 곧 버전 릴리스 검증이며, 아카이브 브랜치는 별도로 CI를 돌리지 않습니다. (2026-09-15부터 release 작업 의존성은 `docs` + `e2e`이며, php 작업은 계속 돌지만 발행을 막지 않습니다 —— 그 빨간불은 CI 전용 통합 테스트의 역사적 부채이며 `.github/workflows/ci.yml` 주석을 참고하세요.)
