## 1. 시스템 개요

오픈ERP 시스템(open-erp)은 webman v2 + Flutter 기반으로 구축된 풀스택 전사적 자원 관리(ERP) 시스템으로, 시스템 관리, 매입·판매·재고, 재무, CRM, 승인 워크플로, 메시지 알림, 프로젝트 관리, 인사 관리, 생산 제조, 커스텀 리포트 등 14대 업무 도메인을 포괄합니다.

### 1.1 설계 목표
- 모놀리스 배포, 모듈화 설계
- 모든 ID는 snowflake로 생성 + hashids로 암호화 전송
- 민감 데이터 이중 암호화(전송 계층 AES-256-CBC + 저장 계층 AES-128-ECB)
- 이동가중평균 원가 계산
- 모듈 간 자동 연동(구매→매입채무, 판매→매출채권, 수금·지급→정산)

### 1.2 기술 제약
- PHP 8.3+, MySQL 8.0+, Redis 7, Elasticsearch 8
- 테이블 접두사 erp_, 기본키 BIGINT 비자동증가
- API 버전은 요청 헤더 API-Version으로 제어
- JWT 인증 + RBAC 권한
- 전역 함수에 \ 접두사 없음

## 2. 시스템 관리 모듈

### 2.1 사용자 관리
- 관리자 CRUD, 일괄 활성/비활성, 일괄 소프트 삭제 지원
- Excel 일괄 가져오기(행별 검증 + 오류 보고서)
- 비밀번호 bcrypt 해시, 비밀번호 변경 시 기존 비밀번호 확인 필요
- 삭제 작업은 현재 사용자 비밀번호 2차 확인 필요
- 휴대폰/이메일/주민등록번호 암호화 저장, 목록 자동 마스킹

### 2.2 역할 권한 (RBAC)
- 역할 CRUD, slug 고유 식별자
- 권한 트리(무한 레벨 parent_id 자기 참조), 유형: 메뉴/버튼/API
- 권한 식별자 형식: {method}.{path}(예: get.admin/product, post.admin/user/batch/destroy)
- 역할-권한 다대다 연관
- 슈퍼 관리자(super_admin)는 모든 권한 검사 생략
- AdminPermission 미들웨어 Redis 권한 캐시(TTL=60s)

### 2.3 시스템 설정
- 키-값 저장, 그룹 지원
- 값 유형: string|int|bool|json|array

### 2.4 작업 감사
- 모든 POST/PUT/DELETE 작업 자동 기록
- 기록: 작업자, 동작, 메서드, 경로, IP, 파라미터(민감 필드 마스킹), 시간
- 8개 플랫폼 출처 단말 자동 감지(Web/Flutter/HarmonyOS/API 등)
- 조회만 지원, 삭제/수정 불가

### 2.5 보안 방어
- 18계층 심층 방어(상세는 SECURITY.md 참고)
- SecurityFilter: HTTP 메서드 제한 + XSS/SQL 인젝션/경로 탐색/명령 인젝션/CSRF 차단
- RateLimit: Redis 슬라이딩 윈도우 속도 제한(Lua 원자화, 60회/분)
- 클릭 캡차(로그인/가입 강제)
- 계정 잠금: 5회 실패 시 15분 잠금
- 동시 세션 제한: 동일 사용자 최대 3개 Token
- CSP 헤더, security.txt (RFC 9116)
- poster-php 민감 작업 무작위 2차 검증

## 3. 상품과 기초 데이터

### 3.1 상품 관리
- 상품 마스터: 코드(고유), 이름, 바코드, 규격, 기본 단위, 이미지, 설명
- 다중 규격 SKU: 동일 상품 아래 여러 SKU, 각각 독립 코드·바코드·규격 속성(JSON)
- 다중 단위 환산: 기본 단위 ↔ 보조 단위, 환산율
- 가격 정책: 매입가, 도매가, 소매가, 고객 등급별 가격
- 상품 분류: 무한 레벨 트리 구조, 드래그 정렬 지원
- 브랜드 관리: 브랜드 이름, Logo, 설명

### 3.2 창고·로케이션
- 다중 창고 관리(이름, 코드, 주소, 담당자)
- 각 창고에 다중 로케이션(코드는 창고 내에서 고유)
- 창고 연락처 암호화 저장

### 3.3 공급업체/고객
- 공급업체 마스터: 코드, 이름, 담당자, 전화/이메일(암호화), 주소, 은행 정보
- 고객 마스터: 코드, 이름, 고객 등급, 신용 한도
- 고객 등급: 이름, 기본 할인율
- 공급업체/고객 ES 전문 검색 지원

## 4. 구매 모듈

### 4.1 구매 프로세스
신청 → 승인 → 오더 → 입고 → 정산

### 4.2 구매 신청
- 부서/담당자가 구매 수요 제출
- 상태: 승인 대기 → 승인/반려 → 오더 전환
- 승인자 작업 지원

### 4.3 구매 오더
- 공급업체 연관, 상품 내역(수량, 단가, 금액)
- 상태: 심사 대기 → 심사 완료 → 부분 입고 → 입고 완료 → 취소
- 구매 신청 기반 생성 가능, 직접 생성도 가능

### 4.4 구매 입고(모듈 간 연동)
- 오더 기준 입고, 분할 입고 지원
- 입고 시 자동 트리거:
  1. InventoryService.stockIn() → 실시간 재고 갱신 + 이동가중평균 재계산
  2. FinanceService.createAp() → 매입채무 기록 생성
  3. 오더 입고 수량과 상태 갱신
- 로케이션, 로트번호 기록 지원

### 4.5 구매 반품
- 공급업체로 반품, 출고 상쇄 생성
- 입고 전표 연관

### 4.6 공급업체 정산
- 공급업체별 집계: 구매 금액, 지급 완료, 미지급
- 정산 상태: 미정산/부분 정산/정산 완료

### 5.1 판매 프로세스
견적 → 오더 → 출고 → 정산

### 5.2 견적서
- 고객에게 견적, 판매 오더 전환 지원

### 5.3 판매 오더
- 고객 연관, 상품 내역(수량, 단가, 할인)
- 상태: 심사 대기 → 심사 완료 → 부분 출고 → 출고 완료 → 취소
- 할인 금액 지원

### 5.4 판매 출고(모듈 간 연동)
- 오더 기준 출고, 분할 출고 지원

  1. InventoryService.stockOut() → 재고 차감(이동가중평균 원가 사용)

### 5.5 판매 반품
- 고객 반품, 입고 상쇄 생성

### 5.6 고객 정산과 매출이익
- 고객별 집계: 판매 금액, 수금 완료, 미수금
- 판매 매출이익: 오더/상품/고객 차원으로 계산

## 6. 재고 모듈

### 6.1 재고 관리
- 실시간 재고: 창고+로케이션+로트+SKU 4차원 정밀도
- 입출고 이력: 모든 재고 변동 일괄 기록(방향, 수량, 원가, 출처 오더번호)
- 로트 추적: 생산일자, 만료일자
- 시리얼 번호 추적: 고유 시리얼 번호, 입출고 시 상태 기록(재고/출고)

### 6.2 원가 계산
- 이동가중평균법
- 공식: 새 평균가 = (기존 재고 총액 + 이번 입고 총액) / (기존 재고 수량 + 이번 입고 수량)
- 입고 시마다 자동 재계산, 출고는 현재 평균가로 원가 처리
- 완전한 원가 기록 체인(변동 전 평균가 → 변동 후 평균가)

### 6.3 재고 이동
- 창고 간/로케이션 간 이동
- 상태: 이동 대기 → 이동 완료(출) → 이동 완료(입) → 완료
- 이동 출/입 입출고 이력 자동 생성

### 6.4 재고 실사
- 계획 실사(창고/분류 기준) + 동적 실사(SKU 기준)
- 장부 수량 vs 실사 수량 기록
- 실사 차이 자동으로 재고 과부족 입출고 이력 생성

### 6.5 재고 경고
- SKU+창고별 상한/하한 설정
- 하한 미만/상한 초과 시 자동으로 경고 로그 기록

## 7. 재무 모듈

### 7.1 회계 과목
- 과목 트리: 자산/부채/자본/수익/비용 5대 분류
- 과목 코드 고유
- 잔액 방향: 차변/대변

### 7.2 부기 전표
- 전표 번호, 일자, 요약
- 복식 부기: 각 분개에 차변 금액과 대변 금액 포함(차변·대변 반드시 일치)
- 상태: 초안 → 심사 완료

### 7.3 총계정원장
- 회계 과목 + 회계 기간(연도/월)별 집계
- 기록: 기초 차변/대변 잔액, 당기 차변/대변 발생액, 기말 차변/대변 잔액
- 기말 잔액 = 기초 잔액 ± 당기 발생액(과목 잔액 방향에 따라)
- 전표 심사 후 자동 갱신
- 연도/월/과목 필터 지원

### 7.4 보조원장
- 지정 과목의 매 전표 분개를 건별 기록
- 포함: 전표번호, 방향(차/대), 금액, 잔액, 요약, 일자
- 과목+일자 범위 조회 지원
- 전표 분개와 동기 갱신

### 7.5 대차대조표
- 회계 기간별 생성(월간/연간)
- 총계정원장 잔액 자동 집계:
  - 자산 유형 과목(1) → 총자산 = 유동자산 + 비유동자산
  - 부채 유형 과목(2) → 총부채 = 유동부채 + 비유동부채
  - 자본 유형 과목(3) → 지배기업 소유주 지분
  - 항등식: 자산 = 부채 + 지배기업 소유주 지분
- 스냅샷 저장 지원(JSON 전체 데이터)
- 스냅샷 없으면 총계정원장에서 자동 생성

### 7.6 현금흐름표
- 회계 기간별 생성(월간/연간)
- 3분류:
  - 영업 활동 현금흐름(판매 수금 - 구매 지급 - 비용 지출)
  - 투자 활동 현금흐름
  - 재무 활동 현금흐름
- 기초/기말 현금 잔액 = 전체 은행 계좌 기초/기말 잔액 합계
- 현금·은행 일계부 자동 집계로 생성
- 스냅샷 저장 지원(JSON 전체 데이터)

### 7.7 매출채권·매입채무
- 구매 입고/판매 출고로 자동 생성
- 매출채권: 유형=매출채권, 고객 연관, 출처=판매 출고 전표
- 매입채무: 유형=매입채무, 공급업체 연관, 출처=구매 입고 전표
- 상태: 미정산 → 부분 정산 → 정산 완료
- 동일 출처 문서는 중복 생성 불가(멱등성 보호)

### 7.8 수금 관리
- 다중 계좌(현금/은행/위챗/알리페이)
- 심사 후 자동으로 은행 계좌 잔액과 현금 일계부 갱신
- 정산: 매출채권 기록 선택, 정산 금액 입력(미정산 잔액 초과 불가)
- 부분 정산 상태 자동 전환

### 7.9 지급 관리
- 수금과 동일 로직, 방향 반대
- 매입채무 기록 정산

### 7.10 현금·은행 일계부
- 계좌+일자별 매 수입·지출 기록
- 변동 후 잔액 기록
- 은행 계좌 잔액 실시간 갱신

### 7.11 비용 정산
- 프로세스: 제출 → 승인 → 송금
- 비용 과목 연관
- 송금 후 자동으로 지급 전표 + 일계부 생성

### 7.12 손익계산서
- 월별 집계: 영업 수익, 영업 비용, 비용, 이익
- 데이터 스냅샷 저장(year+month 고유)

### 7.13 고정자산 감가상각
- 자산 전 생애주기 관리: 취득 → 사용 → 감가상각 → 처분
- 감가상각 방법: 정액법((원가-잔존가치) / 사용 개월 수)
- 월별 감가상각 계상, 자동으로 감가상각 기록 생성
- 기록: 원가, 잔존가치, 사용 연한, 월 감가상각액, 누적 감가상각, 장부가액

### 7.14 세무 관리
- 다중 세목 지원: 부가가치세/법인세/개인소득세/인지세
- 세율 유연 구성
- 구매/판매 전표와 연동, 세액 자동 기록

### 7.15 다중 통화
- 통화 관리: CNY/USD/EUR/JPY 등
- 기능 통화 표시
- 환율은 적용 일자 기준 관리
- 외화 환산 지원

### 7.16 예산 관리
- 연간 예산 편성: 원가센터+과목+월별 편성
- 예산 vs 실적 비교 분석
- 실행률 계산 + 차이 분석
- 상태: 초안 → 승인 완료 → 실행 중 → 마감

### 7.17 원가센터/이익센터
- 트리 계층 구조
- 원가 귀속 + 비용 배분
- 이익센터 독립 회계

## 8. CRM 모듈

### 8.1 고객 관리
- 고객 마스터가 기초 데이터 고객과 연관
- 고객 아래 다중 담당자(대표 담당자 표시)
- 담당자 전화/이메일 암호화 저장

### 8.2 팔로우 기록
- 팔로우 방식: 전화/방문/이메일/메시지/기타
- 팔로우 내용, 다음 팔로우 계획, 다음 팔로우 시간 기록
- 고객, 담당자, 영업기회 연관

### 8.3 마케팅 활동
- 활동 전 생애주기: 계획 → 진행 중 → 완료 → 취소
- 다중 채널: 이메일/문자/전화/이벤트/소셜 미디어
- 참여 고객 추적, 전환율 통계
- 예산 vs 실제 지출 비교

### 8.4 서비스 티켓
- 티켓 관리: 대기 → 처리 중 → 해결 → 마감
- 우선순위: 낮음/보통/높음/긴급
- 분류: 기술 지원/불만/문의/반품·교환/기타
- 처리자 배정 + 답글(공개/내부 메모)
- 해결률 통계

### 8.5 고객 분석 리포트
- 6대 핵심 지표: 신규 고객/활성 고객/유지율/객단가/CLV/티켓 해결률
- 리포트 자동 생성(JSON 데이터 스냅샷)
- 월간/분기/연간 지원

### 8.6 판매 퍼널
- 단계 구성: 초기 접촉(10%) → 수요 확인(30%) → 견적 제안(50%) → 상업 협상(70%) → 성사(100%) → 패배(0%)
- 영업기회: 고객, 현재 단계, 예상 금액, 성사 확률, 예상 성사 일자, 담당자
- 영업기회 상태: 패배/진행 중/성사
- 단계 이동 추적

### 8.7 고객 공해 풀
- 고객 공해 풀: 소속 미배정 또는 기한 초과 미팔로우 고객은 자동으로 공해로 진입
- 회수 규칙: 고객 등급별 무팔로우 자동 회수 일수 설정
- 1인 최대 수령 수 제한으로 고객 자원 침체 방지
- 수령/해제/회수 작업 모두 이력 기록
- 영업팀 활성도 촉진, 고객 침체 방지

### 8.8 CRM 견적 관리
- 판매 모듈과 독립된 CRM 내부 견적 프로세스
- 상태: 초안 → 발송 완료 → 고객 확인 → 계약 전환 → 기간 만료
- 견적 유효 기간 지원
- 계약으로 직접 전환 지원(`to-contract`)
- 고객과 영업기회 연관

### 8.9 계약 관리
- 계약 전 생애주기: 초안 → 승인 대기 → 승인 완료 → 실행 중 → 완료/종료
- 고객, 영업기회, 견적 연관
- 계약 내역: 상품/수량/단가/금액
- 체결 일자, 시작/종료 일자 기록
- 계약 조항 내용(TEXT 대형 필드)
- 담당자 배정

## 13. 생산 제조 모듈

### 13.1 BOM (자재 명세서)
- BOM 정의: 상위 제품, 하위 자재, 표준 사용량, 단위, 공정

- 버전 관리: BOM 수정 기록

- 생산 오더 CRUD: 제품, 계획 수량, 계획 시작/종료 일자
- 상태: 생산 대기 → 생산 중 → 완료 → 마감
- 착공/완공 작업: 실제 시작/종료 시간 기록
- 생산 내역: 자재 출고 목록(BOM 전개 기반)

### 13.3 공정 경로
- 공정 경로 정의: 제품, 공정 시퀀스, 각 공정 표준 공수

### 13.5 MRP (자재 소요 계획)

- 구매 제안(원자재 부족 시)과 생산 제안(반제품 부족 시) 자동 생성
- MRP 내역: 자재, 총소요, 재고 가용량, 순소요, 제안 오더 수량
- 계획 상태: 초안 → 생성 완료 → 구매/생산 제안 하달

## 16. 국제화 (i18n)

### 16.1 언어 자동 감지
- 요청 헤더 `Accept-Language` 자동 인식(zh-CN → 中文, en → 英文)
- Locale 미들웨어는 전역 미들웨어 체인 첫 번째로 실행
- 폴백 체인: 현재 언어 → 설정된 fallback_locale → 원본 key 반환

### 16.2 번역 파일
- 디렉토리: `resource/translations/{locale}/`
- 공통 메시지: `common.php`(41개 키: 성공/실패/생성/업데이트/삭제/검증 등)
- 모듈 이름: `modules.php`(69개 키: 상품/구매/판매/재고/재무/CRM 등)
- 검증 규칙: `validation.php`(11개 규칙 + 10개 필드 라벨)

### 16.3 사용 방식
- 컨트롤러 내: `$this->trans('created')`
- 전역 함수: `__('modules.product')`, `__m('finance')`
- 모듈 이름: `__('modules.product')` → 상품 / Product
