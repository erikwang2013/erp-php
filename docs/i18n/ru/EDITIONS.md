> то есть различия версий теперь можно проследить только по коммитам и тегам — веток версий, которые можно было бы checkout, в репозитории больше нет.

## Изменения v1.17.0 (2026-09-15)

> Позиционирование версии не меняется: в репозитории по-прежнему реализована только полная версия (Full) одним набором кода; колонки Lite/Standard — плановые значения продукта, соответствующие ветки заархивированы и заморожены.

- **Панелей управления стало три вместо двух**: добавлены Angular 22 (`apps/angular/`) и React 19 + Vite (`apps/react/`),
  они работают наравне с существующей Flutter 3.x Web (`apps/flutter/`); все три используют один и тот же набор эндпоинтов `/admin/v1`, `/api/v1`, `/open/v1`.
- **13 языков на всей платформе** (zh/en/ja/ko/de/fr/es/pt/ru/ar/hi/bn/id):
  - Сообщения ответов бэкенда `resource/translations/<locale>/` — `zh_CN` 565 записей, остальные 11 языков по 544 записи, `en` 30 записей
    (критерий: листовые записи трёх файлов; метки полей в `attributes` файла `validation.php` учитываются, ключи группировки — нет, поэтому у `zh_CN` на 21 запись больше — переведён 21 метка поля. Строка `en` — «английский как key», словарь почти пуст)
  - Интерфейсы панелей управления: исходный словарь Angular 1456 ключей, React 1451 ключ × 11 новых языков; **ленивая загрузка по языку**, каждый язык — отдельный chunk
  - Генераторы: `scripts/gen-be-locales.mjs` (бэкенд), `scripts/gen-fe-locales.mjs` (фронтенд, `--app angular|react`)
  - Точка переключения: **отдельный значок глобуса** в верхней панели + выпадающий список в личном кабинете (одинаково в обоих клиентах)
- **Flutter и HarmonyOS по-прежнему поддерживают только китайский и английский**, в этот цикл они не включены.
- **Влияние на таблицу ниже**: колонка Full 163 таблицы / 122 контроллера / 19 бизнес-модулей → **227 / 159 / 23**;
  в матрицу завершённости добавлена строка «мультиязычность (i18n)» (строк модулей 44 → 45, backend API 39 → 40, бизнес-логика 33 → 34);
  примечание: после объединения дублирующейся строки «мультитенантность» в сводной матрице от 2026-09-15 строк модулей стало снова 44 (backend API 39, бизнес-логика 33),
  приведённая выше фраза отражает прирост на момент v1.17.0 и оставлена без изменений.

## Изменения v1.4.0 (2026-09-05)

> Позиционирование версии не меняется: в репозитории по-прежнему реализована только полная версия (Full) одним набором кода; колонки Lite/Standard — плановые значения продукта, соответствующие ветки заархивированы и заморожены.

- **Версионирование путей по всему сайту**: `/admin/*` → `/admin/v1/*`, `/api/*` → `/api/v1/*`, `/open/*` → `/open/v1/*`;
  исключения — только `GET /api/docs` (документация OpenAPI) и webhook TMS; точки прав RBAC проверяются по `method.path` без сегмента версии,
  миграция существующих данных ролей не требуется (коммит `3ee1430`; управление заголовком запроса `API-Version` было удалено ранее, коммит `8276a1b`).
- **P0 Мультиорганизационность и учёт затрат**: независимый учёт по организациям (Company/LedgerPeriod), движок консолидированной отчётности (пересчёт по курсу на конец периода + взаимозачёт между дочерними компаниями,
  приоритет снимка с сохранением в FinanceConsolidationReport), учёт запасов и себестоимости производства (отпуск материалов + сбор затрат).
- **P1 Исполнение производства и взаимодействие**: учёт выработки по операциям / сдельная оплата / передача и приёмка подряда / загрузка мощностей / прослеживаемость партий и серийных номеров (M1/M2/M6/M3), контроль кредитных лимитов (F7),
  полотно конструктора процессов согласования (B3), шаблоны печати (B1), зарплата HR (H1/H2), сканирование при осмотре оборудования (E1), стоимость проекта (P1).
- **P2 Дифференциация и экосистема**: программа лояльности (C1), реестр векселей и сверка с банком (F6), пул входящих счетов-фактур и электронные счета (F5, точка адаптации — реальный канал налоговой службы),
  многодрайверность каналов и повтор при сбое (B4), пользовательские поля (B7), тарификация мультитенантности по сроку (B5 — middleware изоляции арендаторов всё ещё не зарегистрирован, включено частично),
  обучение и социальное страхование (H3/H4).
- **Матрица функций**: из 44 строк модулей 33 строки имеют двойную ✅; 21 строка помечена v1.4.0 (включая 1 частично включённую), подробности в `docs/FUNCTIONS.md` §19.

## Стратегия веток (с 2026-08-27)

> Относится к трём веткам версий `lite` / `standard` / `full` и согласована с задачей release в CI (идемпотентный тег версии).
> **Дополнение о текущем состоянии (измерено 2026-09-22)**: три ветки удалены, остальные пункты этого раздела следует понимать как «архив = коммиты и теги»,
> веток версий, которые можно было бы checkout, больше нет.

- **`main` — единственный источник разработки**: вся разработка функций, исправления дефектов и обновления зависимостей вливаются в `main`, коммиты выполняет Lead.
- **Ветки версий только архивируются, не поддерживаются**: `lite` / `standard` / `full` заморожены как исторические архивные ветки, они не принимают новые коммиты,
  не синхронизируют инкременты `main` и не получают принудительных обновлений или push (чтобы не поддерживать три линии кода); **после окончания периода заморозки три ветки удалены**,
  архивное содержимое сохранилось в истории `main` в коммите `eea90c0`.
- **Различия версий фиксируются тегами версий**: выпуск выполняет задача release в CI, идемпотентно создавая `vX.Y.Z` по последнему тегу
  (см. `scripts/bump-version.sh`); функциональные различия между версиями определяются тегами и таблицей сравнения выше, а не поддерживаемыми линиями кода веток.
- **Проверка**: CI ветки `main` и есть проверка релиза версии, архивные ветки больше не запускают CI отдельно. (С 2026-09-15 задача release зависит от `docs` + `e2e`; задача php выполняется как прежде, но не блокирует выпуск — её красный статус это исторический долг интеграционных тестов, специфичный для CI, см. комментарии в `.github/workflows/ci.yml`.)
