## Сценарии применения

| Версия | Рекомендуемые сценарии |
|------|---------|
| **Lite** | Малые и средние торговые предприятия: ядро — закупки/продажи/склад + базовые финансы, без процессов согласования и расширенных модулей |
| **Standard** | Тот же функциональный объём, упрощённая модель данных, подходит как база для кастомизации |
| **Full** | Средние и крупные предприятия: полный стек закупки/продажи/склад + финансы + CRM + HR + производство + проекты |

## Стратегия веток (с 2026-08)

> Документ соответствует текущим соглашениям о ветках репозитория для веток `lite` / `standard` / `full`.

- **`main` — единственный источник разработки**: вся разработка функций, исправления дефектов и обновления зависимостей вливаются в `main`.
- **Ветки версий — только cherry-pick при релизах**: `lite` / `standard` / `full` не получают ежедневные коммиты как независимые линии разработки;
  при выпуске версии инженер по версиям выполняет cherry-pick соответствующих функций из `main` (или при необходимости полное слияние),
  сохраняя в ветках намерения по сокращению (различия модулей — см. таблицу сравнения выше).
- **Принцип сокращения**: ветка версии = подмножество `main`. При слиянии/переносе из `main`, если конфликт попадает в логику сокращения версии
  (например, различия модулей в EDITIONS.md, сокращение маршрутов), сохраняйте намерения ветки; во всём остальном используйте версию из `main`.
- **Проверка**: после слияния ветка версии должна пройти полную проверку синтаксиса `php -l`; тесты, неприменимые из-за сокращения, можно пропускать с фиксацией причины.
- **Релиз**: слияние/перенос в ветки версий выполняет инженер по версиям и фиксирует merge-коммит; коммиты в `main` выполняет Lead.
