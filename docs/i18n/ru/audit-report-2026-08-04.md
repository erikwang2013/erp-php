## III. Оценка безопасности

### 3.1 Реализованные меры безопасности ✅

```
Сетевой уровень → Nginx: лимиты частоты/размер тела/соединения/заголовки безопасности/запрет чувствительных файлов
Промежуточное ПО → SecurityFilter: XSS/SQLi/обход путей/инъекции команд/обнаружение вредоносных файлов/CSRF (проверка Origin)
                 → RateLimit: атомарное скользящее окно Lua (по умолчанию 60 раз/мин, вход 10, регистрация 5)
                 → AdminAuth: JWT-аутентификация + чёрный список + ограничение сессий (макс. 3 токена)
                 → AdminPermission: авторизация RBAC method.path (кэш 60 с)
                 → Cors: CSP/X-Frame/X-Content-Type/Referrer-Policy/Permissions-Policy
                 → OperationLog: фильтрация чувствительных полей + try-catch
Прикладной уровень → EncryptionService: транспортное шифрование AES-256-CBC + маскирование phone/email
                 → Повторное подтверждение пароля для чувствительных операций
Слой данных → Encryptable: автоматическое шифрование/дешифрование PII-полей (email/phone/id_card)
           → Пессимистичная блокировка строк (lockForUpdate) против параллельной перепродажи
           → Алгоритм скользящей средневзвешенной себестоимости (финансовая строгость)
Аутентификация → bcrypt-хеширование паролей + блокировка учётной записи (5 неудач / 15 минут)
Система ID → Распределённые ID Snowflake + внешняя обфускация Hashids
Комплаенс → security.txt (RFC 9116)
```

### 3.2 Правила обнаружения атак SecurityFilter

| Тип атаки | Число правил | Что обнаруживает |
|-----------|--------------|------------------|
| XSS | 5 | `<script>`, `on*=`, `javascript:`, `data:text/html`, `{{}}` |

### 3.3 Проблемы безопасности

#### ❌ P0-1 — Ключи по умолчанию не изменены

Ключи в `.env` остаются значениями по умолчанию; в продакшене обязательна замена:

| Переменная ключа | Значение по умолчанию |
|------------------|-----------------------|
| `JWT_SECRET_KEY` | `open-admin-jwt-secret-change-in-production` |
| `ENCRYPTION_KEY` | `open-admin-api-encryption-key32b` |
| `ENCRYPTABLE_KEY` | `open-admin-db-encryption-key-32b` |
| `HASHIDS_SALT` | `open-admin-hashids-salt-2026` |

**Ущерб**: атакующий может подделать JWT-токен, расшифровать данные API/БД.
**Исправление**: `openssl rand -hex 32` для генерации случайных 64-символьных ключей.

#### ❌ P0-2 — composer.lock игнорируется .gitignore

**Проблема**: разные среды устанавливают разные версии зависимостей, CI и прод расходятся. Composer официально рекомендует коммитить lock-файл.
**Исправление**: удалить `composer.lock` из `.gitignore` и закоммитить.

#### ⚠️ P1-1 — CSP использует `unsafe-inline`

```php
// app/middleware/Cors.php:36
'script-src \'self\' \'unsafe-inline\''
'style-src \'self\' \'unsafe-inline\''
```

Разрешает выполнение инлайн-скриптов/стилей, ослабляя защиту от XSS. Рекомендуется CSP nonce.

#### ⚠️ P1-2 — Сессии используют файловый драйвер

```php
// config/session.php
'type' => 'file'       // конкуренция за блокировки при мультипроцессе
'secure' => false      // в среде HTTPS должно быть включено
```

Рекомендуется в проде перейти на Redis, включить безопасные Cookie через `SESSION_SECURE=true`.

#### ⚠️ P1-3 — Отсутствует .dockerignore

Сейчас `COPY . .` упаковывает в образ `.env`, `runtime/`, `.git/` и т. п. Нужно создать `.dockerignore`.

#### ⚠️ P2 — CORS `Allow-Origin: *` + отключена аутентификация безопасности ES

- CORS-подстановочный знак разрешает доступ из любых источников
- В `docker-compose.yml` — `xpack.security.enabled: "false"`
