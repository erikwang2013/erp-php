## 1. Обзор

Поверх существующей базы системного управления `service/` расширить три бизнес-домена — закупки/продажи/склад, финансы, CRM — и построить полноценную ERP-систему.
Весь код развёртывается монолитно в `service/app/`, модули разделены по каталогам.

### 1.1 Этапное планирование

| Этап | Модули | Пояснение |
|------|------|------|
| Phase 1 | Базовые данные товаров + закупки + продажи + склад + финансы + CRM | Замкнутый цикл ключевого бизнеса |
| Phase 2 | Управление производством + управление проектами | Последующее расширение |

### 1.2 Технологический стек (продолжаем существующий)

- PHP 8.3+, webman v2, MySQL 8.0+
- Первичный ключ BIGINT генерируется snowflake-php
- ID на уровне API шифруются/дешифруются через hashids
- JWT-аутентификация, шифрование чувствительных данных — всё через пакеты серии erikwang2013/*
- Префикс таблиц `erp_`, мягкое удаление, глобальные функции без `\`

## 3. Перечень функций модулей

### 3.1 Товары и базовые данные

| Функция | Пояснение |
|------|------|
| Карточка товара | Название, код, штрих-код, категория (дерево), бренд, атрибуты спецификаций |
| Множественные SKU | Один товар с несколькими спецификациями, у каждой свой SKU, штрих-код, цена |
| Перевод единиц | Коэффициент пересчёта основная единица ↔ вспомогательная |
| Ценовые стратегии | Закупочная цена, оптовая цена, розничная цена, цена по уровню клиента |
| Управление категориями | Дерево категорий без ограничения уровней, поддержка сортировки перетаскиванием |
| Управление брендами | CRUD брендов |
| Управление складами | Несколько складов, на каждом складе несколько ячеек |
| Управление ячейками | Места хранения внутри склада, уникальный код |
| Карточка поставщика | Название, контакт, телефон, адрес, банковский счёт, налоговая ставка |
| Карточка клиента | Название, контакт, телефон, адрес, уровень клиента, кредитный лимит |

### 3.2 Модуль закупок

| Функция | Пояснение |
|------|------|
| Заявка на закупку | Отделы/сотрудники подают потребности в закупках, поддержка процесса согласования |
| Заказ на закупку | На основе заявки или напрямую, связывает поставщика, товары, количество, цену |
| Приёмка закупки | Приёмка по заказу, генерация приходной накладной, поддержка частичной приёмки |
| Возврат закупки | Возврат поставщику, генерация расходной накладной-сторно |
| Сверка с поставщиком | По поставщику+периоду времени сводка суммы закупок, оплачено, к оплате |
| Расчёт закупки | Зачёт приёмки закупки с платежами |

### 3.3 Модуль продаж

| Функция | Пояснение |
|------|------|
| Коммерческое предложение | Цитирование клиенту, поддержка конвертации в заказ на продажу |
| Заказ на продажу | Заказ клиента, связывает товары, количество, цену, скидку |
| Отгрузка продажи | Отгрузка по заказу, генерация расходной накладной, поддержка частичной отгрузки |
| Возврат продажи | Возврат клиентом, генерация приходной накладной-сторно |
| Сверка с клиентом | По клиенту+периоду времени сводка суммы продаж, получено, к получению |
| Расчёт продажи | Зачёт отгрузки продажи с поступлениями |
| Валовая прибыль продаж | Расчёт валовой прибыли по заказу/товару/клиенту |

### 3.4 Модуль склада

| Функция | Пояснение |
|------|------|
| Реальные остатки | Остатки по складу+ячейке+партии+SKU |
| Отслеживание партий | Дата производства, срок годности, номер партии |
| Отслеживание серийных номеров | Уникальные серийные номера, запись при приходе/расходе |
| Операции прихода/расхода | Единый журнал всех складских изменений (номер исходного документа+тип+количество+направление) |
| Перемещение остатков | Перемещение между складами/ячейками, генерация накладных перемещения прихода/расхода |
| Задачи инвентаризации | Плановая (по складу/категории) + динамическая (по SKU) |
| Разницы инвентаризации | Излишки/недостачи автоматически генерируют операции прихода/расхода |
| Предупреждения об остатках | Верхний/нижний предел по SKU+складу, сигнал ниже нижнего или выше верхнего |
| Калькуляция себестоимости | Метод скользящего средневзвешенного, при каждом приходе пересчёт себестоимости |

### 3.5 Модуль финансов

| Функция | Пояснение |
|------|------|
| Счета учёта | Дерево счетов (активы/обязательства/капитал/доходы/расходы), поддержка кастомизации |
| Дебиторка-кредиторка | Автогенерация из документов продаж/закупок, ручной зачёт |
| Приходный кассовый ордер | Поступления по нескольким счетам, нескольким способам (наличные/банк/WeChat/Alipay) |
| Расходный кассовый ордер | Платежи по нескольким счетам, нескольким способам |
| Зачёт | Приходный ордер зачитывает дебиторку, расходный ордер зачитывает кредиторку |
| Журнал наличных и банка | Запись операций доходов/расходов по счёту+дате |
| Возмещение расходов | Подача→согласование→выплата, связь со счётом учёта |
| Отчёт о прибылях и убытках | Помесячная сводка доходов/расходов/прибыли |

### 3.6 Модуль CRM

| Функция | Пояснение |
|------|------|
| Управление клиентами | Карточки клиентов (связаны с клиентами базовых данных) |
| Управление контактами | Несколько контактов одного клиента |
| Записи сопровождения | Способ, время, содержание, план следующего сопровождения |

## 6. Межмодульные потоки данных

```
Приёмка закупки → inventory_flow(приход) → inventory(+количество) → cost_record(пересчёт средней цены)
       → finance_ar_ap(кредиторка)

Отгрузка продажи → inventory_flow(расход) → inventory(-количество) → cost_record(фиксация себестоимости)
       → finance_ar_ap(дебиторка)

Зачёт приходного ордера → finance_ar_ap(обновление получено) → cash_journal(запись дохода)
Зачёт расходного ордера → finance_ar_ap(обновление оплачено) → cash_journal(запись расхода)

Разница инвентаризации → inventory_flow(приход излишка/расход недостачи) → inventory(корректировка)

Возмещение расходов (выплачено) → finance_payment(автогенерация) → cash_journal(запись расхода)
```

Способ реализации: после завершения каждой бизнес-операции через события запускаются последующие действия, без прямых межмодульных вызовов Service.

## 7. Экспорт Excel/PDF

- Все списковые страницы поддерживают параметр `?export=excel`, генерируется файл .xlsx со стилями
- Панели дашборда поддерживают `?export=pdf`, выводится PDF-отчёт с диаграммами
- Чувствительные поля (суммы, номера телефонов и т.д.) при экспорте маскируются через EncryptionService
- Переиспользуется существующий базовый класс ExportController, контроллеры модулей наследуют его и реализуют собственные определения колонок экспорта

## 8. Панели дашборда

| Панель | Маршрут | Показатели |
|------|------|------|
| Обзор бизнеса | `/admin/dashboard` | Сегодня/в этом месяце: сумма продаж, сумма закупок, дебиторка/кредиторка, общая стоимость запасов, валовая прибыль |
| Панель склада | `/admin/dashboard/inventory` | Список предупреждений, тренд прихода/расхода, занятость ячеек |
| Панель продаж | `/admin/dashboard/sales` | График тренда, рейтинг клиентов, хиты продаж, конверсия воронки |
| Финансовая панель | `/admin/dashboard/finance` | Тренд доходов/расходов, возраст дебиторки-кредиторки, денежный поток |

Данные кэшируются в Redis 5 минут, поддерживается переключение временного диапазона.
