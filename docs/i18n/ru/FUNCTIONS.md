# Открытая ERP-система — Функциональный мануал

> Copyright (c) 2026 erik <erik@erik.xyz> — https://erik.xyz

## Обзор

Открытая ERP-система (open-erp) охватывает 23 бизнес-домена <!-- stats:modules=23 -->, 227 таблиц данных <!-- stats:tables=227 --> и предоставляет полнофункциональную корпоративную систему управления: от закупок/продаж/склада до производства, от финансового учёта до управления персоналом. Интернационализация: поддержка 13 языков (`zh_CN`/`en`/`ja`/`ko`/`de`/`fr`/`es`/`pt`/`ru`/`ar`/`hi`/`bn`/`id`), автоматическое переключение по заголовку запроса `Accept-Language`.

> Документация API: после запуска сервиса откройте `http://localhost:8788/apidoc` для просмотра интерактивной документации интерфейсов (автогенерация erikwang2013/apidoc-php)

## 1. Системное управление

### 1.1 Управление пользователями
- Полный жизненный цикл учётных записей администраторов (создание/редактирование/удаление/включение-отключение)
- Массовые операции: массовое удаление, массовое включение/отключение
- Массовый импорт пользователей из Excel с построчной проверкой + отчётом об ошибках
- Пароли хранятся как bcrypt-хеш, смена пароля требует подтверждения старого
- Чувствительные операции (удаление и т.п.) требуют повторного подтверждения паролем текущего пользователя
- Телефон/email/ID-номер шифруются при хранении, в списках автоматически маскируются

### 1.2 Роли и права (RBAC)
- Управление ролями: создание/редактирование/удаление, уникальный идентификатор slug
- Дерево прав: неограниченная иерархия, три типа — меню (видимость в навигации), кнопки (операции на странице), API (доступ к интерфейсам)
- Формат идентификатора права: `{method}.{path}`, например `get.admin/product`, `post.admin/user/batch/destroy`
- Связь роли-права «многие ко многим», суперадминистратор пропускает все проверки прав
- Middleware AdminPermission кэширует права пользователя в Redis (TTL=60s)

### 1.3 Системная конфигурация
- Хранение пар «ключ-значение», поддержка группировки
- Типы значений: строка/целое/булево/JSON/массив

### 1.4 Аудит операций
- Автоматически записываются все операции POST/PUT/DELETE
- Фиксируются: оператор, действие, метод, путь, IP, параметры (чувствительные поля маскируются), время
- Автоматическое определение источника по 8 платформам (Web/Flutter/HarmonyOS/API и др.)
- Только чтение: удаление и изменение запрещены

### 1.5 Защита безопасности
- 7 уровней эшелонированной защиты: ограничение HTTP-методов, блокировка XSS/инъекций SQL/обхода путей/инъекций команд/CSRF
- Капча по клику (обязательная проверка при входе/регистрации)
- Ограничение частоты запросов скользящим окном Redis (атомарность Lua, по умолчанию 60 раз/мин)
- Блокировка аккаунта: 5 неудачных попыток — блокировка на 15 минут
- Ограничение параллельных сессий: максимум 3 действующих Token на пользователя
- Заголовок CSP, security.txt (RFC 9116)
- Случайная повторная проверка чувствительных операций (poster-php)

## 2. Товары и базовые данные

### 2.1 Управление товарами
- Карточка товара: код (уникальный), название, штрих-код, спецификация, базовая единица, изображение, описание
- Многовариантные SKU: несколько SKU у одного товара, у каждого свой код, штрих-код и атрибуты спецификации (JSON)
- Пересчёт единиц: коэффициент пересчёта между базовой и вспомогательной единицами
- Ценовые стратегии: закупочная цена, оптовая, розничная, цена по уровню клиента
- Поддержка полнотекстового поиска ES

### 2.2 Категории товаров
- Неограниченная иерархическая структура категорий
- Поддержка сортировки, включения/отключения
- Сортировка перетаскиванием

### 2.3 Управление брендами
- Название бренда, логотип, описание, сортировка

### 2.4 Склады и ячейки
- Управление несколькими складами (название, код, адрес, ответственный, контактный телефон)
- У каждого склада несколько ячеек (код уникален в пределах склада)

### 2.5 Управление поставщиками
- Код поставщика, название, контактное лицо, телефон/email (шифрование), адрес
- Банковские реквизиты (шифрование при хранении), ИНН, налоговая ставка
- Полнотекстовый поиск ES

### 2.6 Управление клиентами
- Код клиента, название, уровень клиента, кредитный лимит
- Контактное лицо/телефон/email (шифрование) / адрес
- Уровни клиентов: название, скидка по умолчанию
- Полнотекстовый поиск ES

## 3. Управление закупками

### 3.1 Заявка на закупку
- Подача потребностей отделами/сотрудниками
- Процесс согласования: на согласовании → одобрено/отклонено → конвертировано в заказ
- Подключается к движку workflow согласования

### 3.2 Заказ на закупку
- Привязка поставщика, позиции товаров (количество, цена, сумма)
- Статусы: на проверке → проверен → частично получен → получен → отменён
- Можно создать на основе заявки или напрямую

### 3.3 Приёмка закупок (связка между модулями)
- Приёмка по заказу, поддержка частями
- Приёмка автоматически запускает: ① оприходование на склад (расчёт по скользящему средневзвешенному) ② создание записи кредиторки ③ обновление полученного количества заказа

### 3.4 Возврат закупок
- Возврат поставщику, формирование стонирующей проводки списания

### 3.5 Расчёты с поставщиками
- Сводка по поставщику: сумма закупок, оплачено, к оплате
- Статусы: не рассчитано/частично рассчитано/рассчитано

## 4. Управление продажами

### 4.1 Коммерческое предложение
- Предложение клиенту, поддержка конвертации в заказ на продажу
- Статусы: черновик → предложено → конвертировано в заказ → недействительно

### 4.2 Заказ на продажу
- Привязка клиента, позиции товаров (количество, цена, скидка)
- Статусы: на проверке → проверен → частично отгружен → отгружен → отменён

### 4.3 Отгрузка продаж (связка между модулями)
- Отгрузка по заказу, поддержка частями
- Отгрузка автоматически запускает: ① списание со склада (по скользящему средневзвешенному) ② создание записи дебиторки ③ обновление отгруженного количества заказа

### 4.4 Возврат продаж
- Возврат от клиента, формирование стонирующей проводки прихода

### 4.5 Расчёты с клиентами и валовая прибыль
- Сводка по клиенту: сумма продаж, получено, к получению
- Расчёт валовой прибыли по осям: заказ/товар/клиент

### 4.6 Контроль кредитных лимитов клиентов (поставлено в v1.4.0)

- Управление кредитными лимитами: ведение лимита по клиенту, учёт использования и правила блокировки
- Блокировка до создания заказа/отгрузки: CreditControlService assertOrderCreate / assertDeliveryCreate / guard отклоняет заказы сверх лимита и возвращает причину

## 5. Управление складом

### 5.1 Реальные остатки
- Четырёхмерная точность: склад + ячейка + партия + SKU
- Поддержка нескольких складов и ячеек
- Запрос реальных остатков в реальном времени

### 5.2 Операции прихода/расхода
- Единая запись всех изменений остатков (направление, количество, себестоимость, номер исходного документа, время)

### 5.3 Отслеживание партий
- Дата производства, срок годности, номер партии
- Фиксация партий при приходе/расходе

### 5.4 Отслеживание серийных номеров
- Управление уникальными серийными номерами
- Фиксация статуса при приходе/расходе (на складе/отгружен)

### 5.5 Калькуляция себестоимости
- Метод скользящего средневзвешенного
- Формула: новая средняя цена = (старая стоимость остатка + стоимость текущего прихода) / (старое количество остатка + количество текущего прихода)
- Автоматический пересчёт при каждом приходе, списание по текущей средней цене

### 5.6 Перемещение запасов
- Перемещение между складами/ячейками
- Статусы: к перемещению → выбыло → поступило → завершено
- Автоматическое формирование операций выбытия/поступления

### 5.7 Инвентаризация
- Плановая инвентаризация (по складу/категории) + динамическая (по SKU)
- Фиксация «учётное vs фактическое» количество
- При расхождении автоматически формируются операции излишка/недостачи

### 5.8 Предупреждения об остатках
- Нижняя/верхняя границы по SKU+склад
- Автоматическая запись журнала предупреждений при выходе за границы

### 5.9 Прослеживаемость партий/серийных номеров и предупреждения об истечении срока (поставлено в v1.4.0)

- Цепочка прослеживания: TraceService forward/backward — прямая и обратная трассировка движения/источника партии, реестр серийных номеров serial
- Предупреждения о сроке: expiryAlert — напоминания по партиям с истекающим и истёкшим сроком

## 6. Управление финансами

### 6.1 Дебиторка/кредиторка
- Автогенерация из приёмки закупок/отгрузки продаж
- Статусы: не погашено → частично погашено → погашено
- Защита от повторного создания по одному исходному документу (идемпотентность)

### 6.2 Управление поступлениями
- Несколько счетов (наличные/банк/WeChat/Alipay)
- После проверки автоматически обновляется остаток счёта и кассовый журнал
- Поддержка зачёта записей дебиторки

### 6.3 Управление платежами
- Та же логика, что у поступлений, направление противоположное
- Поддержка зачёта записей кредиторки

### 6.4 Кассовый/банковский журнал
- Учёт операций прихода/расхода по счёту+дате
- Остаток банковского счёта обновляется в реальном времени

### 6.5 Возмещение расходов
- Процесс: подача → согласование → выплата
- После выплаты автоматически формируются платёжный документ + журнал

### 6.6 Отчёт о прибыли
- Сводка по месяцам: выручка, себестоимость, расходы, прибыль
- Хранение снимков (уникальность по year+month)

### 6.7 Основные средства
- Полный жизненный цикл актива: приобретение → использование → амортизация → выбытие
- Линейная амортизация: (первоначальная стоимость − остаточная) / срок в месяцах
- Ежемесячное начисление амортизации, автогенерация записей амортизации
- Фиксация: первоначальная стоимость, остаточная, срок службы, месячная амортизация, накопленная амортизация, балансовая стоимость

### 6.8 Налоговое управление
- Несколько видов налогов: НДС/налог на прибыль организаций/НДФЛ/гербовый сбор
- Гибкая настройка ставок (включая 4 налоговые ставки по умолчанию в seed-данных)
- Привязка к документам закупок/продаж, автоматический учёт сумм налогов

### 6.9 Мультивалюта
- Управление валютами: CNY/USD/EUR/JPY (включая 4 валюты по умолчанию в seed-данных)
- Признак функциональной валюты
- Управление курсами по дате вступления в силу

### 6.10 Бюджетирование
- Составление годового бюджета: по центру затрат + счёту + месяцу
- Сравнительный анализ бюджет vs факт (процент исполнения + отклонение)
- Статусы: черновик → согласован → исполняется → закрыт

### 6.11 Центры затрат / прибыли
- Иерархическая древовидная структура
- Сбор затрат + распределение расходов
- Раздельный учёт по центрам прибыли

### 6.12 Закрытие периода / учёт по нескольким организациям / консолидация отчётности (поставлено в v1.4.0)

- Закрытие периода по прибыли и убыткам: агрегация оборотов по статьям доходов и расходов за период (доходы − расходы = чистая прибыль, status=calculated)
- Закрытие не формирует проводки (нет настройки счёта нераспределённой прибыли и правил защиты от повторного закрытия), эндпоинтов контроллера нет — в поставку v1.4.0 не включено, оставлено в списке задач
- Учёт по нескольким организациям: CompanyController / LedgerPeriodController — независимые субъекты учёта и учётные периоды (поставлено в v1.4.0)
- Движок консолидированной отчётности (поставлено в v1.4.0): ConsolidationService rateToBase/translateLedger — пересчёт по курсу на конец периода (без курса отказывает), addElimination — взаимозачёт между дочерними компаниями (проверка баланса дебета и кредита), generateDraft — выпуск отчёта (для уже выпущенных периодов читается снимок, без снимка — пересчёт по утверждённым проводкам в реальном времени), issue — защита от повторного выпуска, latest/list; результат сохраняется в FinanceConsolidationReport
- Тесты: PeriodCloseServiceTest 4 кейса + ConsolidationServiceTest 3 кейса

### 6.13 Учёт запасов и себестоимости производства (поставлено в v1.4.0)

- Отпуск материалов в производство и сбор затрат: MaterialIssueController — списание материалов в производство с проводкой, CostEntryController + MfgCostService — сбор материалов/труда/накладных расходов по производственному заказу
- Правила проводок: MfgCostVoucherRule — проводка себестоимости готовой продукции и списания отклонений (связка с §12 «Производство»)

### 6.14 Векселя и сверка с банком (поставлено в v1.4.0)

- Полный жизненный цикл векселя: FinanceBillService store/update/endorse (индоссамент)/discount (дисконт)/collect (инкассо)/cash (оплата)/reject + dueWarnings — предупреждения о наступлении срока
- Сверка с банком: BankReconService importStatement — импорт выписки, autoReconcile/manualReconcile/unreconcile — сопоставление, reconReport — отчёт о сверке

### 6.15 Пул входящих счетов-фактур и электронные счета (поставлено в v1.4.0)

- Пул входящих: TaxInvoicePoolService registerOne/registerBatch/verify/check/deduct/deductStats; проверка идёт через MockTaxVerifier (точка адаптации — реальный канал налоговой службы)
- Электронные счета: EInvoiceService issueInvoice/voidInvoice/issueLogs, через EInvoiceAdapter/MockEInvoiceAdapter (точка адаптации — реальный канал налоговой службы)

## 8. Движок workflow согласования

### 8.1 Шаблоны workflow
- Настраиваемая цепочка согласования: разные процессы для разных типов документов
- Узлы согласования: последовательное, поддержка условной маршрутизации (по сумме, отделу и другим полям)
- Типы согласующего: конкретное лицо/роль/руководитель отдела/непосредственный начальник
- Поддержка отклонения, перенаправления

### 8.2 Операции согласования
- Подача → поэтапное согласование → утвердить/отклонить/отозвать
- Список «мои согласования» (на согласовании + согласованные)
- Полное отслеживание записей согласования

### 8.3 Визуальный конструктор процессов (поставлено в v1.4.0)

- Компоновка на полотне: WorkflowDesignerController читает и записывает определения узлов и связей (персистентность в canvas_json)
- Единый источник с движком согласования: после публикации цепочка согласования работает по определению с полотна

## 9. Система уведомлений

### 9.1 Управление уведомлениями
- Внутренние сообщения: статусы непрочитано/прочитано
- Шаблоны уведомлений: поддержка подстановки переменных (например, «У вас есть согласование от {заявителя} на рассмотрении»)

## Потоки данных между модулями

```
Приёмка закупок → автооприходование (скользящее средневзвешенное) → запись кредиторки
Отгрузка продаж → автосписание → запись дебиторки
Поступления/платежи → зачёт дебиторки/кредиторки → обновление журнала
Расхождения инвентаризации → автоформирование операций излишка/недостачи
Подача на согласование → маршрутизация workflow → поэтапное согласование → рассылка уведомлений
Выплата возмещения расходов → автоформирование платёжного документа + журнала
Амортизация активов → ежемесячное начисление → распределение затрат по центрам затрат
Расчёт MRP → развёртка BOM → расчёт чистой потребности → рекомендации закупок/производства
Согласование отпуска → после утверждения обновление статуса посещаемости
Завершение производства → автооприходование (готовой продукции) + списание сырья
Учёт трудозатрат → агрегация в задачи → в стоимость проекта
```

## 17. Складское хозяйство (WMS)

### 17.1 Зоны и ячейки
- **Зоны**: приёмка/хранение/комплектация/упаковка/отгрузка/возвраты/контроль качества
- **Расширение ячеек**: проход → стеллаж → ярус → ячейка, иерархия + штрих-код/вместимость/грузоподъёмность/порядок комплектации

### 17.2 Входящие потоки
- **ASN (авансовое извещение о прибытии)**: поставщик → ожидаемое прибытие → перевозчик → трек-номер
- **Задача приёмки**: приёмка на рампе → ввод фактического количества → контроль качества
- **Задача размещения**: автогенерация → назначение → стратегия (fifo/zone_fixed/abc) → подтверждение размещения (stockIn)

### 17.3 Исходящие потоки
- **Управление волнами**: агрегация нескольких заказов → волна комплектации/волна отгрузки → приоритет
- **Задача комплектации**: по заказу/пакетно/по зоне/по волне → назначение → подтверждение (фактическое количество)
- **Задача упаковки**: тип упаковки (box/bag/pallet) → вес/габариты

## 18. Управление транспортом (TMS)

### 18.1 Перевозчики
- Код/тип перевозчика (курьер/сборный груз/полная загрузка/авиа/морской/ж/д)
- Услуги перевозчика: standard/express/overnight/2day/economy + сроки
- Конфигурация API: абстракция custom/shippo/afterShip/17track

### 18.2 Управление тарифами
- **Тарифная карта**: пункт отправления/назначения → весовой интервал → базовый тариф/тариф за кг/топливная надбавка
- **Мультивалюта**: CNY/USD/EUR и др., привязка к exchange_rate
- **Сравнение тарифов**: по стране назначения + весу запрос всех доступных тарифов с сортировкой по возрастанию

### 18.3 Перевозочные документы и трекинг
- **Перевозочный документ**: услуга перевозчика → трек-номер → статус (к отгрузке → забран → в пути → доставлен/аномалия/возврат)
- **Трек логистики**: webhook-колбэк → автоматическая синхронизация статуса перевозочного документа
- **Счёт перевозчика**: создание → подтверждение → оплата → генерация кредиторки
