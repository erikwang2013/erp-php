## 1. Обзор системы

Открытая ERP-система (open-erp) — полнофункциональная корпоративная система планирования ресурсов на базе webman v2 + Flutter, охватывающая четырнадцать крупных бизнес-доменов: системное управление, закупки/продажи/склад, финансы, CRM, workflow согласования, уведомления, управление проектами, кадры, производство, пользовательские отчёты.

### 1.1 Цели дизайна
- Монолитное развёртывание, модульный дизайн
- Все ID генерируются через snowflake + шифруются при передаче через hashids
- Двухслойное шифрование чувствительных данных (транспортный слой AES-256-CBC + слой хранения AES-128-ECB)
- Калькуляция себестоимости по скользящему средневзвешенному
- Автоматическая связка между модулями (закупки→кредиторка, продажи→дебиторка, поступления-платежи→зачёт)

### 1.2 Технические ограничения
- PHP 8.3+, MySQL 8.0+, Redis 7, Elasticsearch 8
- Префикс таблиц erp_, первичный ключ BIGINT без автоинкремента
- Версия API задаётся заголовком запроса API-Version
- JWT-аутентификация + права RBAC
- Глобальные функции без префикса \

## 2. Модуль системного управления

### 2.1 Управление пользователями
- CRUD администраторов, массовое включение/отключение, массовое мягкое удаление
- Массовый импорт из Excel (построчная проверка + отчёт об ошибках)
- Пароли — bcrypt-хеш, смена пароля требует подтверждения старого
- Удаление требует повторного подтверждения паролем текущего пользователя
- Телефон/email/ID-номер хранятся в шифрованном виде, в списках автоматически маскируются

### 2.2 Роли и права (RBAC)
- CRUD ролей, уникальный идентификатор slug
- Дерево прав (неограниченная вложенность, parent_id самоссылка), типы: меню/кнопка/API
- Формат идентификатора права: {method}.{path} (например get.admin/product, post.admin/user/batch/destroy)
- Связь роль-право «многие ко многим»
- Суперадминистратор (super_admin) пропускает все проверки прав
- Middleware AdminPermission кэширует права в Redis (TTL=60s)

### 2.3 Системная конфигурация
- Хранение пар «ключ-значение», поддержка группировки
- Типы значений: string|int|bool|json|array

### 2.4 Аудит операций
- Автоматическая запись всех операций POST/PUT/DELETE
- Фиксация: оператор, действие, метод, путь, IP, параметры (чувствительные поля маскируются), время
- Автодетект источника по 8 платформам (Web/Flutter/HarmonyOS/API и др.)
- Только запросы, удаление/изменение запрещены

### 2.5 Защита безопасности
- 18 уровней эшелонированной защиты (подробности в SECURITY.md)
- SecurityFilter: ограничение HTTP-методов + блокировка XSS/SQL-инъекций/обхода путей/инъекций команд/CSRF
- RateLimit: лимит скользящим окном Redis (атомарность Lua, 60 раз/мин)
- Капча по клику (обязательна при входе/регистрации)
- Блокировка аккаунта: 5 неудач — блокировка на 15 минут
- Ограничение параллельных сессий: максимум 3 Token у одного пользователя
- Заголовок CSP, security.txt (RFC 9116)
- poster-php — случайная повторная проверка чувствительных операций

## 3. Товары и базовые данные

### 3.1 Управление товарами
- Карточка товара: код (уникальный), название, штрих-код, спецификация, базовая единица, изображение, описание
- Многовариантные SKU: несколько SKU у одного товара, у каждого свой код, штрих-код и атрибуты спецификации (JSON)
- Пересчёт единиц: базовая единица ↔ вспомогательная, коэффициент пересчёта
- Ценовые стратегии: закупочная, оптовая, розничная, цена по уровню клиента
- Категории товаров: неограниченная древовидная структура, сортировка перетаскиванием
- Управление брендами: название бренда, логотип, описание

### 3.2 Склады и ячейки
- Управление несколькими складами (название, код, адрес, ответственный)
- У каждого склада несколько ячеек (код уникален в пределах склада)
- Контактный телефон склада хранится в шифрованном виде

### 3.3 Поставщики/клиенты
- Карточка поставщика: код, название, контактное лицо, телефон/email (шифрование), адрес, банковские реквизиты
- Карточка клиента: код, название, уровень клиента, кредитный лимит
- Уровни клиентов: название, скидка по умолчанию
- Поставщики/клиенты поддерживают полнотекстовый поиск ES

## 4. Модуль закупок

### 4.1 Процесс закупок
Заявка → согласование → заказ → приёмка → расчёт

### 4.2 Заявка на закупку
- Подача потребностей отделами/сотрудниками
- Статусы: на согласовании → одобрено/отклонено → конвертировано в заказ
- Поддержка действий согласующего

### 4.3 Заказ на закупку
- Привязка поставщика, позиции товаров (количество, цена, сумма)
- Статусы: на проверке → проверен → частично получен → получен → отменён
- Можно создать на основе заявки или напрямую

### 4.4 Приёмка закупок (связка между модулями)
- Приёмка по заказу, поддержка частичной приёмки
- При приёмке автоматически запускается:
  1. InventoryService.stockIn() → обновление реальных остатков + пересчёт скользящего средневзвешенного
  2. FinanceService.createAp() → формирование записи кредиторки
  3. Обновление полученного количества и статуса заказа
- Поддержка фиксации ячейки и номера партии

### 4.5 Возврат закупок
- Возврат поставщику, формирование стонирующей проводки списания
- Привязка к приёмке

### 4.6 Расчёты с поставщиками
- Сводка по поставщику: сумма закупок, оплачено, к оплате
- Статус расчёта: не рассчитано/частично рассчитано/рассчитано

## 5. Модуль продаж

### 5.1 Процесс продаж
Предложение → заказ → отгрузка → расчёт

### 5.2 Коммерческое предложение
- Предложение клиенту, поддержка конвертации в заказ на продажу
- Статусы: черновик → предложено → конвертировано в заказ → недействительно

### 5.3 Заказ на продажу
- Привязка клиента, позиции товаров (количество, цена, скидка)
- Статусы: на проверке → проверен → частично отгружен → отгружен → отменён
- Поддержка суммы скидки

### 5.4 Отгрузка продаж (связка между модулями)
- Отгрузка по заказу, поддержка частичной отгрузки
- При отгрузке автоматически запускается:
  1. InventoryService.stockOut() → списание остатков (по скользящему средневзвешенному)
  2. FinanceService.createAr() → формирование записи дебиторки
  3. Обновление отгруженного количества и статуса заказа

### 5.5 Возврат продаж
- Возврат от клиента, формирование стонирующей проводки прихода

### 5.6 Расчёты с клиентами и валовая прибыль
- Сводка по клиенту: сумма продаж, получено, к получению
- Валовая прибыль продаж: расчёт по осям заказ/товар/клиент

## 6. Модуль склада

### 6.1 Управление складом
- Реальные остатки: четырёхмерная точность склад+ячейка+партия+SKU
- Операции прихода/расхода: единая запись всех изменений остатков (направление, количество, себестоимость, номер исходного документа)
- Отслеживание партий: дата производства, срок годности
- Отслеживание серийных номеров: уникальный серийный номер, фиксация статуса при приходе/расходе (на складе/отгружен)

### 6.2 Калькуляция себестоимости
- Метод скользящего средневзвешенного
- Формула: новая средняя цена = (старая стоимость остатка + стоимость текущего прихода) / (старое количество остатка + количество текущего прихода)
- Автоматический пересчёт при каждом приходе, списание по текущей средней цене
- Полная цепочка записей себестоимости (средняя цена до изменения → средняя цена после изменения)

### 6.3 Перемещение запасов
- Перемещение между складами/ячейками
- Статусы: к перемещению → выбыло → поступило → завершено
- Автоматическое формирование операций прихода/расхода выбытия и поступления

### 6.4 Инвентаризация
- Плановая инвентаризация (по складу/категории) + динамическая (по SKU)
- Фиксация учётного количества vs фактического
- При расхождении автоматически формируются операции излишка/недостачи

### 6.5 Предупреждения об остатках
- Нижняя/верхняя границы по SKU+склад
- Автоматическая запись журнала предупреждений при выходе за границы

## 7. Модуль финансов

### 7.1 План счетов
- Дерево счетов: пять групп — активы/обязательства/капитал/доходы/расходы
- Код счёта уникален
- Направление остатка: дебет/кредит

### 7.2 Учётные документы (проводки)
- Номер документа, дата, содержание
- Двойная запись: каждая проводка содержит дебетовую и кредитовую сумму (дебет обязательно равен кредиту)
- Статусы: черновик → проверен

### 7.3 Главная книга
- Сводка по счёту + учётному периоду (год/месяц)
- Фиксация: входящий дебетовый/кредитовый остаток, обороты периода по дебету/кредиту, исходящий дебетовый/кредитовый остаток
- Исходящий остаток = входящий остаток ± обороты периода (в зависимости от направления остатка счёта)
- Автообновление после проверки документа
- Фильтр по году/месяцу/счёту

### 7.4 Аналитика (субкнига)
- Построчная фиксация каждой проводки указанного счёта
- Включает: номер документа, направление (дебет/кредит), сумму, остаток, содержание, дату
- Запрос по счёту + диапазону дат
- Синхронное обновление с проводками

### 7.5 Баланс
- Формирование по учётному периоду (месяц/год)
- Автоматическая сводка остатков главной книги:
  - Счета активов (1) → итого активов = оборотные активы + внеоборотные активы
  - Счета обязательств (2) → итого обязательств = краткосрочные + долгосрочные
  - Счета капитала (3) → собственный капитал
  - Тождество: активы = обязательства + собственный капитал
- Поддержка сохранения снимка (полные данные JSON)
- При отсутствии снимка — автогенерация из главной книги

### 7.6 Отчёт о движении денежных средств
- Формирование по учётному периоду (месяц/год)
- Три категории:
  - Денежные потоки от операционной деятельности (поступления от продаж − платежи за закупки − расходы)
  - Денежные потоки от инвестиционной деятельности
  - Денежные потоки от финансовой деятельности
- Входящий/исходящий остаток денежных средств = сумма входящих/исходящих остатков всех банковских счетов
- Автогенерация из сводки кассового/банковского журнала
- Поддержка сохранения снимка (полные данные JSON)

### 7.7 Дебиторка/кредиторка
- Автогенерация из приёмки закупок/отгрузки продаж
- Дебиторка: тип=дебиторская, привязка клиента, источник=документ отгрузки продаж
- Кредиторка: тип=кредиторская, привязка поставщика, источник=документ приёмки закупок
- Статусы: не погашено → частично погашено → погашено
- По одному исходному документу повторная генерация запрещена (защита идемпотентности)

### 7.8 Управление поступлениями
- Несколько счетов (наличные/банк/WeChat/Alipay)
- После проверки автоматически обновляется остаток банковского счёта и кассовый журнал
- Зачёт: выбор записей дебиторки, ввод суммы зачёта (не более непогашенного остатка)
- Автоматический переход статуса частичного погашения

### 7.9 Управление платежами
- Та же логика, что у поступлений, направление противоположное
- Зачёт записей кредиторки

### 7.10 Кассовый/банковский журнал
- Построчная фиксация каждой операции прихода/расхода по счёту + дате
- Фиксация остатка после изменения
- Остаток банковского счёта обновляется в реальном времени

### 7.11 Возмещение расходов
- Процесс: подача → согласование → выплата
- Привязка счёта расходов
- После выплаты автоматически формируются платёжный документ + журнал

### 7.12 Отчёт о прибыли
- Сводка по месяцам: выручка, себестоимость, расходы, прибыль
- Хранение снимков данных (year+month уникальны)

### 7.13 Амортизация основных средств
- Управление полным жизненным циклом актива: приобретение → использование → амортизация → выбытие
- Метод амортизации: линейный ((первоначальная стоимость − остаточная) / срок в месяцах)
- Ежемесячное начисление амортизации, автогенерация записей амортизации
- Фиксация: первоначальная стоимость, остаточная, срок службы, месячная амортизация, накопленная амортизация, балансовая стоимость

### 7.14 Налоговое управление
- Поддержка нескольких видов налогов: НДС/налог на прибыль организаций/НДФЛ/гербовый сбор
- Гибкая настройка ставок
- Привязка к документам закупок/продаж, автоматический учёт сумм налогов

### 7.15 Мультивалюта
- Управление валютами: CNY/USD/EUR/JPY и др.
- Признак функциональной валюты
- Управление курсами по дате вступления в силу
- Поддержка пересчёта иностранной валюты

### 7.16 Бюджетирование
- Составление годового бюджета: по центру затрат + счёту + месяцу
- Сравнительный анализ бюджет vs факт
- Расчёт процента исполнения + анализ отклонений
- Статусы: черновик → согласован → исполняется → закрыт

### 7.17 Центры затрат/прибыли
- Древовидная иерархическая структура
- Сбор затрат + распределение расходов
- Раздельный учёт по центрам прибыли

## 8. Модуль CRM

### 8.1 Управление клиентами
- Карточка клиента связана с клиентом из базовых данных
- У клиента несколько контактных лиц (отметка основного)
- Телефон/email контактов хранятся в шифрованном виде

### 8.2 История контактов
- Способы контакта: телефон/визит/email/сообщение/другое
- Фиксация содержания контакта, плана следующего контакта, времени следующего контакта
- Привязка клиента, контактного лица, сделки

### 8.3 Маркетинговые кампании
- Полный жизненный цикл: планирование → выполняется → завершена → отменена
- Многоканальность: email/СМС/телефон/мероприятия/соцсети
- Отслеживание участников, статистика конверсии
- Сравнение бюджета vs фактических затрат

### 8.4 Сервисные тикеты
- Управление тикетами: к обработке → обрабатывается → решён → закрыт
- Приоритет: низкий/средний/высокий/срочный
- Категории: техподдержка/жалоба/консультация/возврат-обмен/другое
- Назначение исполнителя + ответы (публичные/внутренние заметки)
- Статистика доли решённых

### 8.5 Аналитические отчёты по клиентам
- 6 ключевых метрик: новые клиенты/активные клиенты/удержание/средний чек/CLV/доля решённых тикетов
- Автогенерация отчётов (снимки данных JSON)
- Поддержка месяца/квартала/года

### 8.6 Воронка продаж
- Настройка этапов: первичный контакт (10%) → подтверждение потребности (30%) → предложение и решение (50%) → коммерческие переговоры (70%) → сделка (100%) → проигрыш (0%)
- Сделка: клиент, текущий этап, прогнозная сумма, вероятность сделки, прогнозная дата закрытия, ответственный
- Статус сделки: проиграна/в работе/заключена
- Отслеживание перехода по этапам

### 8.7 Общий пул клиентов
- Общий пул клиентов: клиенты без закреплённого владельца или не получавшие контактов дольше установленного срока автоматически попадают в пул
- Правило возврата: по уровню клиента задаётся число дней без контактов до автоматического возврата
- Ограничение максимального числа клиентов в личном владении, защита от оседания ресурсов
- Операции взятия/освобождения/возврата фиксируются в журнале
- Повышает активность отдела продаж, предотвращает оседание клиентов

### 8.8 Предложения в CRM
- Внутренний процесс предложений CRM, независимый от модуля продаж
- Статусы: черновик → отправлено → подтверждено клиентом → конвертировано в договор → недействительно
- Поддержка срока действия предложения
- Поддержка прямой конвертации в договор (`to-contract`)
- Привязка клиента и сделки

### 8.9 Управление договорами
- Полный жизненный цикл: черновик → на согласовании → согласован → исполняется → завершён/расторгнут
- Привязка клиента, сделки, предложения
- Позиции договора: товар/количество/цена/сумма
- Фиксация даты подписания, дат начала/окончания
- Текст условий договора (большое поле TEXT)
- Назначение ответственного

## 9. Модуль workflow согласования

### 9.1 Определение workflow
- Название, описание, применяемый модуль
- Конфигурация цепочки согласования из нескольких узлов
- Каждый узел задаёт согласующего/роль согласования, стратегию (единогласное/любое)

### 9.2 Процесс согласования
- Подача бизнес-документа на согласование → автоматическое создание экземпляра согласования
- Переход по предопределённым узлам, каждый согласующий обрабатывает по очереди
- Операции согласования: подача (инициируется из бизнес-модуля), утверждение, отклонение, отзыв
- Результат согласования колбэком обновляет статус документа в бизнес-модуле
- Список «мои согласования»: на согласовании/согласованные

### 9.3 Записи согласования
- Полное отслеживание цепочки: каждый шаг фиксирует согласующего, операцию, мнение, время
- Экземпляр согласования связан с номером бизнес-документа

## 10. Модуль уведомлений

### 10.1 Управление уведомлениями
- Список уведомлений: обратный хронологический порядок, постраничный вывод
- Типы уведомлений: о согласовании, системные объявления, бизнес-предупреждения
- Отметка прочитанного: по одному / всё прочитано
- Счётчик непрочитанных: количество непрочитанных сообщений в реальном времени

### 10.2 Шаблоны уведомлений
- Предопределённые шаблоны (заголовок + плейсхолдеры содержимого)
- Категории шаблонов: согласование/предупреждение/системные
- Настройки уведомлений: предпочтения каналов по пользователю

### 10.3 Сервис уведомлений
- Единый интерфейс отправки NotificationService
- Поддержка расширения несколькими каналами (внутренние сообщения/email/СМС/WebSocket)

## 11. Модуль управления проектами

### 11.1 Управление проектами
- CRUD проектов: название, описание, статус, даты начала/окончания, ответственный
- Статусы проекта: планируется → выполняется → завершён → архивирован
- Управление участниками: добавление/удаление участников проекта

### 11.2 Управление задачами
- CRUD задач: заголовок, описание, приоритет, статус, срок
- Привязка к проекту, поддержка родительских/дочерних задач
- Статусы задач: к началу → выполняется → завершена → закрыта
- Назначение задач: указание ответственного

### 11.3 Учёт трудозатрат
- Ввод трудозатрат по задаче: дата, длительность, описание
- Сводка статистики трудозатрат по проекту

## 12. Модуль управления персоналом

### 12.1 Организационная структура
- Управление отделами: древовидная структура, название отдела, код, руководитель, родительский отдел
- Управление должностями: название, код, отдел, статус

### 12.2 Управление сотрудниками
- Карточка сотрудника: код, ФИО, пол, телефон (шифрование), email (шифрование), дата приёма, отдел, должность
- Статусы: в штате/уволен
- Привязка учётной записи системного пользователя

### 12.3 Учёт посещаемости
- Отметки: приход, уход, фиксация времени
- Запрос посещаемости: по сотруднику + диапазону дат
- Правила посещаемости: рабочее время, пороги опоздания/раннего ухода

### 12.4 Управление отпусками
- CRUD отпусков: тип (по семейным обстоятельствам/больничный/ежегодный и др.), период, причина
- Процесс согласования: подача → согласование руководителем отдела → одобрено/отклонено
- Статусы: на согласовании → одобрен → отклонён

### 12.5 Управление зарплатами
- Статьи зарплаты: оклад/премия/надбавки/вычеты и др., способ расчёта
- Выплата зарплаты: ежемесячное формирование расчётного листа, привязка сотрудника
- Статус выплаты: к выдаче → выдано

## 13. Модуль производства

### 13.1 BOM (спецификация материалов)
- Определение BOM: родительский продукт, дочерние материалы, норма расхода, единица, операции
- Уровни BOM: поддержка многоуровневого развёртывания
- Управление версиями: история редакций BOM

### 13.2 Производственные заказы
- CRUD производственных заказов: продукт, плановое количество, плановые даты начала/окончания
- Статусы: к производству → производится → завершён → закрыт
- Операции запуска/завершения: фиксация фактического времени начала/окончания
- Производственные позиции: ведомость получения материалов (развёртка BOM)

### 13.3 Технологические маршруты
- Определение маршрута: продукт, последовательность операций, нормативное время каждой операции
- Привязка BOM и рабочих центров

### 13.4 Рабочие центры
- CRUD рабочих центров: название, код, тип, мощность, статус
- Привязка операций маршрута

### 13.5 MRP (планирование потребностей в материалах)
- План MRP: расчёт потребностей в материалах на основе заказов на продажу/производственных планов + BOM
- Автогенерация рекомендаций по закупкам (при нехватке сырья) и по производству (при нехватке полуфабрикатов)
- Детали MRP: материал, валовая потребность, доступный остаток, чистая потребность, рекомендуемый объём заказа
- Статусы плана: черновик → сформирован → выданы рекомендации закупок/производства

## 14. Модуль пользовательских отчётов

### 14.1 Определение отчёта
- CRUD шаблонов отчётов: название, описание, набор данных, поля, условия фильтрации, тип диаграммы
- Набор данных: предопределённый SQL-запрос или метод модели
- Поля отчёта: имя колонки, отображаемое имя, тип данных, сортировка
- Фильтры: поле, оператор, значение по умолчанию

### 14.2 Выполнение отчёта
- Выполнение отчёта с генерацией данных: применение условий фильтрации, сортировка, пагинация
- Отображение результата: таблица или диаграмма (рендер через фронтенд)
- Поддержка экспорта

### 14.3 Планировщик
- Плановые задачи отчётов: указанный отчёт, частота выполнения (cron), получатели
- Статус планировщика: включён/выключен
- Запрос истории выполнения

## 16. Интернационализация (i18n)

### 16.1 Автодетект языка
- Автоматическое распознавание заголовка запроса `Accept-Language` (zh-CN → китайский, en → английский)
- Middleware Locale выполняется первым в глобальной цепочке middleware
- Цепочка отката: текущий язык → настроенный fallback_locale → возврат исходного ключа

### 16.2 Файлы переводов
- Каталог: `resource/translations/{locale}/`
- Общие сообщения: `common.php` (41 ключ: успех/ошибка/создание/обновление/удаление/валидация и др.)
- Названия модулей: `modules.php` (69 ключей: товары/закупки/продажи/склад/финансы/CRM и др.)
- Правила валидации: `validation.php` (11 правил + 10 меток полей)

### 16.3 Использование
- В контроллере: `$this->trans('created')`
- Глобальные функции: `__('modules.product')`, `__m('finance')`
- Названия модулей: `__('modules.product')` → товары / Product

## 17. Экспорт

### 17.1 Экспорт Excel
- Все страницы списков поддерживают ?export=excel
- PhpSpreadsheet формирует .xlsx
- Шапка белым по синему + закрепление первой строки + автоширина колонок
- Чувствительные поля автоматически маскируются

### 17.2 Экспорт PDF
- Панели данных дашбордов поддерживают ?export=pdf
- Рендер Dompdf, A4 альбомный
- Неудаляемая информация об авторских правах
