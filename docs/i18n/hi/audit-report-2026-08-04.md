## 三、सुरक्षा सुरक्षा मूल्यांकन

### 3.1 लागू सुरक्षा उपाय ✅

```
नेटवर्क परत   → Nginx: रेट लिमिट/अनुरोध बॉडी सीमा/कनेक्शन सीमा/सुरक्षा हेडर/संवेदनशील फ़ाइल प्रतिबंध
मिडलवेयर परत → SecurityFilter: XSS/SQLi/पाथ ट्रैवर्सल/कमांड इंजेक्शन/दुर्भावनापूर्ण फ़ाइल पहचान/CSRF(Origin सत्यापन)
         → RateLimit: Lua एटॉमिक स्लाइडिंग विंडो (डिफ़ॉल्ट 60 बार/मिनट, लॉगिन 10, रजिस्टर 5)
         → AdminAuth: JWT प्रमाणीकरण+ब्लैकलिस्ट+सत्र सीमा (अधिकतम 3 Token)
         → AdminPermission: RBAC method.path प्रमाणीकरण (60s कैश)
         → Cors: CSP/X-Frame/X-Content-Type/Referrer-Policy/Permissions-Policy
         → OperationLog: संवेदनशील फ़ील्ड फ़िल्टर+try-catch
एप्लिकेशन परत → EncryptionService: AES-256-CBC ट्रांसमिशन एन्क्रिप्शन+phone/email मास्किंग
         → संवेदनशील ऑपरेशन द्वितीय पासवर्ड पुष्टि
डेटा परत   → Encryptable: PII फ़ील्ड स्वचालित एन्क्रिप्ट/डिक्रिप्ट (email/phone/id_card)
         → पेसिमिस्टिक रो लॉक (lockForUpdate) समवर्ती ओवरसेल रोकथाम
         → मूविंग वेटेड एवरेज लागत एल्गोरिदम (लेखा-स्तरीय सटीकता)
प्रमाणीकरण     → bcrypt पासवर्ड हैश+खाता लॉक (5 विफलताएँ/15 मिनट)
ID प्रणाली   → Snowflake वितरित ID + Hashids बाहरी ऑब्स्क्यूरेशन
अनुपालन     → security.txt (RFC 9116)
```

### 3.2 SecurityFilter हमला पहचान नियम

| हमला प्रकार | नियम संख्या | पहचान सामग्री |
|----------|--------|----------|
| XSS | 5 | `<script>`, `on*=`, `javascript:`, `data:text/html`, `{{}}` |
| SQL इंजेक्शन | 6 | UNION SELECT, OR 1=1, DROP/ALTER/TRUNCATE, सिस्टम तालिका प्रोबिंग |
| पाथ ट्रैवर्सल | 3 | `../`, `/etc/passwd`, `%00` |
| कमांड इंजेक्शन | 4 | shell मेटाकैरेक्टर+खतरनाक कमांड, बैकटिक, `$()` |
| दुर्भावनापूर्ण अपलोड | 2 | डबल एक्सटेंशन (.php.png), .php अंत |

हमला एस्केलेशन तंत्र: एक ही IP 5 बार/60s ट्रिगर → अस्थायी ब्लैकलिस्ट 15 मिनट।

### 3.3 सुरक्षा समस्याएँ

#### ❌ P0-1 — डिफ़ॉल्ट कुंजियाँ संशोधित नहीं

`.env` में कुंजियाँ अभी भी डिफ़ॉल्ट मान हैं, उत्पादन में बदलना अनिवार्य:

| कुंजी चर | डिफ़ॉल्ट मान |
|----------|--------|
| `JWT_SECRET_KEY` | `open-admin-jwt-secret-change-in-production` |
| `ENCRYPTION_KEY` | `open-admin-api-encryption-key32b` |
| `ENCRYPTABLE_KEY` | `open-admin-db-encryption-key-32b` |
| `HASHIDS_SALT` | `open-admin-hashids-salt-2026` |

**नुकसान**: हमलावर JWT Token जाली बना सकता है, API/डेटाबेस डेटा डिक्रिप्ट कर सकता है।  
**मरम्मत**: `openssl rand -hex 32` से 64-वर्ण यादृच्छिक कुंजी बनाएँ।

#### ❌ P0-2 — composer.lock .gitignore द्वारा अनदेखा

**समस्या**: विभिन्न वातावरण अलग-अलग संस्करण की निर्भरताएँ स्थापित करते हैं, CI और उत्पादन असंगत। Composer आधिकारिक रूप से lock फ़ाइल सबमिट करने की सलाह देता है।  
**मरम्मत**: `.gitignore` से `composer.lock` हटाकर सबमिट करें।

#### ⚠️ P1-1 — CSP `unsafe-inline` उपयोग करता है

```php
// app/middleware/Cors.php:36
'script-src \'self\' \'unsafe-inline\''
'style-src \'self\' \'unsafe-inline\''
```

इनलाइन स्क्रिप्ट/स्टाइल निष्पादन की अनुमति देता है, XSS सुरक्षा कमजोर करता है। CSP nonce अपनाने की सलाह।

#### ⚠️ P1-2 — Session फ़ाइल ड्राइवर उपयोग

```php
// config/session.php
'type' => 'file'       // मल्टी-प्रोसेस में लॉक प्रतिस्पर्धा
'secure' => false      // HTTPS वातावरण में चालू करना चाहिए
```

उत्पादन में Redis पर स्विच करने की सलाह, `SESSION_SECURE=true` से सुरक्षित Cookie चालू करें।

#### ⚠️ P1-3 — .dockerignore अनुपलब्ध

वर्तमान `COPY . .` `.env`, `runtime/`, `.git/` आदि को इमेज में पैक करता है। `.dockerignore` बनाना आवश्यक।

#### ⚠️ P2 — CORS `Allow-Origin: *` + ES सुरक्षा प्रमाणीकरण अक्षम

- CORS वाइल्डकार्ड किसी भी ओरिजिन को पहुंच की अनुमति देता है
- `docker-compose.yml` में `xpack.security.enabled: "false"`
