## ERP मॉड्यूल

विभिन्न व्यावसायिक मॉड्यूलों के बीच डेटा प्रवाह:

- क्रय प्राप्ति → स्वतः इनबाउंड (मूविंग वेटेड एवरेज लागत गणना) → स्वतः देय उत्पन्न
- विक्रय डिलीवरी → स्वतः आउटबाउंड → स्वतः प्राप्य उत्पन्न
- प्राप्ति/भुगतान → प्राप्य/देय समायोजन → जर्नल अपडेट
- वाउचर अनुमोदन → स्वतः सामान्य खाता बही (खाता सारांश) + विवरण खाता बही (पंक्ति-दर-पंक्ति रिकॉर्ड) अपडेट
- बैलेंस शीट → सामान्य खाता बही के अंतिम शेष को स्वतः संकलित करके उत्पन्न
- कैश फ्लो स्टेटमेंट → नकद/बैंक जर्नल को स्वतः संकलित करके उत्पन्न (संचालन/निवेश/वित्तपोषण तीन श्रेणियां)
- अनुमोदन वर्कफ़्लो → व्यावसायिक दस्तावेज़ अनुमोदन हेतु सबमिट → बहु-नोड प्रवाह → अनुमोदन परिणाम व्यावसायिक मॉड्यूल को कॉलबैक
- संदेश अधिसूचना → अनुमोदन/अलर्ट/सिस्टम घटनाओं से ट्रिगर → रीयल-टाइम पुश → उपयोगकर्ता द्वारा पठित चिह्नित
- MRP → विक्रय आदेश + BOM पर आधारित → सामग्री आवश्यकता गणना → क्रय सुझाव/उत्पादन सुझाव उत्पन्न
- OMS → मल्टी-चैनल ऑर्डर आयात → स्टॉक रिज़र्वेशन (ATP) → फ़ुलफ़िलमेंट निर्माण → WMS पिकिंग/पैकिंग जारी
- WMS → वेव एकत्रीकरण → पिकिंग कार्य → पिकिंग पुष्टि → पैकिंग पूर्ण → TMS शिपमेंट ट्रिगर
- TMS → फ्रेट मूल्य तुलना → शिपमेंट निर्माण → डिलीवरी पुष्टि (stockOut+AR) → लॉजिस्टिक्स ट्रैकिंग → हस्ताक्षर प्राप्ति
- WMS इनबाउंड → ASN पूर्व-आगमन → प्राप्ति → गुणवत्ता निरीक्षण → पुटअवे पुष्टि (stockIn+AP) → स्टॉक अपडेट
- RMA → वापसी अनुरोध → अनुमोदन → वापसी इनबाउंड → रिफंड

## सिस्टम आर्किटेक्चर आरेख

> पूर्ण आकार देखने के लिए छवि पर क्लिक करें। आरेख अंग्रेज़ी नामों का उपयोग करते हैं, सिस्टम के सभी स्तरों के आर्किटेक्चर डिज़ाइन को पूर्ण और स्पष्ट रूप से प्रदर्शित करते हैं।

## डेटाबेस मानदंड

- **टेबल उपसर्ग**: `erp_`
- **प्राथमिक कुंजी**: सभी तालिकाओं की प्राथमिक कुंजी `id BIGINT UNSIGNED NOT NULL` है, **AUTO_INCREMENT निषिद्ध**
- **ID जनरेशन**: प्राथमिक कुंजी ID एप्लिकेशन परत में `SnowflakeService::generate()` से उत्पन्न होती है, वितरित रूप से अद्वितीय
- **अनिवार्य फ़ील्ड**: प्रत्येक तालिका में `id`, `created_at`, `updated_at` होना चाहिए
- **सॉफ्ट डिलीट**: सॉफ्ट डिलीट आवश्यकता वाली तालिकाओं में `deleted_at DATETIME DEFAULT NULL` जोड़ें
- **संवेदनशील फ़ील्ड**: फोन नंबर, ईमेल, पहचान पत्र नंबर आदि `encryptable` प्लगइन से स्वतः एन्क्रिप्ट/डिक्रिप्ट होते हैं, डेटाबेस फ़ील्ड सिफरटेक्स्ट को `VARCHAR(500)` में संग्रहीत करती है

### व्यावसायिक त्रुटि कोड

| त्रुटि कोड | अर्थ | विवरण |
|-------|------|------|
| `0` | सफल | |
| `400` | अनुरोध पैरामीटर त्रुटि | |
| `401` | लॉगिन नहीं (टोकन अमान्य या समाप्त) | |
| `403` | कोई अनुमति नहीं / सुरक्षा अवरोध | RBAC प्रमाणीकरण विफल / SecurityFilter हमले की पहचान |
| `404` | संसाधन मौजूद नहीं | |
| `422` | पैरामीटर सत्यापन विफल | |

| `405` | अनुरोध विधि अनुमत नहीं | SecurityFilter ट्रिगर, केवल GET/POST/PUT/DELETE/OPTIONS/HEAD |

| `500` | सर्वर आंतरिक त्रुटि | |

### अंतर्राष्ट्रीयकरण

अनुरोध हेडर `Accept-Language` स्वतः भाषा बदलता है (zh-CN → चीनी, en → English), डिफ़ॉल्ट चीनी।

### ID प्रसंस्करण

- **अनुरोध/प्रतिक्रिया में ID**: hashids से एन्क्रिप्ट करके स्ट्रिंग बनती है, वास्तविक डेटाबेस ID उजागर नहीं होती
- **इंटरफ़ेस पथ**: `GET /admin/user/{hashid}` — पथ में `{id}` hashid स्ट्रिंग है
- **डेटाबेस भंडारण**: BIGINT मूल मान, snowflake से उत्पन्न

### API संस्करण

API संस्करण अनुरोध हेडर से नियंत्रित होता है, **URL में दिखाई नहीं देता**:

```http
API-Version: v1
```

- संस्करण नंबर नहीं होने पर डिफ़ॉल्ट `v1` उपयोग होता है
- असमर्थित संस्करण पर `400 Bad Request` लौटता है
- नया संस्करण जोड़ने के लिए केवल `app/api/{version}/controller/` निर्देशिका बनाएँ, मिडलवेयर में नया संस्करण पंजीकृत करें

### रेट लिमिट

Redis स्लाइडिंग विंडो एल्गोरिदम पर आधारित, डिफ़ॉल्ट 60 बार/मिनट/IP/रूट। संवेदनशील इंटरफ़ेस अधिक सख्त:
- लॉगिन: 10 बार/मिनट
- पंजीकरण: 5 बार/मिनट (डिफ़ॉल्ट रूप से बंद, `REGISTRATION_ENABLED=1` से खोलें)

प्रतिक्रिया हेडर में `X-RateLimit-Limit`, `X-RateLimit-Remaining`, `X-RateLimit-Reset` होते हैं। सीमा पार करने पर 429 लौटता है और `Retry-After` संलग्न होता है।

### मिडलवेयर आर्किटेक्चर

वैश्विक मिडलवेयर सभी अनुरोधों पर लागू होता है, क्रम से निष्पादित:

```
Locale（Accept-Language 自动检测，设置语言环境）
  → Cors（跨域预处理 + 响应头）
  → SecurityFilter（HTTP方法限制/请求体大小/Content-Type校验/XSS/SQL注入/路径遍历/命令注入/CSRF 攻击拦截）
  → RateLimit（Redis 滑动窗口限流 + 账号锁定：5次登录失败锁定15分钟）
  → ApiVersion（API 版本校验，/api 路由组）
  → AdminAuth（JWT 认证 + 黑名单，/admin 路由组）
  → AdminPermission（RBAC 鉴权，/admin 路由组）
  → OperationLog（POST/PUT/DELETE 自动记录，含来源端检测，/admin 路由组）
```

`/health` और `/api/docs` और `/install` सार्वजनिक एंडपॉइंट हैं, केवल `Locale → Cors → SecurityFilter → RateLimit` से गुजरते हैं।

सुरक्षा संवर्द्धन:
- **खाता लॉक**: लगातार 5 बार लॉगिन विफल होने पर खाता स्वतः 15 मिनट लॉक हो जाता है, लॉक अवधि में लॉगिन 429 लौटाता है
- **समवर्ती सत्र सीमा**: एक उपयोगकर्ता के पास अधिकतम 3 वैध टोकन, अधिक होने पर सबसे पुराना टोकन स्वतः ब्लैकलिस्ट में जाता है
- **security.txt**: `GET /.well-known/security.txt` RFC 9116 मानक सुरक्षा संपर्क जानकारी प्रदान करता है
- **Nginx सुरक्षा कॉन्फ़िगरेशन**: `docs/nginx-security.conf` देखें, पूर्ण रिवर्स प्रॉक्सी सुरक्षा सुदृढ़ीकरण उदाहरण

### प्रमाणीकरण

लॉगिन और पंजीकरण के लिए पहले **क्लिक कैप्चा** सत्यापन आवश्यक है:

1. क्लाइंट `POST /api/captcha/generate` से कैप्चा छवि (base64 PNG) और टेक्स्ट लक्ष्य सूची प्राप्त करता है
2. उपयोगकर्ता छवि में संबंधित टेक्स्ट स्थानों पर क्रम से क्लिक करता है, क्लिक निर्देशांक `[{x, y}, ...]` एकत्र करता है
3. लॉगिन के समय `captcha_key` और `clicks` साथ सबमिट करें, सर्वर पहले कैप्चा फिर क्रेडेंशियल सत्यापित करता है

```http
POST /api/auth/login
Content-Type: application/json

{
  "username": "admin",
  "password": "******",
  "captcha_key": "abc123...",
  "clicks": [{"x": 120, "y": 85}, {"x": 210, "y": 140}, {"x": 95, "y": 170}]
}
```

प्रशासन के बाद के इंटरफ़ेस के लिए JWT प्रमाणीकरण आवश्यक है:

```http
Authorization: Bearer <token>
```

लॉगिन सफल होने पर access_token लौटता है, वैधता 2 घंटे; इसके अलावा refresh_token लौटता है, वैधता 14 दिन।

लॉगआउट पर टोकन Redis ब्लैकलिस्ट में जाता है, वैधता अवधि में दोबारा उपयोग नहीं हो सकता। POST /admin/profile/logout

### संवेदनशील ऑपरेशन की द्वितीयक पुष्टि

उपयोगकर्ता, भूमिका, अनुमति आदि हटाने जैसे संवेदनशील ऑपरेशनों के लिए अनुरोध निकाय में वर्तमान लॉगिन उपयोगकर्ता का `password` पास करके पहचान की द्वितीयक पुष्टि करनी होती है:

```http
DELETE /admin/user/{id}
Content-Type: application/json
Authorization: Bearer <token>

{ "password": "******" }
```

## विकास मानदंड

- वैश्विक फ़ंक्शन/क्लास संदर्भों में अग्रणी `\` नहीं लगता, समान रूप से `use` आयात उपयोग होता है
- सभी PHP फ़ाइलों के शीर्ष पर कॉपीराइट घोषणा होनी चाहिए
- सभी कॉन्फ़िगरेशन फ़ाइलों में चीनी टिप्पणी स्पष्टीकरण होना चाहिए
- डेटाबेस प्राथमिक कुंजी एप्लिकेशन परत के snowflake से उत्पन्न होनी चाहिए, ऑटोइंक्रीमेंट निषिद्ध
- API परत के सभी पैरामीटर और प्रतिक्रिया में ID hashids से एन्क्रिप्ट/डिक्रिप्ट होनी चाहिए
- AdminPermission मिडलवेयर उपयोगकर्ता अनुमतियों को Redis में कैश करता है (TTL=60s), N+1 क्वेरी बाधा समाप्त करता है

## परिनियोजन

### Docker Compose (अनुशंसित)

प्रोजेक्ट रूट निर्देशिका में `docker-compose.yml` है, जिसमें 5 सेवाओं का ऑर्केस्ट्रेशन है:

| सेवा | इमेज | पोर्ट |
|------|------|------|
| `nginx` | nginx:alpine | 80, 443 |
| `app` | स्थानीय `Dockerfile` से निर्माण | 8788 |
| `mysql` | mysql:8.0 | 3306 |
| `redis` | redis:7-alpine | 6379 |
| `elasticsearch` | elasticsearch:8.x | 9200 |

PHP इमेज `Dockerfile` से निर्मित होती है, आधार इमेज `php:8.3-cli`, OPcache सक्षम।

```bash
cp .env.docker .env
docker-compose up -d
```

### CI/CD

GitHub Actions सतत एकीकरण पाइपलाइन: `.github/workflows/ci.yml`

- PHP सिंटैक्स जांच (`php -l`)
- PHPUnit यूनिट टेस्ट
- Flutter स्टैटिक विश्लेषण (`flutter analyze`, CI में शामिल, सक्षम — `.github/workflows/ci.yml` का flutter job देखें)

### डेटाबेस बैकअप

`database/backup/` निर्देशिका:

- `backup.sh` — mysqldump + gzip बैकअप, 30 दिन पुराने बैकअप स्वतः साफ़ करता है
- `restore.sh` — इंटरैक्टिव पुनर्स्थापना, उपलब्ध बैकअप सूचीबद्ध करता है

### Nginx सुरक्षा कॉन्फ़िगरेशन

उत्पादन परिनियोजन के लिए `docs/nginx-security.conf` देखकर रिवर्स प्रॉक्सी सुरक्षा सुदृढ़ीकरण कॉन्फ़िगर करें।
